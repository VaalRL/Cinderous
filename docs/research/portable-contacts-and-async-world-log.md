# 研究：把 Cinderous 的加好友機制移植到遊戲，與「無 host 的非同步世界日誌」

> 兩個問題：
> ① 好友對戰既然已經加過好友就能走 WebRTC，那是否可以直接把 Cinderous 的加好友機制
>    與 relay 限制原樣複製到遊戲裡？
> ② 平行世界是否可以不需要時時連線——把世界狀態更新做成獨立事件放上 relay（7 天保存），
>    其他人讀取後更新本地狀態、自己有變動再發回去，於是「有一人的 relay 當 host，
>    但他不會知道，且他的行為與他人一致」？
>
> 相關：ADR-0024（QR 加好友）、ADR-0055（禁止跨身分互加好友）、ADR-0121（訊息請求）、
> ADR-0281（加好友輸入解析）、ADR-0284（QR 自報名稱與反垃圾紅線）、ADR-0123（具名訂閱）、
> ADR-0006（容量模型）、ADR-0235 H1（時鐘窗）、ADR-0065（TTL）；
> `docs/research/p2p-duels-and-host-anchored-worlds.md`（前一份）。
>
> 本文件為**研究記錄、非決策**。

## 結論摘要

| 問題 | 答案 |
| --- | --- |
| ① 複製加好友機制 | ✅ **幾乎沒有東西要複製——因為它本質上只是「取得 npub → 存本地」**。而 relay 限制照抄之後，**好友對戰今天就能在 cinder-relay 上跑，完全不需要 ADR-0366** |
| ① 共用同一把金鑰 | 🔴 **不該**。理由就是 ADR-0055 的理由，只是方向相反。正解是用 Cinderous 當**安全通道**去交換各遊戲的獨立身分 |
| ② 非同步世界日誌 | ✅ **可行，而且比上一份的 host-sequencer 模型更穩**（沒有必須在線的人）。但有三個必須處理的前提，且**只適用於低競爭的狀態** |

---

## 一、加好友機制：可以複製，但要複製的東西比想像中少

### Cinderous 的「加好友」在 relay 上**不存在**

查下來，整套機制沒有任何伺服器端狀態：

| 步驟 | 發生在哪 | 依據 |
| --- | --- | --- |
| 取得對方 npub | QR／貼上／`npub…@wss://…`（帶中繼提示） | `packages/core/src/contact-input.ts`、ADR-0024／0280／0281 |
| 存進聯絡人 | **純本地清單** | ADR-0014 |
| 對方收到 | 走 Gift Wrap 私訊，落進**訊息請求區**而非聯絡人 | ADR-0121 |
| 對方接受 | 他本地也存一筆 ⇒ 變成雙向 | ADR-0121 |

**沒有 friend table、沒有 follow 事件、沒有任何 relay 端的好友概念。**
所以「複製機制」實際上只是複製一個輸入解析器與一份本地清單——**極易移植**。

⚠ 有一條反垃圾紅線要一起複製，否則會複製出一個探測器：ADR-0284 記載
「單向加好友時，對方**在接受之前不會回送個人檔**——回送等於向陌生人確認『這把金鑰是活的』」。
遊戲若照抄機制卻漏掉這條，等於提供一個免費的 pubkey 存活性探測服務。

### 🔴 真正值得複製的是那兩個 filter 形狀

```jsonc
{"kinds":[20000], "authors":[好友們]}   // 好友在線狀態
{"kinds":[20078], "#p":[自己]}          // 挑戰／SDP／ICE 收件匣
```

**這兩個形狀在 ADR-0123 的 `scoped()` 下都是合法的。** 也就是說：

> **好友對戰（發現好友在線 → 指名挑戰 → WebRTC → DataChannel）整條路徑，
> 今天就能在 cinder-relay 上跑，一行 relay 程式碼都不用改。**

這是一條很乾淨的切分線：**ADR-0366 的車道只有「陌生人配對」需要，好友對戰不需要。**
可以先出好友對戰、把車道那一大塊往後排。

### 🔴 但不該共用同一把 nsec

使用者的前提是「已經加過好友」，那隱含**遊戲與 Cinderous 共用身分**。這會撞上 ADR-0055。

ADR-0055 禁止跨身分互加好友，理由是「把分身連結**主動送給最不該信任的中繼站**」。
遊戲共用金鑰是同一個問題的**放大版**，而且更糟——因為：

> **開放大廳是刻意公開的。** 你的 pubkey 會連同顯示名稱、遊戲、時段被廣播出去。

而 Cinderous 花了一整批 ADR（0088 jitter／0120 封裝 typing／0123 具名訂閱／0129 心跳降為無內容信標／
0240 真隱身）把 pubkey 的可觀測性壓到最低。**共用金鑰等於在遊戲那側把這些努力全部撤銷**，
而且是不可逆的：大廳公告一旦發出去就在別人的 relay 上。

### 正解：用 Cinderous 當安全通道，交換獨立的遊戲身分

```
每個遊戲一把獨立 game key（與 Cinderous 的 nsec 無關）

Cinderous 裡按「邀請他玩元素使」
  └─ 送一則 Gift Wrap 給對方（Cinderous 身分）
       content（密文）＝ { game: "elementalist", pubkey: <我的 game pubkey> }
  └─ 對方回一則，附上他的 game pubkey

⇒ 雙方各自在遊戲裡學到對方的 game 身分
⇒ relay 只看到「兩個 Cinderous 身分之間又傳了一則密文」——它本來就看得到這件事
⇒ game pubkey 的對應關係**從未離開密文**
```

好處：
- 好友清單的便利性拿到了（一鍵邀請，不用重新交換 QR）
- 金鑰不連結——relay、其他玩家、大廳觀察者都無法把你的遊戲身分連到聊天身分
- **這是 Cinderous 既有能力的直接應用**（1:1 加密訊息），不需要新協定

限制：對方也得用 Cinderous。沒有的話退回 QR／連結，和 Cinderous 自己的流程一樣。

## 二、非同步世界日誌：可行，但只適用於低競爭

### 它的形狀

世界狀態 ＝ 某座 relay 上的一串簽章事件。每個玩家訂閱、讀取、套用到本地狀態；
自己有動作就發一顆新事件回去。**relay 擁有者不需要跑任何東西，他的 Worker 只是儲存。**

這其實就是**事件溯源（event sourcing）＋ CRDT**，而且是**順著 Nostr 的本性用它**——
Nostr 本來就是一個只增不減的簽章事件日誌。

### ✅ 「host 不會知道」成立，而且是真好處

它解掉上一份研究稿裡最大的脆弱點：sequencer 模型需要 host 的**客戶端**保持在線，
他一離線世界就凍結。這個模型沒有任何人必須在線 —— relay（Worker）本來就不會離線。

### 🔴 前提一：必須用邏輯時鐘，不能用 `created_at`

`created_at` 是**客戶端自填的**。本站的時鐘窗（`host-config.ts`）是：

- 未來：`MAX_FUTURE_SKEW_SEC` = 15 分鐘
- 過去：`MAX_PAST_SKEW_SEC` = `TIMESTAMP_JITTER_SECONDS + 1h` ≈ **2 天又 1 小時**

（過去窗必須這麼寬是 NIP-59 的要求——Gift Wrap 刻意把外層時戳往前推最多 2 天以免中繼從時序
關聯社交圖譜，ADR-0235 H1。這條不能為了遊戲收緊。）

⇒ **攻擊者可以把「我先殺到的」這顆事件回溯兩天。** 任何「先到先得」的判定若以 `created_at`
排序，都會被這個窗打穿。

正解是事件自帶**因果順序**：每顆事件帶 `prev`（它看見的前序事件 id）形成 DAG，
決勝用 `(lamport, event.id)` 字典序——**和 NIP-01 可取代事件的決勝規則同款**
（`shouldReplace`：較新者勝，同時則 id 字典序小者勝）。

### 🔴 前提二：只有「可交換的操作」會收斂

| 狀態類型 | 會收斂嗎 | 說明 |
| --- | --- | --- |
| 玩家自己的位置／狀態 | ✅ | 只有本人會寫 ⇒ per-author LWW，天然收斂 |
| 「NPC X 被 Y 擊殺」 | ✅ | first-writer-wins register，用 `(lamport, id)` 決勝 |
| 累計傷害／擊殺數 | ✅ | G-Counter |
| 自己的背包 | ✅ | 單一作者 |
| **「攻擊必須在射程內且未死亡」** | ❌ | 約束取決於全域狀態；作弊者直接發一顆宣稱做到了的事件 |
| **排他資源（稀有掉寶只有一份）** | ❌ | first-writer-wins ＋ 可回溯時戳 ⇒ 作弊者恆勝 |
| **逾時判定**（「他沒回應所以判負」） | ❌ | 最終一致的日誌裡**無法證明某顆事件不存在** |

⇒ **低競爭的世界可以完全無權威；有排他性的東西不行。**

### 🔴 前提三：7 天保存 ⇒ 需要壓縮 ⇒ 權威問題回來了

事件 7 天後消失（ADR-0065），新加入者無法重放完整歷史。標準解法是快照
（可尋址 30xxx，`d = worldId`，30 天 TTL）——但**誰寫快照？寫的人可以說謊，
而 7 天後沒有人能靠重放驗證他。**

**建議反過來利用它：把 7 天做成「賽季」。**

世界的日誌活 7 天，到期世界結束，結果結算成一顆永久的可尋址紀錄。
這樣：不需要可信快照、不需要壓縮、世界有天然的生命週期與重置節奏——
**把協定限制變成遊戲機制**，而不是與它對抗。

### ⚠️ 「不時時連線」在成本上其實比較貴

這點與直覺相反，值得先講清楚。ADR-0006 的計費模型是
「**每筆進入的 WebSocket 訊息**約當一次計費請求」，而**中繼 → 客戶端的推送不計費**。

| 做法 | 每日進站訊息/人 |
| --- | --- |
| 保持一條長訂閱（relay 主動推送） | **1 次 REQ**（＋自己的寫入） |
| 每 30 秒輪詢一次 | **2,880 次 REQ** |

⇒ **保持訂閱比定期輪詢便宜將近三千倍。**

所以「不時時連線」的價值**不是省成本**，而是**離線容錯**：關掉遊戲、隔天回來，
從日誌把落掉的東西補回來。那個價值是真的，只是理由不同——而且它正好是
sequencer 模型做不到的事。

### 兩個模型不是二選一

| 競爭程度 | 建議模型 |
| --- | --- |
| 無競爭（探索、收集、各自的進度） | **事件日誌 CRDT，完全無 host** |
| 低競爭（共享世界、擊殺有先後但獎勵不排他） | 事件日誌 ＋ 邏輯時鐘（本節） |
| 高競爭（稀有掉寶、PvP、排行榜計分） | host 排序器 ＋ commit-reveal（前一份 §二），或乾脆做成 1v1 P2P |

「NPC 背擊殺」落在哪一格，取決於**擊殺有沒有排他獎勵**：
- 每個人都能打自己那份 NPC、獎勵不排他 ⇒ 第一格，最簡單，完全可行
- 全世界只有一隻、掉寶只有一份 ⇒ 第三格，需要權威或承諾機制

## 三、建議

1. **好友對戰先做，且不共用金鑰。** 照抄兩個 filter 形狀（`authors:[好友]` ＋ `#p:[自己]`），
   用 Cinderous 的加密管道 bootstrap 各遊戲的獨立身分。**這條路今天就能跑，不等 ADR-0366。**
2. **世界日誌先做「無競爭」的那一格。** 位置、探索、收集、個人進度——全部是天然 CRDT，
   不需要權威、不需要 host 在線、不需要邏輯時鐘以外的東西。
3. **7 天做成賽季。** 不要跟保存期對抗。
4. **保持長訂閱，不要輪詢。** 離線容錯靠 `since` 補齊，不靠定期 poll。
5. **排他性獎勵晚點再說。** 那是唯一真正需要權威的東西，把它隔離在一小塊功能裡，
   不要讓它的複雜度污染整個世界模型。

## 四、待決

1. 遊戲身分要不要做成「每個遊戲一把」還是「所有遊戲共用一把、但與 Cinderous 分離」。
   後者方便（跨遊戲道具需要同一個身分），但四款遊戲的大廳會互相連結你的活動。
2. 邏輯時鐘的具體形狀（Lamport 計數 vs 完整因果 DAG）——後者正確但事件會變大。
3. 賽季結算的那顆永久紀錄由誰寫、怎麼驗——這是把權威問題從「每一刻」縮小到「每 7 天一次」，
   但沒有消除它。
