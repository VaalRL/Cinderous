## 一、分層（全域原則）

| 層 | 傳輸 | 內容 | relay 成本 |
| --- | --- | --- | --- |
| **即時** | WebRTC DataChannel | 走棋、位置、動畫、聊天、特效 | **0** |
| **持久** | relay 事件 | 世界動作、結算、房間公告、贈禮 | 低 |
| **發現** | 共同集（少數硬編碼） | 世界／房間公告、找對手 | 極低 |

三條硬規則：

1. **要被搜尋到的東西，不可以是 Ephemeral。** NIP-01 的 20000–29999「not expected to be stored」，
   一座行為正確的中繼對它回 EOSE 零筆。想被查到就用可尋址 kind ＋ NIP-40 `expiration`。
2. **保持長訂閱，不要輪詢。** ADR-0006 只計進站訊息，推送不計費 ⇒ 長訂閱 1 次 REQ，
   每 30 秒輪詢 2,880 次。
3. **每個遊戲一把獨立身分金鑰**，不與 Cinderous 共用（理由見 `portable-contacts-and-async-world-log.md` §一之三）。

## 四、非同步共享世界

### 4.1 世界公告（kind 31078）

```jsonc
{
  "kind": 31078,
  "tags": [
    ["d", "<worldId>"],
    ["t", "<appId>"],
    ["relay", "wss://<世界所在站>"],     // 動作事件發到哪
    ["epoch_len", "86400"],              // 秒
    ["epoch0", "<unix 秒>"],             // 第 0 個 epoch 的起點
    ["settle_lag", "216000"],            // 見 4.3
    ["rules", "1.4.0"],                  // 規則版本（見 §五）
    ["cap", "100"], ["pop", "37"],
    ["expiration", "<now + 數分鐘>"]     // 同時就是 liveness 證明
  ],
  "content": "{...世界描述...}"
}
```

`expiration` 兼作存活證明：世界主停止續命，公告自然消失，玩家被退回選世界畫面。

### 4.2 動作事件（kind 1078）

```jsonc
{
  "kind": 1078,
  "tags": [
    ["t", "<appId>"],
    ["w", "<worldId>"],                  // 單字母，供索引
    ["rules", "1.4.0"]
  ],
  "content": "{ \"op\": \"...\", \"cost\": {...}, \"args\": {...} }"
}
```

### 4.3 Epoch 結算

```
epoch N 的區間     = [epoch0 + N·epoch_len, epoch0 + (N+1)·epoch_len)
暫定結算時點       = 區間結束 + settle_lag
```

🔴 **`settle_lag` 必須 ≥ 該世界所有 relay 的「過去方向時鐘窗」中的最大值。**

本站的窗是 `MAX_PAST_SKEW_SEC = TIMESTAMP_JITTER_SECONDS + 1h` ≈ **2 天又 1 小時**
（`host-config.ts`）；超窗的 `created_at` 中繼**直接拒收**。所以過了 `settle_lag` 之後，
**沒有任何人能再往該 epoch 塞事件**——集合定案，不需要任何權威、邏輯時鐘或 host。

建議預設 `settle_lag = 216000`（2.5 天），留半天餘裕。

> ⚠ 這個數字取自**本站的**設定。世界若掛在別人的 relay 上，必須讀得到那座站的窗
> ——這是 §十 要求 NIP-11 揭露時鐘窗的原因。

### 4.4 排序與摺疊

```
events(N) = 所有 created_at ∈ epoch N 區間、kind 1078、#w = worldId、且通過 §4.5 驗證者
order     = 依 (created_at, event.id) 升冪
state(N)  = fold(state(N-1), order, rulesVersion)
```

🔴 **不要設計依賴順序的規則。** `event.id` 可以被「磨」出來（正是 PoW 在做的事），
`created_at` 在 epoch 內可自選 ⇒ **任何由攻擊者可控欄位推導出的「誰先」都是可買的。**

⇒ **規則應設計成順序無關**：聚合 ＋ 在 epoch 結束時判定門檻。
（見 §4.6。真要「誰先」有價值，走 commit-reveal 或做成 1v1 P2P。）

### 4.5 驗證發生在摺疊時，不是寫入時

Relay 不懂遊戲規則，但 **fold 函式懂**。一顆前提不成立的事件仍會被中繼收下、仍存在，
但每個客戶端摺疊時都會略過它 ⇒ 對世界狀態的影響是零。**那不是「挽回」，是「從未發生」。**

fold 至少檢查：
- **前提**：該動作要求的前置事件在日誌裡（例：屠龍前須有「抵達巢穴」）
- **成本**：宣稱消耗的資源，依 `state(N-1)` 餘額足夠（不足即略過，且可作為雙花證據）
- **規則版本**：`rules` tag 與本 epoch 釘住的版本相符

### 4.6 統計門檻（建議的主要玩法形狀）

聚合是**集合的純函數**，與順序無關 ⇒ 這是本架構最擅長的事：

```
在 epoch N 結算時：
  if aggregate(events(N), "antagonise", A→B) ≥ T_enter  → 宣戰
  elif ... ≤ T_exit                                      → 回到僵持
```

三條必要細節：

1. **遲滯**：`T_enter > T_exit`，並設最短持續 epoch 數。否則計數在門檻附近震盪 ⇒ 世界戰和閃爍。
2. **分母必須是日誌的純函數**。優先用絕對門檻；要用比例則分母定義為可計算的集合
   （例「最近 K 個 epoch 有動作的 pubkey 數」）。
3. **進度條藏不住**（日誌公開）。若不想被掐時機，對門檻做承諾：世界建立時公布
   `H(T ‖ salt)`，結算時揭曉。

### 4.7 🔴 計數的是「代價」，不是「人」

金鑰免費 ⇒ 數人必被 Sybil 打穿。`aggregate` 的權重只能取自可驗證的成本：

| 權重來源 | 強度 | 說明 |
| --- | --- | --- |
| **NIP-13 PoW**（`minPowDifficulty`） | ★★★ | 門檻實質變成「累計工作量 ≥ T」。Sybil 完全沒有幫助 |
| **世界年資**（≥N 個已結算 epoch 有活動） | ★★★ | 🔵 **epoch 模型讓這條特別有效**——中繼拒收超窗時戳 ⇒ **Sybil 大軍無法回溯偽造年資，只能真的花時間養** |
| **消耗日誌上的資源** | ★★ | 重放即可查雙花 |

### 4.8 快照（kind 31079）與新玩家

事件 7 天後消失 ⇒ 新玩家需要快照。**但這裡的快照不需要權威**：

> 因為摺疊是確定性的，**「同意」是免費的——不需投票，只需數有多少個獨立的相同答案。**

任何人發布自己算出的 `state(N)` 雜湊；新玩家只採用 **≥k 把獨立金鑰發布了相同雜湊**的那份。
建議 k 的簽署者須在該世界日誌中有行為紀錄（否則同樣是 Sybil）。

暫定結算在 +2.5 天、事件活到 +7 天 ⇒ **約 4.5 天的重疊窗，任何人都能重放原始事件自行驗證**。

## 五、規則引擎契約

```
fold(prevState, orderedEvents, rulesVersion) → nextState     // 純函式
```

必須**位元確定**，跨平台、**跨版本**：

- 無 I/O、無時鐘、無亂數（亂數取自 `H(worldSeed ‖ epoch ‖ seq)`）
- 不使用浮點（或全面定點）；不依賴 Map/Set 的列舉順序；不依賴 locale
- **每個 epoch 釘住一個 `rules` 版本**；遇到比自己新的版本 ⇒ **停下來要求更新，不要猜**

> ⚠ **確定性摺疊的敵人通常不是作弊者，是你自己的下一次改版。**

## 六、挑戰協定（fraud proof）

```
epoch 結束 → +settle_lag → 暫定結算 → 挑戰窗 → 最終結算 → 事件過期
```

挑戰事件（kind 1079）指向一顆被質疑的動作，並附上**可由規則驗證的理由**。
判定必須**也是確定性的**，否則權威問題就回來了。兩種可接受：

- **規則可驗證的矛盾**：後續日誌出現不相容事實（宣稱消耗的資源當時餘額不足…）
  ⇒ fold 自動作廢，**不需要任何人出面**
- **k-of-n**：≥k 把有世界歷史的金鑰共同簽署異議

🔵 **挑戰窗長度是可調的營運參數**：`MAX_TTL_DAYS`（ADR-0160）是站方環境變數，
自架的世界站設 30 天即可。不是協定限制。

**仍有一類挽不回**：真值在日誌外、且永不產生後續矛盾的宣稱。對這類唯一有效的防線是
**讓宣稱附帶可驗證的代價**——「我屠了龍」改成「我消耗 50 體力與 3 次劍擊」，
而體力與劍擊在日誌上。**結果無法驗證，但成本可以。**

## 七、房間與好友對戰

### 7.1 好友對戰（🟢 今天就能跑，零 relay 改動）

```jsonc
{"kinds":[20000], "authors":[好友們]}   // 好友在線
{"kinds":[20078], "#p":[自己]}          // 挑戰／SDP／ICE（NIP-44 加密）
```

**兩個形狀在 ADR-0123 的 `scoped()` 下都合法。** 握手後走 DataChannel ⇒ relay 用量歸零。
《沒當好爸爸》ADR-0008 已完整實作此路徑。

⚠ 殘餘：**TURN 尚未接**（其 ADR-0008 寫「等對稱 NAT 成為實際問題再接」）。
P2P 成為主要路徑之後這不再是「以後再說」。

### 7.2 開放房間（需要 §十 的變更）

房間公告（31080）發到**共同發現集**，`["relay", ...]` 指向對局所在站；對局流量在房主自己的站。
⚠ 房主的自架站必須跑寬鬆車道（陌生人要訂閱得到），且**他是自費讓陌生人寫入**
⇒ 需 PoW／速率限制，或以 `allowedAuthors`（ADR-0044）限定已入場者。

### 7.3 發現：用 NIP-66，不是 NIP-11

NIP-11 只能描述、不能發現。陌生 relay 的發現標準是 **NIP-66（kind 30166／10166）**，
其 `["R","!payment"]` 正是四份規格想要的「過濾收費節點」。

🔴 **但發現只解韌性，不解配對。** 配對是會合問題：A、B 配得到對當且僅當兩人的 relay 集合有交集，
而「選 RTT 最低者」是本地量測值 ⇒ 台灣玩家選台灣站、德國玩家選德國站，**各自最佳化之後交集為空**。
⇒ 配對維持硬編碼的少數會合集；動態選法若要用，排序鍵必須全球一致（URL 字典序），不是 RTT。

## 十、🔴 Cinderous relay 需要修改的地方（本文結論）

### P0 — 沒有這些，世界與開放房間跑不起來

| # | 變更 | 檔案 | 為什麼 |
| --- | --- | --- | --- |
| 1 | **車道路由**：`/app/<id>` → 獨立 DO（雜湊分片取上界）；**未知路徑一律拒絕連線** | `shard.ts`、`worker.ts:211` | 寬鬆規則必須落在**物理上不同的 DO**，其 SQLite 裡沒有任何 Cinderous 事件。順手收掉「未知→`global`」的遷移期回退（`shard.test.ts:48-52` 釘著 `/`、`/s/zz`、`/s/ab`） |
| 2 | **`scoped()` 車道版**：放行 tag-scoped 訂閱（至少一個 `#`-tag 或 `authors`），仍擋裸 `{kinds:[…]}` | `relay-core.ts:426-447` | §八 的三個 ❌ 全卡在這裡。**ADR-0123 對訊息平面一字不動** |
| 3 | **可尋址讀取閘收窄**：`isAddressableKind(kind)` → 只對 `SNAPSHOT_KIND` 生效 | `relay-core.ts:473`、`:584` | 現行語意過寬，把整個 30000–39999 都閘成作者專屬 ⇒ 牌組、世界公告、快照沒有第二個人看得到 |
