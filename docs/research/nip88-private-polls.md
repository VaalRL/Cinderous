# 研究：NIP-88 Polls 是否適合本專案（私密群組投票）

> 目的：評估在 Cinderous 實作投票功能的可行性與形態。
> 判準：隱私模型相容性（Gift Wrap／零知識中繼）、與既有架構的重用度、成本結構、一致性語意。
> 相關：ADR-0259（NIP 適用性盤點——**已否決公開版 NIP-88**）、ADR-0263/0264（行事曆——本案的
> 架構前例）、ADR-0027（群組無共用金鑰扇出）、ADR-0068（群組快照）、PRD §12。結論先行。

## 結論摘要

**適合做，但只做「借形狀、不借傳輸」的私密版**；照 NIP-88 原樣實作＝直接違反隱私模型。
優先級中——建議先讓行事曆實機驗收一輪（同構的 fanout／補送模式吸收實戰問題），再上投票直接受益。

## 1. 前情：ADR-0259 的否決針對「公開版」，不自動涵蓋本案

- **ADR-0259 已將 NIP-88 列入否決批次**：「全屬公開社群/內容平台功能」，牴觸 PRD §12。
  該否決正確——NIP-88 原樣的 poll（kind 1068）與每張票（kind 1018）都是**公開事件**：
  誰投了什麼、何時投，中繼與全世界可見。
- 但「私密群組/1:1 投票」是另一個問題。repo 的完美前例＝**行事曆對 NIP-52 的處理**
  （`packages/core/src/calendar.ts` 檔頭）：「不是 NIP-52 相容實作……欄位直接沿用——照抄一個
  想清楚過的資料形狀沒有壞處。但**傳輸完全不同**」。本案與之完全同構：
  NIP-88 之於私密投票＝NIP-52 之於行事曆。

## 2. 評估

| 面向 | 評估 |
| --- | --- |
| 產品價值 | 🟢 群組投票是主流標配（WhatsApp/LINE 皆有）；與行事曆互補（投票選時間→轉行程）；企業群表決強需求 |
| 架構相容 | 🟢 NIP-88 資料形狀（選項/單複選/截止）作 rumor 塞 Gift Wrap、依 ADR-0027 逐成員扇出——中繼只見密文 |
| 成本結構 | 🟡 每張票扇出全群＝O(N²)，與 RSVP 相同（ADR-0259 §1.4 已量化並接受）；補送重用行事曆 6h 節流 |
| 一致性 | 🟡 與群訊同級殘餘：離線 >7 天（TTL）漏票→計票分歧；改票＝同 poll id 每投票者 LWW；截止本地判定（容忍時鐘偏移，同限時訊息）；群組快照（ADR-0068）日後可帶 poll 狀態自癒 |
| 匿名投票 | 🔴 v1 不做並明示——無共用金鑰＋E2E 簽章下票天生**記名**（同 WhatsApp）；真匿名需盲簽/混淆等額外密碼學，超出範圍。UI 必須寫明「群組成員看得到你投了什麼」 |

**輕量替代**（誠實列出）：用既有 reactions 當土製投票（訊息列選項＋emoji 計數）——零新協定，
但無選項結構/計票/截止，UX 差一截；只適合試水溫，不建議作為正式路徑。

## 3. 若實作：形態與工作量

1. **core**：poll/vote rumor 形狀＋驗證（選項 2~N、單/複選、endsAt）——借 NIP-88 欄位（~200 行＋測試）。
2. **engine**：sendPoll/votePoll、每投票者 LWW 儲存、onPoll/onVote 事件、補送節流（重用行事曆模式，~300 行）。
3. **桌面 UI**：composer 📊 建立、氣泡選項/百分比/投票、截止顯示（~300 行）；行動端後續。
4. **ADR（下一號，現為 0268）**：須明寫與 0259 的關係——「0259 否決公開版；本案為私密版，
   關係同 0263 之於 NIP-52」。

總工作量約為行事曆的六成（fanout/補送/儲存模式全可重用）。

## 4. 建議

- **做，優先級中**：價值明確、路徑已被行事曆踩平、風險皆為已知已接受的同款。
- **時機**：行事曆實機驗收過一輪後再上（同構模式的實戰問題先吸收）。
- 匿名投票若日後有強需求，另立研究（盲簽/可驗證混洗的成本效益）。

> 本文件為**研究記錄、非決策**。啟動實作時依上述第 4 點另立 ADR。
