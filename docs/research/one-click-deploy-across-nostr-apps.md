# 研究：讓每個 Nostr 應用都能「一鍵部署自有 relay ＋ 自動遷移」是否可行

> 目標流程（使用者裁示）：下載應用 → 點部署按鈕 → 自動遷移預設勾選（可不勾）→
> 網頁自動跳出登入 Cloudflare → 登入後回到應用內 → 應用顯示 relay 網址，背後也遷移好。
> 範圍：Cinderous ＋《辭職信》《菜鳥教頭》《元素使》《沒當好爸爸》。
> 相關：**ADR-0356**（App 內建一鍵部署，已接受）、ADR-0357（官網自架教學）、
> ADR-0039／0066／0069（錨點、home 搬家與排水）、ADR-0241（跟版義務）、ADR-0354（統一節點）、
> ADR-0366（第三方應用車道，提議中）。
>
> 本文件為**研究記錄、非決策**。

## 結論摘要

拆成兩個問題，答案相反：

1. **技術上做得出那個流程嗎？** ——**可以，而且比 ADR-0356 寫的時候更接近。** 該 ADR 把 OAuth 列為
   「待過審」而先走 token 貼上；查證後 OAuth 的閘門看起來是**自助式 DNS 網域驗證**，不是排隊過審。
   真正的新前提只有一個：**你需要一個自己控制 DNS 的網域**（`vaalrl.github.io` 加不了 TXT record）。
2. **每個應用都該做嗎？** ——**不該。** 「自動遷移」對 Cinderous 是**帶著走**，對遊戲是
   **把自己搬進一座空無一人的大廳**。五個應用裡只有 1.5 個適合。

## 一、使用者流程逐步拆解

| # | 步驟 | 可行性 | 依據／缺口 |
| --- | --- | --- | --- |
| 1 | 下載應用 | ✅ | — |
| 2 | 點部署按鈕 | ✅ | ADR-0356 已接受並設計完畢 |
| 3 | 自動遷移**預設勾選、可不勾** | ✅ | ADR-0356 §5 就是這個形狀：「預設已勾選的核取方塊，不是問句也不是無聲發生」 |
| 4 | **網頁自動跳出登入 Cloudflare** | ⚠ **需要 OAuth 公開客戶端** | 見 §二。token 路徑做不到這一步——它是「開連結→建 token→複製→貼回」 |
| 5 | **登入後回到應用內** | ⚠ 同上 | PKCE ＋ loopback redirect（`http://localhost:<port>/callback`），Tauri 開系統瀏覽器、Rust 端起臨時 listener 接 callback |
| 6 | 應用顯示 relay 網址 | ✅ | ADR-0356 §4：網址由子網域算出，不需回呼；**且必須實連收到 NIP-42 `["AUTH", challenge]` 才算成功**（部署 API 回 200 不等於 relay 活著） |
| 7 | 背後自動遷移好 | 🔴 **因應用而異** | 見 §四。這是整份研究真正的結論所在 |

第 4、5 步是整個流程「一鍵感」的來源，而它們**完全押在 OAuth 上**。

## 二、OAuth：ADR-0356 的前提可能要更新

ADR-0356 §1b 寫的是：

> `CfAuth::OAuth` ⏳ **待我方客戶端過審** …客戶端要從 private 轉 public 才能讓任意使用者授權，
> 而那需要先滿足前置條件並通過**網域驗證**。

2026-09-22 查證結果：

| 項目 | 查到的內容 |
| --- | --- |
| 自管 OAuth 客戶端 | 2026-06-03 上線（與 ADR-0356 記載一致） |
| **PKCE** | 支援，明確點名 single-page／mobile／**desktop／CLI**；用 PKCE 的客戶端**不需要 client secret** |
| **Redirect URI** | 有「Allow localhost clients」設定，另有 `127.0.0.1` loopback 選項 ⇒ **桌面 App 的標準做法可用** |
| **轉 public 的條件** | 需對 client URL 做**網域所有權驗證**——在 DNS 加一筆帶 `cloudflare_oauth_client_publisher=` 前綴的 TXT record。**僅供帳號內成員私用則免驗證** |
| 同意頁 | 已驗證網域顯示藍色盾牌，未驗證顯示琥珀色盾牌 |

**⇒ 看起來是自助式的（加一筆 TXT record），不是排隊過審。** 若屬實，ADR-0356 把 OAuth 列為
「跨組織的等待」這個判斷需要修正——它可能是**今天就能做完的一件事**。

### 🔴 兩個必須先處理的前提

1. **你需要一個自有網域。** 官網目前在 `vaalrl.github.io/Cinderous/`，那是 GitHub Pages 的子網域，
   **你加不了 TXT record**。走 OAuth 就得先買一個網域（順帶也解掉 ADR-0357 官網那條的一部分）。
2. **⚠ 本次查證沒有讀到原始頁面。** `developers.cloudflare.com` 被本環境的 egress proxy 擋住，
   上表來自搜尋結果摘要。依本專案「動工前重新查證」的硬規則（那條規則正是因為 2026-09-17 重查
   翻盤了一條限制才立的），**動工前必須直接讀過官方頁面再確認一次**，特別是「轉 public 到底要不要
   人工審核」這一條。

### 不變的部分

OAuth 到位也**不改變 ADR-0356 §1 的架構決定**：access token 一樣是使用者整個 Cloudflare 帳號的
信任根，一樣該留在 Rust ＋ OS 金鑰庫、不進 webview，HTTP 一樣由 `reqwest` 發（CSP 一個字不用動）。
`CfAuth` 那個插座當初就是為這一天留的，OAuth 只是多一個變體。

## 三、五個應用的逐一評估

`api.cloudflare.com` 不送 CORS（ADR-0356 限制 3）⇒ **純網頁版一律做不到**，只有 Tauri 桌面端可行。

| 應用 | 桌面端 | 有自己的 relay 實作？ | 網路模型 | 適合做這個按鈕？ |
| --- | --- | --- | --- | --- |
| **Cinderous** | ✅ Tauri | ✅ 本體就是 | outbox ＋ relay hint，錨點恆連 pool | ✅ **已接受（ADR-0356）** |
| **沒當好爸爸** | ✅ Tauri（`apps/desktop/src-tauri`） | ❌ | **同時連全部、不做主備切換**（ADR-0007） | ✅ 但語意要改成「加一座」，見 §四 |
| **辭職信** | ✅ Tauri（`apps/desktop/src-tauri`） | ❌（只有兩份測試用 mini-relay） | 🔴 **一次只用一座**（`relay.ts:1-8`，`reconcile` 會 `close()` 並刪掉其他連線，`:378-383`） | ❌ **先改網路模型，否則不該給這個按鈕** |
| **菜鳥教頭** | ✅ `apps/desktop` 存在 | ❌ | 零 nostr 程式碼 | ⏳ 太早 |
| **元素使** | ❌ **`src/`／`src-tauri/` 皆未建立** | ❌ | 只有文件 | ⏳ 太早 |

## 四、🔴「自動遷移」對遊戲的意義，和對 Cinderous 完全不同

這是本研究最重要的一節。

**對 Cinderous，遷移是「帶著走」。** 1:1 通訊靠 outbox 模型與 relay hint（ADR-0035／0039）：
你換站，聯絡人透過開機廣播的新 hint 自動改道（ADR-0066 H1），舊站還有七天排水（H3）不吃掉
未取件的離線留言。整個機制**已經存在且測過**。

**對遊戲，大廳是多對多的「發現」。遷到自己的站 ＝ 站上只有你一個人。**

| 應用 | 遷移後會發生什麼 | 判定 |
| --- | --- | --- |
| **辭職信** | `reconcile` 關掉其他所有連線 ⇒ 你只連自有站。房號是**口傳的 8 碼**，兩邊必須在同一座 relay ⇒ **A 遷了、B 沒遷，兩人從此配不到對** | 🔴 **功能性倒退** |
| **沒當好爸爸** | 同時連全部 ⇒ 自有站只是 pool 多一條，大廳照常由公共備援回應 | ✅ 安全（但那叫「加一座」不叫「遷移」） |
| **菜鳥教頭** | NIP-58 勳章是**給別人看的**；只發到自有站＝沒人看得到 | 🟠 發現性倒退 |
| **元素使** | 牌組公開發布供全球瀏覽；只發到自有站＝沒人抓得到你的牌組，你也抓不到別人的 | 🟠 發現性倒退 |

**⇒ 對遊戲，這個功能的正確名字是「把自有站加進 pool」，而且預設不該切 home。**
Cinderous 那個「預設勾選切 home」的 UX 不能照搬——照搬會讓使用者按一個看起來很棒的按鈕，
然後發現自己找不到對手。

### 還有一個遊戲沒有的東西：排水機制

Cinderous 的 `changeProfileRelay` 有七天排水（ADR-0066 H3，對齊 ADR-0065 的 TTL 上限）。
四款遊戲**都沒有**。直接切站會吃掉：

- 《辭職信》**在途的 kind 1059 禮物**——外層是一次性金鑰、你不是作者，**你搬不走它**，
  而送方已經實質扣款（其 ADR-0009 §40 的 `beforeSend` 先扣後發）；
- **進行中房間的 kind 1078 歷史**——斷線重連靠歷史重放（`session.ts:175`），換站＝重放不完整。

## 五、要部署的是誰的 worker？

四款遊戲都沒有自己的 relay 實作 ⇒ 一鍵部署出去的會是 **Cinderous 的 worker**。三個後果：

1. **ADR-0366 不會因此消失，只會變小。** 自有站要能跑遊戲，那三道閘（`scoped()` 寬鬆模式、
   可尋址讀取閘收窄、`requireAuth` 可關）**仍然得先實作出來**——只是 `/app/` 路由、雜湊分片與
   per-path NIP-11 可以省掉，因為一座站只服務一個應用。
2. **跟版義務會散出去**（ADR-0241 已記：「relay 需 deploy 最新 worker」）。四款應用各自出貨一份
   176KB 的 bundle，版本會漂移。ADR-0356 的「一鍵更新節點」（比對 NIP-11 `version`）必須一起做。
3. **授權**：relay 是 AGPL-3.0（`relay/package.json`）。四個下游把它打包進自己的出貨物要先確認合規。

## 六、建議

**分兩層，不要一套 UX 套五個應用：**

| 層 | 誰 | 做什麼 |
| --- | --- | --- |
| 完整流程（部署＋切 home＋排水） | Cinderous | ADR-0356 已接受，照做 |
| 只做「加一座到 pool」 | 沒當好爸爸 | 不切 home、不排水，風險趨近於零 |
| 先改網路模型再談 | 辭職信 | 單一 active relay 改成 additive pool，否則這個按鈕會弄壞配對 |
| 暫不做 | 菜鳥教頭、元素使 | 一個零 nostr 程式碼，一個連 `src/` 都還沒建立 |

**動工順序建議：**

1. **買網域**——OAuth 的硬前提，且獨立於其他所有決定。
2. **直接讀 Cloudflare 官方頁面重新確認**「轉 public 要不要人工審核」（§二的查證限制）。
3. 若確認自助 ⇒ 補一份 ADR 修正 ADR-0356 §1b 的「待過審」判斷，`CfAuth::OAuth` 實作。
4. 遊戲那側先修各自的前置缺陷（辭職信的 AUTH 與網路模型、兩個 repo 的位址錯誤）。

## 七、待裁示

1. **這條路是否取代 ADR-0366？** 本研究的答案是**不取代，只縮小**（§五 1）。若要走「各自部署」，
   ADR-0366 應從「提議中」改為**縮小範圍後接受**，而不是棄用。
2. **遊戲要不要給這個按鈕？** 給了就要接受「使用者可能把自己隔離到一座空站」這個產品風險，
   即使 UI 講清楚了也會發生。
3. **買哪個網域、掛在誰名下**——它會出現在每一個使用者的 OAuth 同意頁上。
