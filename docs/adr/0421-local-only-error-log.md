# 0421. 本機錯誤紀錄：只存在這台裝置、遮罩後才寫、使用者複製才交出去

- 狀態：已接受
- 日期：2026-11-13
- 相關文件：PRD「隱私預設」；ARCHITECTURE「本地優先、明文與私鑰不離開裝置」；ADR-0130（jsdom 掛載測試）；ADR-0227（關於／版本區）

## 背景與問題

2026-11-13 桌面開發版出現「視窗只剩底色、沒有任何介面」。事後查明是開發環境問題（舊的實體沒關，新的被單一實體機制擋下），但過程暴露了一個產品缺口：

- **前端沒有 ErrorBoundary**：任何元件在 render 時丟例外，React 就會卸掉整棵樹，使用者看到的正是「只剩底色」，沒有任何提示。
- **沒有任何錯誤紀錄**：`console.error` 只出現在開發者工具；Rust 端沒有 log 呼叫，正式版沒有主控台，panic 訊息直接消失。
- **沒有遙測**：這是刻意的（隱私預設），但結果是使用者回報「白畫面」時，我們手上什麼都沒有，只能靠重現。

使用者 2026-11-13 決定：要補，而且存在本地。

## 考量的選項

- 選項 A：接第三方當機回報服務（Sentry 之類）。最完整，但錯誤內容會離開裝置、多一個外部依賴，違反隱私預設。**不採用。**
- 選項 B：只加 ErrorBoundary，不留紀錄。不再白畫面，但回報時仍然沒有資料。
- 選項 C：ErrorBoundary ＋ **只存在本機**的紀錄，遮罩後才寫入，使用者自己按「複製」才交出去。

## 決策

採選項 C。

1. **共用核心** `packages/engine/src/diag-log.ts`（桌面、手機共用）：
   - `redactDiag`：寫入前遮掉 nsec／npub／ncryptsec／nprofile 等 bech32、32 字以上的 hex（公鑰、事件 id、金鑰）、40 字以上的英數串（密文、base64 金鑰）、email，以及網址的 query／fragment（可能帶 token）。
   - `createDiagLog`：環狀緩衝，只留最近 100 筆；訊息上限 500 字、堆疊上限 2000 字。同一來源、同一訊息連續發生就合併成一筆加次數，render 迴圈不會洗掉其他紀錄。記錄本身絕不丟例外，store 壞掉就退回記憶體。
   - `installErrorCapture`：接 `window` 的 `error` 與 `unhandledrejection`。
   - 存在 localStorage 的 `cinder.diag.v1`，是**裝置層**（不分身分）。錯誤跟哪台裝置有關，跟哪個身分無關，紀錄裡也不含身分資訊。
2. **ErrorBoundary**：桌面包在所有 Provider 的最外層，手機包在 `MobileApp` 外。出錯時顯示「畫面出錯了」，附「重新載入」與「複製錯誤資訊」；錯誤記為 `render`，含元件堆疊。保底畫面**不依賴任何 Provider**：桌面看 `<html lang>` 決定語言，手機讀裝置偏好。
3. **桌面原生端**：`src-tauri/src/diaglog.rs`（純 std、無 feature 閘門，`cargo test` 測得到）。
   - 裝 panic hook，把 panic 訊息（遮罩、單行）寫到 App 的 log 資料夾 `native-errors.log`，檔案上限 256 KB，超過只留後半段，再交給原本的 hook。
   - `diag_native_log` 讀最後 64 KB，`diag_native_clear` 刪檔。
   - 不新增依賴（不用 `tauri-plugin-log`）：Rust 端目前沒有其他 log 呼叫，要記的只有 panic。
4. **設定 → 關於 → 診斷紀錄**（桌面、手機都有）：顯示筆數、「複製」（WebView 紀錄加上原生紀錄，合成一段純文字）、「清除」（兩份一起清）。說明只有一句：「只存在這台裝置，不會自動上傳。」

## 理由

- 白畫面是使用者能遇到最糟的失敗型態：沒有提示、無從回報。ErrorBoundary 是最低成本的止血。
- 「只存在本機＋使用者主動複製」守住「明文與私鑰不離開裝置」：沒有任何自動送出的路徑，交不交出去由使用者決定。
- 遮罩是**縱深防禦**：錯誤訊息本來不該帶金鑰或身分，但我們不賭；匯出內容可能被貼到公開的 issue。

## 後果

- 正面：
  - 不再白畫面。
  - 回報問題時有錯誤訊息、堆疊、版本與次數可看。
  - 原生 panic 第一次留得下來。
- 負面 / 已知殘餘風險：
  - 遮罩是啟發式的：短於門檻的識別字串（例如截斷過的 npub、暱稱）不會被遮。錯誤訊息若含使用者輸入的文字（例如某個解析錯誤把訊息內容帶進 message），就可能留在紀錄裡。這份紀錄只在本機，交出去前使用者看得到全文。
  - localStorage 未加密：紀錄跟其他 WebView 資料一樣，靠作業系統的帳號隔離保護。內容已遮罩，風險有限。
  - panic hook 在 Tauri `setup` 才裝，`setup` 之前的 panic 不會進紀錄。
  - 長 base64 規則可能誤遮某些長 token（例如 bundle 檔名雜湊）。誤遮只會讓紀錄少一點資訊，不會漏資料，所以接受。
- 後續行動 / 待辦：
  - 實機確認錯誤畫面在深色主題下可讀。保底畫面刻意用樣式表變數（桌面）或固定亮色（手機）。
  - 若之後 Rust 端開始需要一般 log，再評估 `tauri-plugin-log`，並沿用同一個檔案與遮罩。
