# ADR-0286：行動端聯絡人分頁的好友請求徽章

- 狀態：已接受
- 日期：2026-07-29
- 相關：ADR-0087（底部分頁列）、ADR-0121（訊息請求）、ADR-0285（三欄佈局補上請求區）

## 脈絡

ADR-0285 修掉桌面三欄佈局「完全沒有請求區」之後，隨即被追問：
**行動端呢，APK 收得到邀請嗎？**

查下來與桌面**不同**——行動端的接線是完整的：

- `MobileApp` 有 `requests` state、訂了 `onRequests`。
- 傳給 `ContactListScreen`，含 `onAcceptRequest` / `onDeclineRequest` / `onClearRequests`。
- `ContactListScreen` 確實渲染請求區，且已有測試涵蓋。

所以 APK **收得到、也顯示得出來**。但有一個實用上的缺口：
**請求顯示在「聯絡人」分頁，而底部分頁列只有「聊天」分頁有徽章。**

停在聊天分頁的人不會有任何提示，也就不會切過去看。結果與 ADR-0285 那個 bug 的
使用者體感一模一樣——對方接受之前 ADR-0121 不回送個人檔，雙方名字都停在
`npub1abc…`，看起來像「加好友沒有用」。差別只在：桌面是**真的沒有 UI**，
行動端是**有 UI 但沒人知道要去看**。

## 決策

`BottomTabs` 的徽章由「只有聊天分頁」擴為**依分頁決定計數來源**：

| 分頁 | 計數 |
| --- | --- |
| 聊天 | 未讀訊息總數 |
| 聯絡人 | **待處理的好友請求數** |
| 設定 | 無 |

沿用既有的紅色徽章樣式與 `99+` 上限，不新增視覺語彙。

**桌面不需要對應改動**：三欄與經典佈局的請求區都在側欄常駐可見（ADR-0285 之後），
沒有「被藏在另一個分頁」的問題。

## 後果

**正面**

- 好友請求會主動被看見，加好友的迴圈不再卡在「沒人知道要按接受」。
- 兩種徽章各報各的數，互不污染。

**負面／代價**

- 分頁列同時出現兩個紅點時視覺較吵。可接受——兩者都是需要使用者處理的事。
- 徽章不區分「請求」與「未讀」的緊急程度，都是同一顆紅點。

**待辦**

- 實機驗收：對方加你為好友時，聯絡人分頁出現紅點；接受後紅點消失。
