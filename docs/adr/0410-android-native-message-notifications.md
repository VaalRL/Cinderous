# 0410. Android 版的訊息通知改走系統本機通知

- 狀態：已接受
- 日期：2026-11-02
- 相關文件：ADR-0116（行動端通知）、ADR-0272／0274（前台服務保活）、ADR-0076（桌面原生通知）

## 背景與問題

2026-11-02 在 Pixel 8a 上實測 v0.0.22：App 在背景時訊息有收到，但沒有跳通知。

原因有三個，疊在一起：

- ADR-0116 讓行動端沿用 Web Notification API。這在瀏覽器預覽可以用，但 **Android 殼（Capacitor）的 WebView 裡沒有 `Notification`**，是 undefined。所以 APK 從來沒跳過訊息通知。
- 設定裡的通知開關按下去時，`ensurePermission()` 回 false，開關維持關閉，畫面上沒有任何說明，看起來就像壞掉。
- App 從來沒向系統要過 `POST_NOTIFICATIONS`（Android 13 起要在執行期要）。所以前台服務（ADR-0274）那條「保持連線」的常駐通知也被系統擋掉、看不到。服務本身照常在跑，背景收訊沒受影響。

另外，行動端的開關沿用桌面的字串，顯示成「桌面通知」。

## 考量的選項

- A. 維持現狀，只在發版說明寫「Android 版不會跳通知」。
- B. 引入 `@capacitor/local-notifications`。它是 Capacitor 官方外掛，但功能遠多於需要（排程、鬧鐘），會連帶宣告額外的權限（開機自動啟動、精確鬧鐘）。
- **C. 在既有的原生外掛旁邊新增一個小外掛 `LocalNotify`**：只做三件事——要通知權限、跳一則通知、點通知時把對話鍵交回前端。

## 決策

採用 **C**。

- **原生 `LocalNotifyPlugin`**（`apps/mobile/android/.../LocalNotifyPlugin.java`）：
  - `requestPermission()`：Android 13 起用 Capacitor 的權限流程要 `POST_NOTIFICATIONS`。回傳 `{ granted }`，以系統的「通知是否開啟」為準，所以使用者在系統設定關掉也算沒授權。
  - `notify({ title, body, convo })`：在 `cinderous_messages` 頻道（高重要性）跳一則系統通知。沒有權限就靜默略過。同一個對話只留最新一則。
  - 點通知會帶著對話鍵回到 `MainActivity`（singleTask），外掛再以 `click` 事件交給前端開啟那個對話。
- **前端 `native/notify.ts`**：每次呼叫時才選路。原生殼裡有 `LocalNotify` 就走原生，否則照舊走 Web Notification（瀏覽器預覽與桌面瀏覽器路徑不變）。介面 `Notifier` 不變，呼叫端不用改。
- **設定頁**：開關改叫「訊息通知」。使用者按了、系統卻沒允許時，顯示去哪裡打開（設定 → 應用程式 → Cinderous → 通知）。
- 通知內容仍由前端在本機組好（ADR-0116／0076 的「隱藏預覽」照常適用）。原生層不決定要不要跳、也不讀訊息。

## 理由

- 只需要三個動作，自己寫約一百行 Java，比引入一個會多宣告權限的外掛單純。專案的權限原則是只拿必要的（不要開機自動啟動、不要精確鬧鐘）。
- 跟既有的 `Foreground`、`DeviceKeyStore` 外掛同一種做法：JS 端一個平台縫檔案、原生端一個外掛，文案由前端帶入。
- 要了通知權限之後，前台服務那條常駐通知也會出現。這是 ADR-0274 原本就想要的樣子（「通知列多一條狀態通知」是寫明的代價）。
- 一樣不經任何第三方推播：通知是 App 在本機收到訊息後自己跳的。App 被系統殺掉就收不到，這點跟 ADR-0116 相同；前台服務讓這種情況變少。

## 後果

- 正面：
  - Android 版第一次真的會跳訊息通知，點了會開到那個對話。
  - 開關不再無聲失敗；被系統擋住時說得出原因。
  - 「保持連線」的常駐通知看得到了。
- 負面 / 已知殘餘風險：
  - 通知預設仍是關的（ADR-0116），使用者要自己去設定打開。
  - 使用者如果之後在系統設定把通知關掉，App 裡的開關仍顯示「開」，只是通知不會出現。
  - 通知圖示用系統內建的聊天圖示，不是 Cinderous 的圖示。
  - 原生外掛沒有自動化測試，行為靠實機驗收。
- 後續行動 / 待辦：
  - 每一版的 APK 都要在實機上驗收一次背景通知。

## 測試

- `apps/mobile/src/native/notify.test.ts`：原生殼且外掛在才走原生；系統拒絕或外掛丟例外都回 false；通知內容與對話鍵原樣交給外掛；送出失敗不丟例外；點通知帶回對話鍵、取消註冊後不再收到；瀏覽器預覽不碰原生外掛。
- `apps/mobile/src/screens/GroupUi.test.tsx`：開關叫「訊息通知」；系統沒允許時才顯示說明。
- 都在實作前先確認是紅燈。
- 實機（Pixel 8a，Android 16，2026-11-02）：
  - 按開關跳出系統的「要允許「Cinderous」傳送通知嗎？」。選「不允許」→ 開關維持關閉，並出現去哪裡打開的說明；再按一次選「允許」→ 開關打開。
  - App 在背景時從桌面送一則訊息 → 通知列出現一則通知，標題是寄件人、內文是訊息，在 `cinderous_messages` 頻道。
  - 點通知 → 開到那個對話，通知自動清掉。
  - 前台服務的「保持連線」常駐通知也出現了。
  - 第一版在真機上白畫面：這個 Capacitor 版本的 `addListener` 直接回傳 handle，不是 Promise。已補測試並修正。
