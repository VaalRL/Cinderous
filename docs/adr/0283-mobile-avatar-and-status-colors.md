# ADR-0283：狀態列可換頭像，狀態鈕改用各自的狀態色

- 狀態：已接受
- 日期：2026-07-29
- 相關：ADR-0154（廣播頭像）、ADR-0164（隱身）、ADR-0250（視障友善配色與 `contrastRatio`）、ADR-0278（行動端自己狀態列）

## 脈絡

ADR-0278 在聊天頁頂部加了自己的狀態列之後，兩個地方不對勁。

### 一、頭像畫出來了卻不能點

換頭像只有「設定」分頁能做（`SettingsScreen` 的 `onAvatar`）。狀態列已經把頭像
畫在最顯眼的位置，**擺著卻不能點**——那反而讓人以為壞了，或者根本找不到哪裡能換。

### 二、狀態鈕看不出「狀態」

`StatusSegments` 三顆鈕（線上／離開／忙碌）選中時一律填**主色**（藍）。
但整個 App 對「狀態」的既有視覺語言是 `STATUS_COLORS`——聯絡人清單的狀態點、
桌面的頭像圈都是綠／黃／紅。狀態選擇器反而是唯一不用這組色的地方，
使用者得讀文字才知道自己選了什麼。

## 決策

### 1. 頭像可點即換

狀態列的頭像改為 `Pressable`：點擊 → `pickAvatarImage()`（選圖並縮到 128px）
→ 呼叫 `onAvatar` 廣播。走的是**與設定分頁同一個** `changeAvatar`，不另開路徑。

- 使用者取消選圖（回 `null`）＝什麼都不做，**不清掉現有頭像**。
- 未提供 `onAvatar`（示範後端沒有廣播對象）＝退化成純顯示、`disabled`。
- 圖示化的控制項要有無障礙標籤，沿用既有的 `avatar_change`（「更換頭像」）。

### 2. 狀態鈕改用各自的狀態色

每顆鈕帶一個該狀態顏色的圓點，邊框亦為該色；選中時**以狀態色填底**。
與聯絡人清單的狀態點同一組 `STATUS_COLORS`，看一眼就知道自己對外顯示成什麼。

**字色由對比決定，不是一律白字。** 「離開」的琥珀 `#f2b134` 上，白字對比只有約
2.1:1——看不清楚。改用 ADR-0250 已經引入的 `contrastRatio()` 在白與深墨之間挑高的那個。
這是既有工具的正當用途，不需要新機制。選中時色點改用字色，否則點與底色會糊成一塊。

## 後果

**正面**

- 換頭像從「翻設定」變成「點一下」。
- 狀態選擇器終於和 App 其他地方講同一種顏色語言。
- 琥珀底上的字仍然讀得清楚（而不是為了統一而犧牲可讀性）。

**負面／代價**

- 「忙碌」選中時是一顆紅色實心鈕，視覺上偏強烈，可能被誤讀為錯誤狀態。
  以色點與文字並存緩解，但這是把語義色用在互動元件上的固有代價。
- 狀態鈕變寬（多了色點），三顆在窄螢幕上更容易換行。`flexWrap` 已開，會折行不會截斷。

**待辦**

- 實機驗收：四種主題組合（淺／深 × 一般／高對比）下三顆鈕的可讀性。
- 實機驗收：點頭像 → 選圖 → 對方看得到新頭像（ADR-0154 的廣播路徑未改，但這是第一次
  從這個入口觸發）。
