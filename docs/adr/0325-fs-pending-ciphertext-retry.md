# ADR-0325：保留解不開的密文，等 EK 同步回來再試

- 狀態：已採用
- 日期：2026-08-04
- 關聯：ADR-0316（讓「解不開」看得見；§決策-6 把本工作列為獨立後續）、ADR-0245（opt-in FS）、ADR-0313（自動輪替）、ADR-0322 S2（EK per-device 分發）

## 1. 背景

`openWrapWithEks` 的註解從一開始就寫著：

> 全部失敗＝拋（呼叫端顯示未解、**待 EK 同步後重試**）。

但呼叫端從來沒有重試過——ADR-0316 只做到「看得見」，並明確把保留列為後續：

> **不做的事**：不保留解不開的密文以待日後補解。那是**復原**不是觀測。

現在補上它。真實情境很具體：**多裝置**。EK 私鑰在裝置間靠雲端快照或 kind 10042 信封同步，而訊息可能**比金鑰先到**——尤其在 ADR-0322 S2 改成 per-device 分發之後，新授權的裝置要等下一次信封才拿得到 EK。那段空窗期收到的訊息，過去是 `catch { return; }`，**永遠消失**。

## 2. 決策

解不開時把**原始事件**留下來（`StoredFsState.pending`），EK 到貨時重試：

- **保留時機**：只在 `hadEk` 那一桶。ADR-0316 的不對稱結論——**從未持有過 EK 時的失敗確定與 FS 無關**——所以那些留下來也永遠解不開，只是白白給攻擊者一個塞東西的地方。
- **重試時機**：EK 集合真的變大時，即 `receiveEkEnvelope()` 合併成功後、以及快照合併帶回 EK 後。
- **落點**：`StoredFsState.pending`，per-identity、與 EK 同一把 DEK 加密落地，零新增儲存管線（同 ADR-0316 對 `failures` 的理由）。

## 3. 兩個實作上非做不可的細節

### 3.1 重試**不能**走 `onEvent()` 重放

`onEvent()` 第一件事就是 `if (this.seenBefore(event.id)) return;`，而這些事件的 id 早就在 `seenEvt` 裡了 ⇒ **重放會被自己的去重悄悄吃掉**，整個功能看起來像沒壞但完全沒作用。

故直接依 kind 分派到 `receiveDm()` / `receiveFileChunk()`。

### 3.2 先 `openFs()` 試一次，成功才分派

直接分派的話，仍然解不開的那些會再次走進 `noteUndecryptable()` ⇒ **每次 EK 到貨就把失敗計數灌大一輪**。而那個計數正是 ADR-0316 給使用者看的東西，灌大就失去意義。

多解一次的代價，換掉一個會讓數字說謊的迴圈。有測試釘住。

## 4. 買不到什麼

1. **救不回這個功能上線前掉的訊息。** 那些事件當時就沒留下來。
2. **🔴 這個清單是攻擊者填得進來的。** 密碼學上分不出「缺 EK」與「垃圾密文」（ADR-0316 §先講清楚一件做不到的事），所以任何人朝我送 `#p` 垃圾都會被留下來。上限（50 顆）與 TTL（30 天）**不是效能考量，是濫用防線**。
3. **滿了丟最舊的 ⇒ 灌爆可以把真的擠掉。** 分不出真假就沒有更好的排序依據。這是上一點的直接後果，一併記在這裡而不是假裝有解。
4. **仍然不知道是誰送的。** 補解成功前，那顆密文對使用者是完全不透明的（NIP-59 的必然結果，ADR-0316 已記）。
5. **只重試「EK 集合變大」時**。手動重試入口沒做——沒有其他會讓結果改變的事件。

事件大小由中繼的大小上限界住（SECURITY.md〈濫用防護〉），故不另設每顆位元組上限。

## 5. `pending` 是裝置本地的

同 `failures`：**不進雲端快照、不進配對捆包**。別台裝置可能早就有那把 EK 而順利解開了，把密文搬過去只是在傳遞垃圾——而且那是**任何人都塞得進來**的原始密文。

⚠ 合併端也要保留本機的 `pending`。`mergeSnapshotContent` 是**逐欄位建構**，這個陷阱已經吃掉過 `unsupported`（ADR-0306）與 `retired`（ADR-0314）兩次；漏了它，同步一次就會把本機待補解的密文清光。三處都有回歸測試。

## 6. 後果

- 正面：多裝置空窗期的訊息不再永久消失；`openWrapWithEks` 註解裡承諾的行為終於存在。
- 負面：新增一個攻擊者可填的有界儲存（見 §4）。
- 後續：若觀測到 `pending` 經常滿載，那本身就是訊號（要嘛被灌，要嘛某台的 EK 同步壞了），屆時再考慮是否要顯示。目前不顯示——使用者對它不可行動，同 ADR-0316 對 `notFs` 的處置。
