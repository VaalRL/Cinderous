# 0407. 行動端也走中繼分片：桌面寄給手機的訊息全部遺失

- 狀態：已接受
- 日期：2026-10-30
- 相關文件：ADR-0241（中繼分片）、ADR-0383（跨錨點路由）、ADR-0378（引導座冗餘）、ADR-0100（行動端後端補齊）、ADR-0404／0406（實機對接時發現）

## 背景與問題

ADR-0241 把桌面切成分片模式，`buildBackend` 預設帶 `shardingBase`。在這個模式下，收件匣在自己的訊息片（`/s/<前綴>`），私訊寄到 `shard(對方)`。**行動端從來沒有切過**：`createRelayChat` 沒帶 `shardingBase`，只聽錨點主網址（全域 DO）。ADR-0241 全文也沒有提到行動端。

2026-10-30 實機（桌面 dev 在錨點 2、手機瀏覽器建置在錨點 1，拋棄式金鑰）：

| 方向 | 結果 |
|---|---|
| 手機 → 桌面 | 收得到 |
| 桌面 → 手機 | **收不到**（雙方都加好友，等超過 30 秒仍沒有） |
| 手機上看桌面 | 永遠離線 |

收得到的那個方向，是因為分片端在各錨點主網址（引導座）也掛著收件匣（ADR-0378）。手機寄到主網址，桌面照樣收到。反過來，桌面只寄到手機的訊息片，手機沒在聽。

已發布的 v0.0.20 很可能也有同樣的問題。

## 考量的選項

- **A. 行動端與桌面一樣預設開分片，`shardingEnabled()` 收斂到 engine，兩端共用。**
- B. 分片端寄私訊時，一律多寄一份到收件人那座錨點的主網址：舊手機不升級也收得到。代價是每則私訊在錨點上的寫入加倍。錨點在免費方案上，讀寫列數是先撞到的上限（ADR-0394、SDK ADR 0126），而且這個成本會一直持續下去。
- C. 桌面退回不分片：等於撤銷 ADR-0241 的擴充與爆炸半徑收益。

## 決策

採用 **A**。

- 分片開關 `shardingEnabled()` 從 `apps/desktop/src/App.tsx` 移到 `packages/engine/src/bootstrap-config.ts`，桌面與行動端共用同一個函式與 kill-switch（`localStorage nb.sharding=0`）。
- 行動端 `createRelayChat` 的個人身分（含企業主）加上 `shardingBase: relayUrl`，其餘設定不變。
- 企業成員兩端都不分片，鎖定公司座，跟桌面原本的設定一樣。

## 理由

- 根因是兩端設定不一致，修法是讓它們一致，而且共用同一個開關。之後誰改了分片開關，兩端會一起變。
- **舊手機的過渡**比照 ADR-0241 的「直接切換」：
  - 舊版手機本來就收不到桌面的訊息，這次修正不會讓它更糟。
  - 唯一新增的不相容是：升級後的手機寄給沒升級的手機，舊手機收不到，因為它只聽主網址。
  - 反方向（舊 → 新）照樣收得到，因為新版在引導座也掛著收件匣。
  - 使用者量很小，而且已有「每台裝置都要升級」的規則（ADR-0397 前後的發版規則）。用選項 B 的永久成本，換一段很短的過渡期，不划算。
- 背景通知：Android `ConnectionService` 只負責讓 WebView 保持運作，連線就是引擎那一條，所以開分片後背景照樣收得到。

## 後果

- 正面：桌面 ↔ 手機雙向送達，上線狀態也看得到。開了分片的 CLI（PR #62）→ 手機也一起修好。
- 負面 / 已知殘餘風險：
  - 🔴 **升級後的手機 → 沒升級的手機收不到。** 發版說明必須寫明「所有裝置都要更新」。
  - 手機的連線數略增（自己的訊息片、presence 層、跨錨點時對方那座的 presence），ADR-0241 已列為已知成本。
  - 跨錨點且只有裸 npub 時，上線狀態要等收到對方第一則訊息（學到對方在哪座錨點），再等下一次心跳才會出現。實機約 1～2 分鐘，桌面對桌面也是這樣（ADR-0383 原本的行為）。
- 後續行動 / 待辦：
  - 下次發版要做桌面 ↔ 手機雙向實測（含真實手機），發版說明寫明要全部升級。
- 實機驗證（2026-10-30，修正後，同上配置）：
  - 桌面 → 手機、手機 → 桌面都收得到。
  - 手機上看桌面是「離開」（桌面分頁在背景），並建立了直連。
  - 對照組：另一個桌面在錨點 1，跟錨點 2 的桌面互看上線也正常。
  - 觀察到但沒查證：手機上的桌面名稱仍是 npub。推測是加好友順序造成的（桌面先加手機時送出個人檔，那時手機還沒加桌面），跟分片無關。

## 測試

- `apps/mobile/src/backend-sharding.test.ts`：每個網址一顆 RelayCore。
  - 桌面設定 ↔ 手機設定，同錨點與跨錨點都要雙向送達（修正前紅燈，失敗原因與實機相同：桌面寄的手機收不到）。
  - kill-switch 關掉時，手機退回不分片，照樣能跟不分片的一方互通。
