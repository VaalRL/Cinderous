# ADR-0339：切換鏡頭——手機是翻面，桌面是選裝置

- 狀態：已採用
- 日期：2026-08-05
- 關聯：ADR-0337（畫質三檔與關鏡頭）、ADR-0338（升降級與預先協商的視訊軌）、ADR-0101（通話媒體平台縫）

## 1. 問題

`getUserMedia` 完全沒有指定 `facingMode` 或 `deviceId`，拿到的是瀏覽器預設（手機通常是前鏡頭）。**通話中換不了鏡頭。**

手機視訊通話「把鏡頭轉過去給對方看」是基本操作，缺它會被當成 bug。

## 2. 這其實是兩個功能

| | 使用者要的 | 技術手段 |
| --- | --- | --- |
| **手機** | 前↔後翻面，一顆按鈕 | `facingMode: "user" \| "environment"` |
| **桌面** | 從「內建鏡頭／外接攝影機／擷取卡」裡挑 | `enumerateDevices()` → `deviceId` |

⚠ **不要為了「統一」而把桌面也做成翻面**——桌面的多鏡頭不是前後關係，是一份清單。硬套會做出一個轉了不知道會轉到哪的按鈕。

底層機制**是同一個**：以新約束呼叫 `getUserMedia` → `replaceTrack` 換到既有的視訊 sender。這條路 ADR-0338 已經鋪好，**不需要重新協商**。

## 3. 決策

### 3.1 手機：`facingMode` 翻面

`facingMode: "environment"` 在本專案**已經有實證**——QR 掃描（`apps/mobile/src/native/qr-scan.ts:61`）就是這樣拿後鏡頭的，Android WebView 吃這個約束。所以這不是賭注。

### 3.2 桌面：裝置清單

`enumerateDevices()` 篩 `videoinput`，以 `deviceId` 指定。

⚠ **裝置標籤在取得相機權限前是空字串**（規格如此，防指紋追蹤）。所以清單只在**通話中**（權限已給）才有意義的名稱 ⇒ 入口放通話視窗內，不放設定頁。

### 3.3 只有一個鏡頭就不顯示入口

同 ADR-0338 §4 的立場：**寧可少一個按鈕，也不要一個按了沒反應的按鈕。**

### 3.4 🔴 換鏡頭必須 `stop()` 舊軌

不停舊軌 ＝ **兩個相機同時開著**，指示燈全亮、耗電、部分裝置直接拒絕第二次 `getUserMedia`。

順序：先取新軌 → `replaceTrack` → **才**停舊軌。反過來會有一段沒有畫面的空窗，而且新軌取失敗時就回不去了。

## 4. 順帶修一個現有的錯

`CallScreen.tsx` 的自我預覽寫死 `mirror`：

```tsx
<StreamView stream={localStream} muted mirror />
```

**前鏡頭該鏡像**（照鏡子的直覺），**後鏡頭不該**——後鏡頭鏡像等於把字反過來給自己看。目前寫死，換到後鏡頭就是錯的。

⚠ 只鏡像**自我預覽**，送出去的畫面從來不該鏡像（對方看到的字必須是正的）。這一點目前是對的，不要動壞。

## 5. 買不到什麼

1. **`facingMode` 是偏好不是保證。** 裝置只有一個鏡頭、或系統不回報朝向時，瀏覽器會給它有的那個。所以要以**實際取得的軌**更新按鈕狀態，而不是以「我要求了什麼」。
2. **換鏡頭會有短暫黑畫面**（新軌啟動需時，部分裝置 1 秒以上）。對端看到的是凍結或黑幀，沒有帶內通知說「他在換鏡頭」——這件事值不值得一個信令，我認為不值得。
3. **不處理通話外的鏡頭預覽/測試。** 設定頁沒有「測試我的鏡頭」，那是另一個功能。
4. **桌面清單不隨插拔即時更新**（要監聽 `devicechange`）。首版就讀一次，插拔後要重開通話視窗才會更新。
5. **與畫面分享（ADR-0341）互斥**：視訊 sender 只有一個，分享螢幕時就沒有鏡頭可切。
