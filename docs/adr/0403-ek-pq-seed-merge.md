# 0403. 舊裝置升級後補得回後量子種子：同一把 EK 合併時保留帶種子的那份

- 狀態：已接受（使用者 2026-10-29：「依據你的建議執行」——討論「聯絡人的舊裝置看不出來」後，選先修種子合併、寄件人那邊不做）
- 日期：2026-10-29
- 相關文件：ADR-0365（後量子 EK，種子隨 EK 分發）、ADR-0397（裝置能力回報：跟不上的那台請使用者更新）、ADR-0322 S2（EK per-device 分發）、ADR-0245（多裝置共享 EK、快照 union）、ADR-0325（解不開的密文留著等 EK 到貨重試）

## 背景與問題

ADR-0397 讓「自己有一台裝置跟不上加密方式」在每台裝置上都看得到，提示是「請把它更新到最新版」。可是更新之後**不一定救得回來**。

v0.0.16 以前解析 EK 分發（kind 10042）時只留 `nsec`、`pk`、`at`，會把後量子種子 `pq` 丟掉，存檔裡就是一把沒有種子的 EK。那台升級之後：

1. **重新收到的分發補不上種子。** `receiveEkEnvelope` 是「已經有同一把公鑰就跳過」，帶種子的同一把 EK 進不來。要等下一次輪替（約一週）才有帶種子的新 EK。這段期間別人用混合式寄來的訊息，加上 ADR-0325 留著等重試的那些，全部永遠解不開：重試只在 EK 集合真的變大時觸發，而補不上的那把正是它們需要的。
2. **快照合併會反過來蓋掉別台的種子。** `mergeSnapshotContent` 對同一把公鑰是後到的蓋掉先到的。有裝置不在目錄內時快照會帶 EK 私鑰（ADR-0322 S2 的雙軌期），這時舊裝置那份沒有種子的副本會洗掉新裝置的種子。後果是新裝置也解不開，公告退回 v1，在聯絡人那邊被判成降級（ADR-0365 的 rollback 偵測）。

兩條都先寫成測試、確認會紅，才修。第 2 條原本只是從程式碼推出來的。

### 「聯絡人的舊裝置看不出來」

這次討論的起點是「寄件人看不出聯絡人有一台舊裝置」。核對後的結論是不做寄件人那邊：

- EK 是整個身分共用一把、再分發到每台裝置。寄件人只對那把 EK 加密一次，沒辦法替某一台改用別的方式；看得到也只能轉告對方。
- 能修的只有聯絡人自己，而 ADR-0397 發版後，他只要有一台新版就會看到提示。
- 寄件人那邊的每一種做法都要付隱私或額度的代價，見〈考量的選項〉。

## 考量的選項

- **A. 合併同一把 EK 時保留帶種子的那份（本決策）**：分發與快照兩條路各改一行規則，不動協定、不動 SDK。
- **B. 升級時對沒有種子的 EK 強制輪替**：換一把新的、帶種子的 EK。但舊 EK 上已經寄來的混合式訊息還是解不開，而且每台升級都會觸發一次全身分輪替與重新分發。
- **C. 寄件人那邊顯示「對方有一台舊裝置」**，三種做法都不採用：
  - 讀聯絡人的裝置報告：報告加密給聯絡人自己（ADR-0397），寄件人讀不到。這是刻意的。
  - 聯絡人公開裝置版本或能力下限：全網都看得到他有幾台、各跑什麼版本。ADR-0322 補空槽到 8 的倍數，就是為了藏住裝置數。
  - 每台裝置各回一張送達回條：一樣洩露裝置數，而且每張回條都佔中繼的寫入額度，那是 Cloudflare 免費方案最緊的一項。
- **D. 舊裝置自己回報「解不開」**：舊版沒有這段程式碼，做不到。

## 決策

採 A。

1. **分發**（`RelayChatBackend.receiveEkEnvelope`）：已經有同一把公鑰時，只在本機那份沒有種子、分發那份有的時候才補上 `pq`，其他欄位不動；補上了就算變更，照常存檔並觸發 ADR-0325 的重試。分發那份沒有種子時，本機已有的種子不被洗掉。
2. **快照**（`mergeSnapshotContent`）：同一把公鑰照舊是後到的勝出，**除非那會把種子蓋成沒有**，那時留著有種子的那份。本機沒有、遠端有時照常補上，`changed` 為真，引擎照常觸發重試。
3. 兩份都有種子時照原本的規則。同一把 EK 的種子是一起生的，不應該不同。

## 理由

- 種子是 EK 的一部分（ADR-0365 §3），同一把 EK「有種子」嚴格比「沒種子」完整。合併時丟掉較完整的那份，沒有任何好處。
- 修在合併規則上，舊裝置不需要任何新程式碼以外的配合：新裝置本來就會重發分發，升級後的那台收到就補得上。
- 不做寄件人那邊：受影響、能修的都是聯絡人自己。加一條寄件人看得到的訊號，要拿裝置數或寫入額度去換一個寄件人無從行動的提示。

## 後果

- 正面：
  - ADR-0397 的「請更新那台」真的兌現：舊裝置升級後，下一次收到分發就補上種子，留著的訊息一起補解出來。
  - 雙軌期間，舊裝置的快照不會再把新裝置的種子洗掉，也就不會因此退回 v1、讓聯絡人看到假的降級警示。
- 負面 / 已知殘餘風險：
  - 升級前就超出 ADR-0325 上限的訊息（每身分 50 則、30 天）已經被丟掉，救不回來。
  - 升級後要等新裝置重發分發才補得上。分發在 EK 輪替、目錄變動時重發；中繼上若還留著上一份分發，重連時就會收到。
  - 聯絡人最新的那台停在 v0.0.18–v0.0.20 時，仍然沒有任何一台會提示（那幾版沒有 ADR-0397）。下一次發版後這個空窗才會收掉。
  - 寄件人那邊仍然看不出聯絡人有舊裝置。這是刻意的取捨，見〈考量的選項〉C。
- 後續行動 / 待辦：
  - 下一次發版把 ADR-0397 與本修正一起帶出去。
- 驗證：
  - engine `ek-pq.test.ts`〈舊裝置升級後補得回種子〉：同一把 EK 再收到帶種子的分發時補上種子，之前解不開的訊息補解出來；分發那份沒有種子時，本機的種子不被洗掉。
  - engine `cloud-snapshot.test.ts`：遠端那份沒有種子時本機的種子不被蓋掉；本機沒有、遠端有時補上，而且算變更。
  - 修正前，第一條與第三條是紅的。
