# 0357. 官網自架教學頁：只教學、不動作

- 狀態：已接受
- 日期：2026-09-17
- 相關文件：`docs/research/one-click-relay-deploy-plan.md`（規劃稿）、
  ADR-0090（官網與通訊平面硬隔離鐵則）、ADR-0235（官網 SEO 路由）、ADR-0246（預設語系為 en）、
  ADR-0092＋`docs/NODE-SUBMISSION.md`、ADR-0354（統一節點 Worker）、ADR-0356（App 內建部署器）、
  `docs/SELF-HOSTING.md`／`.en.md`、`apps/website`

## 背景與問題

ADR-0356 讓桌面版的使用者能一鍵部署自己的節點。但三種人被這條路漏掉：

- **用行動端或網頁版的人**——那兩個平台做不到（`api.cloudflare.com` 不送 CORS）。
- **從搜尋引擎找過來的人**——他們還沒裝 App，卻正是最該看到「你可以自己架一座」的人。
- **想改設定、想綁自訂網域的人**——精靈刻意不暴露這些，他們需要完整指令。

而官網現有的「節點」頁只有 51 行、三張步驟卡片，內容停在「wrangler deploy」一句話。
它是**導覽**，不是教學：照著它做不完任何一件事。

同時有一條不能碰的線。ADR-0090 的鐵則寫得很清楚：官網與 E2E 通訊平面**完全分離**，
**永不接觸**使用者資料、金鑰、relay 流量或 npub，且零追蹤零 cookie。一個「自架教學」頁
天然會想長出「幫你部署」的按鈕、想收 token、想確認你部署成功了沒——那每一件都會破鐵則。

## 考量的選項

- **A：擴充現有 `node` 頁**——否決：教學需要的篇幅（三條路線、逐步圖文、常見錯誤）會把
  一張「為什麼要自架」的說明頁撐成一份文件，兩個目的互相稀釋。
- **B：只寫進 `docs/SELF-HOSTING.md`，官網外連過去**——否決：GitHub 的 Markdown 頁
  對非技術使用者是一道門檻，而且拿不到官網的 SEO 與雙語路由。
- **C（採用）：官網新增 `selfhost` 頁為教學主體**，`node` 頁縮回「為什麼」並導向它，
  `SELF-HOSTING.md` 縮成指令速查並指回官網。

## 決策

### 1. 新增 view `selfhost`，`node` 頁保留為「為什麼要自架」

動到的檔案：`routes.ts` 的 `View`／`VIEWS`、`App.tsx` 路由分派、`seo.ts` 標題描述、
`copy.ts` 中英文案、新增 `pages/SelfHost.tsx`。路由與 prerender 測試已按 `VIEWS` 展開，
新頁自動納入涵蓋。

### 2. 🔴 這一頁不做任何動作（ADR-0090 的具體界線）

- **不收 token、不放任何會回傳的表單、不碰 npub、不做部署動作。**
- 不加分析、不加 cookie、不嵌第三方 widget。
- 「Deploy to Cloudflare」按鈕是**純外連**。點下去之後的事全部發生在使用者與 Cloudflare 之間，
  官網不知道、也**不該知道**結果。
- 因此本頁**無法**告訴使用者「你部署成功了」——那需要一個回呼，而回呼就是狀態。
  頁面改為教使用者**自己怎麼確認**（`GET /healthz`，ADR-0354）。

### 3. 內容結構：三條路線並列，各自標明適合誰

| 路線 | 難度 | 大約時間 | 適合 |
| --- | --- | --- | --- |
| 桌面 App 一鍵部署（ADR-0356） | ★☆☆ | 3 分鐘 | 大多數人 |
| 官網 Deploy 按鈕（⏳ 尚未有可按的按鈕，見下） | ★★☆ | 10 分鐘 | 有 GitHub 帳號、不用桌面版 |
| 自己跑 wrangler | ★★★ | 15 分鐘 | 想改設定、想綁自訂網域 |

⚠ **路線二目前只有說明、沒有按鈕**：它需要一個 template repo，而那還在 ADR-0356 的後續行動裡。
頁面必須明確標成「即將提供」，否則讀者捲到路線二會找不到東西可點。

路線二必須**明講它的兩個限制**：會把 repo clone 到你的 GitHub；**部署完網址不會自己回到 App，
要自己複製貼回去**。不寫出來的話，使用者會以為它跟路線一一樣，然後卡在「然後呢」。

路線三的指令一律 `npx --yes wrangler@4`（🔴 **不要用 `pnpm dlx`**，pnpm 10 會以
`ERR_PNPM_IGNORED_BUILDS` 中止），並含統一模式的 `deploy:unified` 與 `run_worker_first` 的理由。

### 4. 要不要花錢：導向官方計費頁，不自己下結論

Durable Objects 的免費層條件變過不只一次。頁面給**實際量級參考**（單人／小圈遠低於額度，
見 ADR-0059／0006 的容量模型）並連到官方計費頁，但**不宣稱**「免費」或「要 $5」。

### 5. 常見錯誤一節：每條都寫「症狀 → 原因 → 怎麼修」

至少涵蓋：token 權限不足、帳號尚未命名 workers.dev 子網域、
統一模式忘了 `run_worker_first` 導致「`/` 回 HTML、WebSocket 握不到手」、DO migration 名稱衝突。

### 6. 誠實邊界寫在頁面上，不藏在 ADR 裡

workers.dev 子網域含你的 Cloudflare 帳號名，會隨分享 ID 外流；自有站下線期間，
落在它上面尚未取件的離線留言要等它復活；統一模式下那台伺服器同時送出客戶端 JS。

### 7. 文件同步：只寫一次

官網 `selfhost` 頁＝主體（中英雙語）。`docs/SELF-HOSTING.md`／`.en.md` 指向它、只留指令速查。
README 的中繼站章節維持現狀（已含兩個部署指令與 `run_worker_first` 警告）。

## 理由

- **教學的受眾與「為什麼要自架」的受眾不同**：後者在決定要不要做，前者已經決定要做。
  同一頁服務兩種人，結果是兩種人都讀到一半就走。
- **官網是唯一能被搜尋到的表面**。把教學放在 GitHub Markdown 等於放棄那些還沒安裝 App 的人，
  而他們正是「去中心化」這個承諾最需要觸及的對象。
- **鐵則寫成頁面規格而不是口頭約束**：ADR-0090 只說「不得接觸」，本 ADR 把它翻譯成
  這一頁**具體不能有什麼**（表單、回呼、分析、成功通知），這樣日後有人想加「部署狀態查詢」
  時會先撞到這份文件，而不是撞到鐵則的解釋爭議。

## 後果

- **正面**：三種被漏掉的人都有路可走；教學有 SEO 與雙語路由；`node` 頁回到它擅長的事。
- **負面 / 已知殘餘風險**：
  - **官網無法確認任何人的部署結果**——這是鐵則的直接代價，不是缺陷。使用者卡住時
    我們看不到，只能靠「常見錯誤」那一節事先攔截。
  - **截圖會過期**：Cloudflare 的儀表板改版會讓路線二、三的圖文失準，而我們不會自動發現。
    ⇒ 截圖一律**不放**在 App 內（App 有自己的精靈畫面），只放官網，且每次改版時一併檢查。
  - **教學與程式碼會漂移**：指令寫在文案字串裡，沒有任何測試盯著它。⇒ 後續行動 1。
  - 路線二依賴官方 Deploy 按鈕的行為，那不在我們控制內。
- **後續行動 / 待辦**：
  1. 讓 `copy.ts` 裡的關鍵指令與 `relay/package.json` 的 scripts 對得起來——至少加一個
     測試斷言「文案裡出現的 pnpm script 名稱確實存在」，否則改了 script 名稱不會有人發現。
  2. `node` 頁底部加「完整教學」導流；`SELF-HOSTING*.md` 改為指回官網。
  3. template repo ＋ 官方 Deploy 按鈕（路線二的落點），與 ADR-0356 §2 共用同一條打包鏈。
