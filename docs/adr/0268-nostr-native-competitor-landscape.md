# 0268. Nostr 生態內的同類產品盤點（研究記錄）

- 狀態：**研究記錄（未決策，本文不改變任何產品行為）**
- 日期：2026-07-28
- 相關文件：**0254**（官網比較頁——只比 Signal／LINE／WhatsApp，**沒有任何 Nostr 生態內的對手**，
  本文補這一塊）、0255（企業版類別比較）、**0257**（盈利可能性與企業服務模式——**§3 對其競爭前提
  提出更新**）、0259／0267（NIP 盤點；0259 §1.3 查出 NIP-EE 已被 Marmot 取代——**§4 說明那份規格
  已經有出貨中的實作**）、0027（群組成對扇出）、0091（MLS 暫緩，已棄用）、0236／0245（前向保密路徑）、
  0237（連線歸屬打穿事件層隱藏）、0061／0065（自足生態、刻意不互通）、0044／0047／0163（企業自架與名冊）
- 資料來源：各專案官方 repo／網站與 2026-07 的公開報導（擷取於 2026-07-28）

> 本文是**研究記錄**。它回答一個既有文件沒回答過的問題：**Nostr 生態裡有沒有同類產品、差在哪。**
> ADR-0254 的比較頁只比主流通訊軟體；對懂 Nostr 的評估者（含潛在企業客戶的技術負責人）而言，
> 第一個問題其實是「那你跟 0xchat／White Noise 差在哪」——**目前倉庫裡沒有答案**。

## 1. landscape：四類，不是一類

| 類別 | 代表 | 與本專案的關係 |
|---|---|---|
| **A. Nostr 原生私訊 App** | **0xchat** | 最接近的同類。Flutter，iOS/Android/桌面；28 個標準 NIP＋3 個自訂；NIP-17＋NIP-EE；含公開頻道（NIP-28）、relay 群組（NIP-29）、zaps、badges。**互通是它的賣點** |
| **B. 以 MLS 為核心的安全通訊** | **White Noise**（Marmot 協定） | 技術上最強的群組 E2EE。Rust 核心＋Flutter；建構於 Nostr＋Blossom＋MLS。**它就是 ADR-0259 §1.3 查到的 Marmot 的參考實作** |
| **C. 支付導向超級 App** | **Keychat** | Signal/MLS 協定跑在 Nostr 傳輸上，**近乎每則訊息輪替收發地址**；ecash 付費投遞。定位是「Bitcoiner 的超級 App」 |
| **D. 自架企業工作區** | **Buzz by Block**（2026-07-21 發布） | 唯一與本專案**商業定位**重疊的。自架 Nostr relay、Tauri 桌面端、Apache-2.0、對標 Slack＋GitHub。**但不是端對端加密** |

一般用途客戶端（Damus／Amethyst／Primal／Coracle）不列入：私訊是它們的一個功能，不是產品。

## 2. 差異：分軸來看

### 2.1 互通性——**最大的結構性差異，而且是雙刃**

A、B、C 三類都把「與整個 Nostr 生態互通」當賣點（帶著身分與聯絡人跨 App 走）。
**本專案刻意相反**（ADR-0061 決策 #5、0065）：自足生態、不與通用客戶端互通。

- **得到的**：所有內容進 Gift Wrap 才有可能——沒有公開 profile、沒有公開社交圖譜、
  沒有公開貼文。互通就必須提供通用客戶端讀得懂的公開形狀，那與 ADR-0002 的前提衝突。
- **付出的**：**零生態網路效應**。0xchat 使用者換 App 還是同一個身分同一批聯絡人；
  本專案的使用者換 App 就是從零開始。這在消費端是實打實的劣勢，**必須誠實列。**

### 2.2 群組加密——**本專案落後，且對手已出貨**

| | 本專案 | White Noise / Marmot |
|---|---|---|
| 群組機制 | **成對扇出**（ADR-0027）：每位成員各一份 Gift Wrap | **MLS** 群組金鑰協商 |
| 每則成本 | O(N)（公告成本隨成員線性成長，ADR-0027 已誠實記為限制） | MLS 樹狀，遠優於線性 |
| 前向保密 | 群組**無**；1:1 有手動 opt-in（ADR-0245，**Phase 3 外部審計未過、不得產線啟用**） | MLS 內建 FS |
| 後向保密（PCS） | **無**（ADR-0091 評估 MLS 後暫緩、已棄用；ADR-0236 明載「完整 PCS／群組走 MLS、延後」） | MLS 內建 PCS |

**這不是可以話術帶過的一格。** 本專案自己的 ADR-0236／0259 都把未來指向 MLS，
而 White Noise 已經在出貨那條路。

### 2.3 元資料——**本專案不是最強的那個**

本專案：Gift Wrap 藏收發雙方（ADR-0002）＋NIP-42 AUTH 預設開（ADR-0057）。
但 **ADR-0237 已自行認定**：每條連線都 AUTH ⇒ **接收端中繼有能力把「誰來拿信」與身分連結**，
事件層藏起來的東西被連線層打穿。

Keychat 的做法（**近乎每則訊息輪替收發地址**）在這一軸上比本專案強。
本專案的答覆只能是 ADR-0237 的 Tier 0/1 承諾工作項——**那是承諾，不是已交付**。

### 2.4 企業與自架——**本專案最有話講的一軸**

| | 本專案 | Buzz | 0xchat / White Noise / Keychat |
|---|---|---|---|
| 自架 | ✅ 自家 relay（Cloudflare Workers＋DO，**設計成跑得進免費額度**，ADR-0109/0244） | ✅ 但需 PostgreSQL＋Redis＋S3/MinIO | ❌ 自備或用公共 relay |
| 端對端加密 | ✅ 全部內容 | ❌ **Block 託管的 relay 上不是 E2E**；E2E（NIP-44）列為「未來考慮」 | ✅ |
| 企業身分 | ✅ **管理者簽章名冊**（ADR-0047，客戶端可驗）＋邀請碼（0156）＋離職接管（0163） | 以網域做社群隔離 | ❌ |
| 定位 | 私密即時通 | Slack＋GitHub 取代品（含 AI agent 身分） | 消費端通訊 |

⇒ **「E2E 加密 ＋ 可自架 ＋ 有企業身分與離職流程」這個交集，目前本專案相當孤單。**
Buzz 佔了自架與企業，但放掉了 E2E；A/B/C 三類有 E2E，但沒有企業面。

### 2.5 產品面完成度——差異比想像中大

本專案已有而 0xchat **尚未有**的：**WebRTC 語音／視訊通話**（0xchat 列為規劃中）。
另有一批同類產品普遍沒有的：檔案傳輸、貼圖／自訂 emoji、敲一下、對話背景、
每對話便條、**共享行程（RSVP／改期／補送／提醒）**、訊息搜尋、高對比與 UI 尺寸無障礙、
桌面三欄與經典佈局。

這是一條**可查證**的差異——但要留意它證明的是「IM 功能完整度」，
**不是安全性**。拿功能表去回應 §2.2 的加密落差是偷換題目。

## 3. ⚠ Buzz 的出現，更新了 ADR-0257 的競爭前提

ADR-0257（2026-07-27）論證「公開 relay 無法盈利、B2B 自架/託管是唯一有毛利的路」，
**當時沒有把任何 Nostr 生態內的企業級對手納入考量**。Buzz 在 2026-07-21 發布，
由 Block 出品、Apache-2.0、可自架、對標 Slack。

這不推翻 ADR-0257 的結論，但**改變了它的論述**：

- 「自架 Nostr 工作區」不再是空白市場，且對手的品牌與資源遠大於本專案；
- 本專案的差異化因此**必須壓在 E2E 上**——那正好是 Buzz 目前沒有的，
  也是本專案唯一無法被資源碾過的立足點；
- 反過來說，**若 Buzz 補上 NIP-44 E2E（它已列為未來考慮），本專案在該軸的優勢就會消失**。
  ADR-0257 §4.2 的託管營收假設應據此重估。

## 4. ⚠ White Noise ＝ 我們自己路線圖指向的那份規格的出貨實作

ADR-0259 §1.3 查出 NIP-EE 已 `unrecommended`、被 Marmot 取代，並建議把 ADR-0027/0236 與
ROADMAP F1/F2 的指標改指向 Marmot（ADR-0260 已改）。本文補上當時沒說的那半句：
**Marmot 不只是一份規格，它有一個在出貨的實作（White Noise），而那個實作正是一個直接對手。**

實務後果有兩面：

- **好的一面**：規格已被真實產品驗證過，本專案日後若走 MLS，不必當第一個踩坑的；
- **要面對的一面**：在「群組 E2EE 誰比較強」這題上，對手**現在就贏**，
  而本專案的答案是「延後」。ADR-0091 暫緩 MLS 的三個理由（多設備、可靠性護欄、複雜度）
  依然成立——但**「對手做到了」是一個新的、當時不存在的反證**，下次重評 MLS 時應納入。

## 5. 誠實結論

**可以講的差異（可查證、對手沒有）**：
1. E2E ＋ 自架 ＋ 企業身分/離職流程的交集（§2.4）；
2. relay 是自家產品且成本模型公開、設計成跑得進免費額度（§2.4）；
3. IM 功能完整度，尤其通話與共享行程（§2.5）；
4. 無公開 profile／無公開社交圖譜——這是不互通換來的（§2.1）。

**必須誠實列的落差**：
1. **群組沒有 FS／PCS**，對手（White Noise/Marmot）有且已出貨（§2.2）；
2. **元資料不是最強**——ADR-0237 已自認連線層打穿事件層；Keychat 的地址輪替更強（§2.3）；
3. **零生態網路效應**，是不互通的直接代價（§2.1）；
4. 1:1 前向保密**尚未可產線啟用**（ADR-0245 Phase 3 審計未過）。

## 決策（研究記錄，未決策）

- 本文**不改變任何產品行為**。
- 不建議把本文的比較放上官網——ADR-0254 的比較頁對象是主流通訊軟體（潛在使用者認得的），
  加入 Nostr 生態內的對手只會替對手做曝光，且 §5 的落差在行銷語境會被斷章取義。
  **本文的讀者是內部決策與企業客戶的技術問答**。

## 後果

- 正面：補上倉庫裡完全空白的一塊（Nostr 原生對手）；為 ADR-0257 的 B2B 論述補上真實競爭者；
  把「我們的未來規格已有對手在出貨」這件事明確化。
- 已知限制：
  - **全部是公開資料閱讀，未實測任何一款**。功能宣稱（尤其「支援某 NIP」）與實際品質可能有落差；
    §2.5 的「0xchat 尚無通話」取自其 repo 的規劃清單，未實機驗證。
  - Buzz 的「非 E2E」取自 2026-07 的報導與其文件，**未讀其原始碼確認**；這一條若要對外使用
    必須先自行驗證。
  - 生態變動快（Buzz 發布距本文僅七天）——引用前應重新確認。
- 後續行動（**皆待決策，本 ADR 不執行**）：
  1. 重評 MLS 時把「對手已出貨」納入 ADR-0091 的暫緩理由檢討。
  2. ADR-0257 §4.2 的託管營收假設，依「Buzz 若補上 E2E」的情境做一次敏感度檢視。
  3. 若要對企業客戶使用 §2.4 的比較表，先實機驗證 Buzz 的加密現況。
