# ADR-0333：行動端的外觀偏好要跨重啟記住

- 狀態：已採用
- 日期：2026-08-05
- 關聯：ADR-0248（初次登入一律明亮）、ADR-0294 §2（裝置層 vs 身分層）、ADR-0167（桌面主色的身分層覆寫）、ADR-0328 §5-4（本問題的發現處）、ADR-0332（外殼／session 的邊界）

## 1. 註解比程式碼樂觀

`apps/mobile/src/main.tsx` 寫著：

> 預設明亮（ADR-0248）；使用者在「設定」改的偏好**由 App 自行讀回**。

但行動端的 `theme`／`locale`／`accent` 三個都只是 `useState(initial*)`——**沒有任何讀回機制**，重開 App 一律回預設。桌面一直有 `nb.theme`／`nb.locale`／`nb.accent`（`theme.tsx`／`i18n.tsx`／`accent.tsx`）。

這是在 ADR-0328 補行動端互動測試時順手發現的（§5-4 記為「未處理」），一直放著。

⚠ 值得記下的是**它為什麼躲過那麼久**：切身分時偏好保留得好好的（同一個元件實例），連 ADR-0328 那條「裝置層偏好必須跨身分保留」的測試都是綠的。**跨身分**與**跨重啟**是兩件事，而測試只覆蓋了前者。

## 2. 決策

在外殼（`MobileApp.tsx`，ADR-0332 的邊界）讀寫三個裝置層鍵，鍵名**與桌面相同**（`nb.theme`／`nb.locale`／`nb.accent`）——同一台裝置的心智模型一致。

`initial*` props 降為「**沒存過時**的預設」。

### 與 ADR-0248 的關係

ADR-0248 要求「所有版本**初次登入**一律明亮模式」。**初次＝沒有存過偏好** ⇒ 「使用者明確選過就記住」不牴觸它；`main.tsx` 給的預設仍是 `light`。

### 壞掉的偏好不得讓 App 起不來

三個 `read*` 都驗值：主題只認 `light`／`dark`、語言必須在 `LOCALES` 內、主色必須是合法的 `#` 色碼。不合法一律回退，KV 整個不可用時也只是記不住——**不拋**。

## 3. 刻意不做的事

🔴 **不順手補主色的身分層覆寫。** 桌面有（ADR-0167：`nb.<pubkey>.accent` → `nb.accent`），行動端沒有。補上去是另一個決策（「要不要讓工作身分有自己的顏色」），不該混在一個修持久化的改動裡。

## 4. 覆蓋

- 單元測試 6 條：往返、沒存過回退、**值壞掉一律回退**、KV 不可用不拋、主色設回預設會清鍵、與桌面同鍵名。
- 互動測試 1 條：改成英文＋深色 → **卸載重掛（模擬重開 App）** → 偏好仍在。

⚠ 這條互動測試補的正是 §1 說的那個縫：既有的「跨身分保留」測試在同一個元件實例內，**碰不到重啟**。
