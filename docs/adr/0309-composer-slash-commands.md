# 0309. Composer 斜線指令：行首 `/` 開命令選單

- 狀態：已接受
- 日期：2026-08-03
- 相關文件：ADR-0308（Composer 輸入層統一——本 ADR 接在該層之上）、ADR-0037（建議列鍵盤契約）、
  ADR-0050（@提及建議列的樣板）、ADR-0048（企業政策停用檔案／貼圖／通話）、
  ADR-0049（公告頻道唯讀）、`packages/core/src/slash-command.ts`

## 背景與問題

桌面對話視窗的動作密度很高（貼圖、相簿、附檔、錄音、限時訊息、搜尋、成員、匯出、歷史、
通話、震動、AI 改寫…），但工具列只放得下六顆鈕，其餘散落在標題列與右欄。

更關鍵的是：`ConversationWindow.tsx` 全檔 `grep ctrlKey|metaKey` **零命中**——
在 ADR-0308 引入 `Ctrl/Cmd+Enter` 之前，這個視窗**沒有任何鍵盤加速路徑**，所有動作都得用滑鼠。
而本專案是 Tauri 與瀏覽器同一份建置（ARCHITECTURE §3），全域組合鍵在瀏覽器版會撞瀏覽器保留鍵，
因此組合鍵並不是一條乾淨的路。

## 考量的選項

- **選項 A：Ctrl+K 命令面板。** 會長成與工具列平行的第二套入口（兩個 SSOT），
  且在瀏覽器版有鍵位衝突風險。否決。
- **選項 B：擴充工具列。** 六顆鈕已經是經典佈局的視覺上限（行動端更已因此折行，ADR-0287）。否決。
- **選項 C（採用）：行首 `/` 觸發建議列**，沿用 ADR-0308 統一後的輸入層與既有建議列樣式。

## 決策

1. **比對規則**（`packages/core/src/slash-command.ts`，純函式）：
   - 觸發位置：`/` 必須位於**草稿開頭或某一行的開頭**，其後到游標之間不含空白與第二個 `/`。
     正規式 `(?:^|\n)\/([^\s/]*)$`——沿用既有三個比對器「只看游標前尾端」的慣例。
   - `/usr/bin` 這類路徑因為含第二個 `/` 而不觸發；`3/15` 這類日期因為 `/` 不在行首而不觸發。
   - **空查詢（只打了 `/`）即列出全部可用命令**（上限 8）。這與 ADR-0037 的「≥2 字」規則不同，
     理由見下：`/` 位於行首是刻意輸入，不像貼圖觸發字那樣任何字元都可能誤觸。
   - 比對 `id` 與 `aliases`（含繁中別名）的前綴，命中為零則回 `null`（不顯示空列）。
2. **命令目錄放 `packages/core`**，命令**行為**留在桌面 UI：core 只認識 `{ id, aliases }`，
   不認識 React、不認識 localStorage。行動端日後要用時可共用同一份比對器。
3. **v1 命令集**，分兩類：
   - **插入型**（直接復用 `ComposerInsert` 的 `InsertTemplate`，**不新增第二套模板來源**）：
     `/code`、`/list`，以及 `CALLOUT_MENU` 的八個 callout（`/note`、`/info`、`/tip`、
     `/success`、`/question`、`/warning`、`/danger`、`/quote`）。
   - **開面板型**：`/sticker`、`/album`、`/file`、`/search`、`/members`、`/export`、`/history`。
4. **v1 明確排除**：`/nudge`、`/call`、`/voice`、`/unsend`。
   前三者不可逆或會啟動硬體（震對方、撥號、開麥克風），第四者是破壞性動作。
   ADR-0037 已立過「不可逆動作不掛在快捷路徑上」的原則，這裡沿用。
5. **情境過濾**：命令目錄依當下情境動態裁切——`readOnly` 公告頻道（ADR-0049）不顯示任何命令；
   `stickersDisabled`（ADR-0048）拿掉 `/sticker`；無 `onSendFile` 拿掉 `/file`；
   非群組拿掉 `/members`；無 `onExport`／`onHistory` 各自拿掉。**不列出按不到的東西。**
6. **鍵盤與 UI**：完全沿用 ADR-0308 的統一鍵盤鏈與既有 `trigbar` 樣式——
   `Tab`／`Enter` 接受（斜線是填入型與開面板型，屬非破壞性）、`↑`/`↓` 移動、`Esc` 關閉。
   接受後從草稿中移除 `/命令` 片段。
7. **純本機**：命令比對在已解密的草稿上進行，不進任何事件、不寫 rumor、不同步到其他裝置——
   與 `calc.ts`／`date-detect.ts` 同一條規則。

## 理由

- `/` 是這個雙棲架構下唯一不需要平台特例的鍵盤入口。
- 沿用建議列而非另開面板，讓斜線指令成為第五種建議來源，而不是第二套 UI 慣例。
- 插入型復用 `InsertTemplate` 是 Fix First 的直接應用：`➕` 選單與 `/` 選單指向同一份模板定義，
  日後加一個 callout 型別兩邊同時得到。
- 排除不可逆動作讓 v1 的誤觸成本上限＝「草稿裡多了幾個字」，可用 Ctrl+Z 或退格還原。

## 後果

- 正面：鍵盤使用者第一次能不碰滑鼠完成大部分對話動作；工具列不必再長；
  新增動作只要往目錄加一列。
- 負面 / 已知殘餘風險：
  - 行首打真正的斜線（例如貼一段以 `/` 開頭的路徑後再打字）會彈出選單，需 `Esc` 關閉。
    這是空查詢即列全部的代價，已知並接受。
  - **八個 callout 落在 `SLASH_SUGGEST_MAX=8` 的截斷之外**：只打 `/` 時看到的是
    `code`／`list` 與開面板型命令，callout 需再打幾個字（`/ti` → tip）才會出現。
    callout 的**發現**入口仍是 `➕` 選單，`/` 是給已經知道要什麼的人用的加速路徑。
  - **行動端不做**：手機軟鍵盤打 `/` 要切符號頁，價值低；且行動端 composer 目前只有 mention 建議
    （ADR-0308 §3）。比照「企業主收儲存槽落盤限桌面」的先例，功能可以只在桌面存在。
- 後續行動 / 待辦：
  - `/timer`（限時訊息）需要決定是開子選單還是循環切換，v1 未收；
  - 若日後要收 `/nudge`／`/call`，必須先決定二次確認的形狀，不得直接接上 `Tab`。
