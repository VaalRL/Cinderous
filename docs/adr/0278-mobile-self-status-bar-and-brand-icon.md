# ADR-0278：行動端聊天頁的自己狀態列，與 Android 品牌啟動圖示

- 狀態：已接受
- 日期：2026-07-29
- 相關：ADR-0142（自訂狀態文字）、ADR-0154（廣播頭像）、ADR-0164/0168（狀態持久與隱身）、ADR-0171（狀態廣播節流）、ADR-0274（Capacitor 打包）、ADR-0277（行動端正式進入點）

## 脈絡

ADR-0277 讓 APK 首開變成真的 App 之後，實機看到兩件不對的事。

### 一、改狀態要離開聊天、切到設定分頁

行動端把「上線狀態」與「自訂狀態文字」放在**設定分頁**裡（`SettingsScreen` 的 `settings_status` 區段）。
可是改狀態是高頻操作——桌面版一直把它擺在聯絡人清單正上方（`DeckSidebar` 的 `dsb__me`：
頭像、名稱、狀態選擇、狀態文字四件一列），行動端沒有對應的東西。

### 二、啟動圖示是 Android Studio 的預設機器人

`apps/mobile/android/app/src/main/res/` 底下整套 `ic_launcher*`（各密度 PNG ＋ 綠色格線背景向量
＋機器人前景）都是 `cap add android` 產生的**樣板預設值**，從未換過。
專案其實已有品牌圖 `apps/desktop/src-tauri/icons/cinderous-ember.svg`
（深藍圓角底 `#0f1f3a` ＋ 橘色漸層火焰 `#e8531a`→`#ffab3d` ＋ 內焰 `#ffd66b`），
桌面版在用，行動端沒接上。裝起來在桌布上是一隻綠色機器人。

## 決策

### 1. 聊天清單頂部加「我」狀態列

新增 `SelfStatusBar`：頭像（含狀態點）＋名稱＋狀態三選一＋自訂狀態文字輸入，
擺在 `ChatsListScreen` 標題列**之上**。以 `self` prop 傳入，未提供＝不顯示
（示範後端沒有 presence 可廣播，與其他真實 relay 功能同一個閘）。

**狀態控制項抽出共用**：`StatusSegments` 由狀態列與 `SettingsScreen` **共同使用**。
若讓聊天列自己再寫一份三選一，同一個開關就會有兩套樣式與 testID 要各自維護——
這正是 Fix-First 要避免的平行路徑。設定頁的狀態區段保留（它同時承載「正在聽」與隱身開關），
只是內部換成共用元件。

**隱身時狀態點畫成離線**（`STATUS_COLORS.offline`）並加註「隱身」。
隱身（ADR-0164）代表對外完全不廣播；若這裡照著 `status` 畫成綠色「線上」，
畫面就在告訴使用者「別人看得到我在線上」，而事實相反。UI 不該說謊，這條有紅字測試鎖住。

自訂狀態文字沿用既有節流語意（ADR-0171）：逐字更新本機、廣播由 `MobileApp` 以 ~600ms 合併，
不逐字打中繼、也不外送打到一半的文字。這裡只是換個位置顯示，沒有另開一條廣播路徑。

### 2. Android 啟動圖示換成品牌火炭

一律改用**向量**，不再帶各密度 PNG：

| 資源 | 內容 | 適用 |
| --- | --- | --- |
| `drawable-v24/ic_launcher_foreground.xml` | 火焰，含原稿漸層 | API 24+ |
| `drawable/ic_launcher_foreground.xml` | 火焰，純色（漸層需 API 24） | API 23 |
| `values/ic_launcher_background.xml` | 背景色 `#0F1F3A` | 自適應背景層 |
| `mipmap-anydpi-v26/ic_launcher{,_round}.xml` | 自適應圖示（背景＋前景） | API 26+ |
| `mipmap/ic_launcher{,_round}.xml` | 完整圖（自帶圓角／圓形背板） | API 23–25 |

前景 viewport 直接用原稿的 1024 而非 108，路徑座標得以原封不動搬過來（少一次換算＝少一個出錯點）。
安全區驗算：火焰下緣圓心約 (512,640)、半徑約 190 → 距圖示中心 128+190 = 318 < 338
（＝66% 安全圈半徑）；尖端 y=200 距中心 312 < 338。任何遮罩形狀都裁不到。

`minSdkVersion` 是 23，而自適應圖示要 API 26，所以 API 23–25 仍需一份完整圖——
用無密度限定詞的 `mipmap/*.xml` 向量供其取用，省掉一整套點陣圖，也不會有哪個密度忘了更新。

## 後果

**正面**

- 改狀態變成聊天頁上就能做的事，與桌面同一個心智模型。
- 同一個狀態控制項只有一份實作。
- 桌布上是品牌火炭而非預設機器人；向量圖示在任何密度都銳利，且不佔 APK 體積。

**負面／代價**

- 聊天清單頂部變高，列表可視區變小。狀態列是靜態高度（未做收合），小螢幕上會少約一列。
- API 23 的火焰是純色而非漸層。形狀相同，退化的只有漸層。
- `cap add android` 若重跑會把 `res/` 整套還原成樣板預設——與 ADR-0274 記錄的
  manifest 權限、toolchain、版號同一類問題，本 ADR 的資源表即為重建依據。

**待辦**

- 實機驗收：桌布圖示為深藍底火炭（圓形與方形啟動器各看一次）；聊天頁頂部狀態列可改狀態與文字。
- 未處理但已發現：`AndroidManifest.xml` 的 `android:allowBackup="true"` 是 `cap add android`
  的預設值，代表 app 私有資料可被 Android 自動備份上傳。落地資料本身有加密
  （DEK 由 nsec 導出、nsec 以 Argon2id 包裹），但「預設把資料複本送出裝置」與本專案的
  隱私預設立場不一致。此事超出本 ADR 範圍，另立 ADR 處理。
