# 0261. 行動端行程 UI（ADR-0260 的最後一塊）

- 狀態：**已接受（已實作＋全測綠**：行動端行程分頁、日期偵測兩處提示、權威三層一致。
  ADR-0260〈後續行動〉的「行動端 UI」自此清空。）
- 日期：2026-07-28
- 相關文件：**0260**（共享行程實作——本 ADR 只補其 UI 的行動端那一半，協定/權威/儲存全部共用）、
  0259（設計來源，§1.6 偵測不導覽、§1.7 主揪權威）、0183（輔助面板＝行程分頁的家）、
  0085/0087（行動端畫面與分頁結構）、0234（行動端破壞性動作的二次確認形態）、
  0037/0097（偵測→提示，不代替使用者行動）；
  `apps/mobile/src/screens/{CalendarPanel,ConversationScreen}.tsx`、`apps/mobile/src/MobileApp.tsx`

## 背景

ADR-0260 把共享行程做完了——但只做到桌面。引擎層（協定、權威、儲存、補送、保留上限）本來就
是共用的，`apps/mobile` 缺的**只有畫面**。本 ADR 記錄「只有畫面」實際上仍需要決定的三件事。

## 決策

### 1. 住在既有的輔助面板裡，不新造導覽層

行程分頁掛在 ADR-0183 的輔助面板（📋）內，與媒體／對話串／便條並列——與桌面的「右欄多一個
分頁」是同一個決定在小螢幕上的樣子。**不新增底部分頁**：行程是「某個對話的」，不是全域的，
放進 `BottomTabs` 會暗示錯誤的資料歸屬。

分頁標籤帶行程數；**沒有 `onCalendarPublish`（示範後端無此能力）＝分頁完全不出現**，
日期也完全不偵測——不給做不到的事的提示。

### 2. ⚠ 時間輸入：桌面的 `datetime-local` 在這裡不存在

桌面用 `<input type="datetime-local">`。行動端沒有這個東西——本 repo 的 `react-native-web`
ambient 宣告刻意只收斂到日後上真 RN 也成立的那些 prop，而真 RN 更沒有 `type`。
硬要使用者在手機上打 `2026-08-01T09:00` 是最糟的選項。

故改為**相對調整**：一行人看得懂的時間 ＋ 天／時／分三組 ▲▼ 鈕，長度用 chip 選
（不設／1 小時／2 小時／整天）。兩個附帶好處：

- **存的是「長度」不是絕對結束時間**：改開始時間時結束跟著走，**不會留下「結束早於開始」
  的壞狀態**——桌面版得靠送出時檢查才擋得住的那個。
- **最常見的路徑根本不用調**：從對話中點日期進來時，開始時間已經是對的。

### 3. ⚠ 預填狀態放在呼叫端，不是元件內

**行動端的測試環境是純 SSR**（`vite.config.ts` 的 `environment: "node"`＋
`renderToStaticMarkup`）——**點不了任何東西**。

第一版把「點日期 → 開面板 → 切到行程分頁 → 預填」整串做成 `ConversationScreen` 的內部
state，寫完才發現：這條路徑**只能靠點擊觸發，SSR 一行都測不到**。這正是 ADR-0260 §7 記過的
同一類錯誤（當時是 `useEffect` 在 SSR 不執行）換了個樣子再出現一次——**「測不到」在這個
專案裡等於「沒做」**。

改為 `onPickDate` 往上、`calendarDraft` 往下，狀態由 `MobileApp` 持有：與桌面同形，而且
SSR 測得到（給 draft → 斷言面板開著、分頁是行程、表單已開）。分頁切換一樣用
**render 期間調整 state**（derived-state-from-props），不用 `useEffect`。

**`calendarDraft` 帶 `convo`**：對話畫面以 `key={activeId}` 重掛，但 `MobileApp` 的 state 不會
——不記是哪個對話的話，換對話回來會冒出上一個對話的預填表單。

### 4. 權威與破壞性動作：與桌面逐條對齊

- **非主揪連編輯／取消鈕都不出現**，不是按了才被拒。三層一致（core／engine／UI）的 UI 那層
  在手機上也得成立，否則「桌面改不動、手機改得動」這種話就會有人信。
- **RSVP 名單只列要來與也許**，不列缺席者。
- **過去的行程留著但退到背景**（本機是真實來源，不刪）。
- **取消要二次確認**：手機沒有桌面的對話框元件，沿用 ADR-0234 的行動端形態
  ——**先出確認鈕，再按才真的送**，絕不一按就發生。

### 5. `calendarNameFor` 與 `nameFor` 分開

`nameFor` 只在群組提供（用來在氣泡上標發送者）。行程在 1:1 也要列得出「誰要來」，
兩者的提供條件不同，**共用會讓 1:1 的參與者名字全變成公鑰片段**。故另開一個 prop。

同理，`selfPubkey` 過去只在群組隨 `groupProps` 傳入——照舊的話，**自己在 1:1 開的行程會被
判成別人的，變成「改不動自己的行程」**。改為一律傳入。

## 後果

- 正面：ADR-0260〈後續行動〉清空；行事曆在桌面與行動端行為一致。
  **引擎層零改動**——這一整塊確實只是畫面。
- 負面 / 已知缺口：
  - **時間調整是 ▲▼ 而非原生日期選擇器**：上真 RN 後應換成平台原生 picker
    （`react-native-web` 這層拿不到）。目前的形態不阻礙那次替換——輸入的是 unix 秒，
    換的是取得它的方式。
  - **提醒**：已由 **ADR-0262** 補上（兩端 UI 皆已接）。
- 測試：行動端 14（分頁顯示條件與行程數、draft → 開在行程分頁且表單已開、**沒有 draft 就不
  自動開**、主揪/非主揪各自看到什麼、取消要按兩次、RSVP 名單不列缺席者、過去的退到背景、
  空狀態、日期標記四條——含**無能力就不偵測**與**已收回不掃**）。
  全工作區綠：core 513／engine 380／desktop 573／relay 197／**mobile 211**；`pnpm -r typecheck` 綠。
- 過程中修掉一個**自己寫的弱斷言**：RSVP 名單測試原本對整份 HTML 斷言 `"我"`——那個字在畫面
  各處都有，等於沒測。改為只比對 `cal-going` 節點本身的文字。
  另外「過去的行程退到背景」原本斷言 `opacity:0.5`，但 **RN-web 把樣式編成雜湊 class 名**，
  斷言不到；改為讓過去的項目帶自己的 `testID`。
