# 0314. FS 停用機制：接上早已造好的「明示退場」

- 狀態：已接受
- 日期：2026-08-03
- 相關文件：ADR-0306 D3.3c（造出 `FS_RETIRED` 原語，但沒有任何地方寫入它）、
  ADR-0245（opt-in FS）、ADR-0302 §2（四態能力解讀）、ADR-0313（自動輪替）、
  `packages/core/src/subkey.ts`、`packages/engine/src/backend/relay-backend.ts`

## 背景與問題

**啟用確認對話框對使用者說謊。** `fs_enableConfirm` 的第四句是：

> ・你可以隨時關閉；本機歷史與身分都不受影響。

但引擎沒有 `disableFs()`，桌面與行動端啟用後也只顯示「立即更換金鑰」——**沒有關閉的路**。
實務上啟用是單向的。

更精確地說，缺的只有**一半**：ADR-0306 D3.3c 已經把難的那半做完了——

- `FS_RETIRED = "none"`（明示退場的能力值）已定義；
- `readFsCapability()` 已能讀出 `retired`；
- 收件端 `switch` 已有 `case "retired": this.unpinFs(sender)`。

**沒有任何地方寫入 `"none"`。** 原語造好了，開關沒接。

而這個原語存在的理由本身就說明了為什麼不能隨便接：D3.3c 的原話是「沒有它，
『刻意停用』與『被攻擊剝除 EK』在收件端**看起來一樣**，會永遠觸發降級警告」，
而那句警告的意思是「對方可能正在被攻擊」。**把停用實作成「把 `fs` 欄位拿掉」
＝讓每個釘選過你的聯絡人永久看到一句關於你的假警報。**

## 考量的選項

- **選項 A：不做停用，改文案（把「可以隨時關閉」刪掉）。** 誠實了，但把一個
  **實驗性、未經審計**的功能做成單向開關，等於要求使用者在資訊不足時做不可逆決定。
  與 ADR-0306「實驗性、預設關」的整個立場矛盾。否決。
- **選項 B：停用＝把 `fs` 欄位從個人檔拿掉。** 即 `absent`。這正是 D3.3c 造 `FS_RETIRED`
  要避免的：對已釘選你的人，`absent` 觸發 `fsWouldDowngrade` ⇒ 永久假警報。否決。
- **選項 C（採用）：停用＝廣播 `fs: "none"`（明示退場）＋保留金鑰讓它自然老化。**

## 決策

1. **新增 `disableFs()`（引擎）**，做三件事：
   - `fsState.enabled = false`，並記 `retired = true`；
   - **保留現有 EK 私鑰**，交給既有的 grace 修剪自然老化；
   - 清 `profileSentTo` 並重播個人檔 → 帶 `fs: FS_RETIRED`。
2. **`retired` 需要一個持久旗標**，不能用 `enabled === false` 推導：
   「從未啟用過」與「啟用過又關掉」在個人檔上必須是 `absent` 與 `"none"` 兩種宣告。
   前者是絕大多數使用者，多送一個 `"none"` 等於對全網宣告一件沒發生過的事。
3. **停用後不刪金鑰、不立即失去解密能力**。理由：停用當下仍有**在途訊息**加密到我的 EK
   （對方尚未學到我退場）。立刻刪＝那些訊息靜默消失。讓 grace 修剪照常運作即可——
   7 天後自然回收，届時對方早已學到退場。
4. **停用後不再發 10040**；既有的可取代事件由中繼 TTL 自然過期。
5. **重新啟用**：`enableFs()` 清掉 `retired`、生成新 EK、恢復週期（ADR-0313）。冪等。
6. **UI**：桌面與行動端在「已啟用」狀態下，除了「立即更換金鑰」再加一顆「停用」。
   停用需二次確認，且**確認文案必須說明會發生什麼**——不是「確定嗎？」而是
   「之後送出的訊息不再有前向保密；已經送出的不受影響；本機歷史與身分不變」。

## 理由

- **選項 C 是唯一讓「停用」與「被攻擊」在收件端可區分的作法**，而那個可區分性正是
  D3.3c 花力氣造 `FS_RETIRED` 的原因。不接上它，等於白造。
- **不可偽造性已經有了**：`fs` 寫在**簽章個人檔**內（ADR-0245 §81），攻擊者無法偽造
  退場宣告來剝奪你的 FS；他最多扣住你的新個人檔，而那樣對方仍看到舊的 `ek-v1`、仍然警告
  ⇒ **失敗方向落在安全側**。這個性質在停用路徑上原樣成立。
- **保留金鑰**是「不要用一個安全動作製造一次資料遺失」的一般原則；FS 的價值來自
  **時間到了才刪**，不是**立刻刪**。

## 後果

- 正面：確認對話框說的話變成真的；使用者可以在資訊不足時安全地試用一個實驗性功能；
  `FS_RETIRED` 原語從死碼變成活的。
- 負面 / 已知殘餘風險：
  - **停用是公開可見的**：`fs: "none"` 寫在給聯絡人的簽章個人檔裡。這是必要的——
    不告訴對方就等於讓他繼續以為你有 FS。
  - 停用後 7 天內仍持有 EK 私鑰 ⇒ 那段期間的 FS 保護實際上還沒生效。
    這與正常運作時的 grace 語意一致，不是新的弱點。
- 後續行動 / 待辦：無。
