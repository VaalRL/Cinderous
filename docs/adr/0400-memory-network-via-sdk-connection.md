# 0400. 記憶體測試網路也走 SDK 的連線層

- 狀態：已接受（使用者 2026-10-29：「繼續」——研究後建議的兩步，第一步是 ADR-0399，這是第二步）
- 日期：2026-10-29
- 相關文件：ADR-0398（真實網路連線改由 SDK 負責）、ADR-0399（記憶體網路的連線真的能關）、ADR-0385（認證前送出）、ADR-0379（容量訊號相容）、ADR-0109（心跳握手）、ADR-0121（請求區）

## 背景與問題

ADR-0398 之後，真實網路的連線走 SDK 的 `RelayPool`，記憶體測試網路卻還是 core 的 `RelayClient`。引擎 800 多個測試驗的是一條**正式環境不走**的路：SDK 的驗簽、以 id 去重、NIP-42、補訂閱、拒收分類，在測試裡一個都沒有被碰到。

研究結果（ADR-0399 記錄）：改走 SDK 沒有語意上的退步，要改的是 28 個時序測試、3 個容量相容測試、1 個心跳測試。

## 決策

1. **轉接層搬到 core**：`connectRelay(url, handlers, onStatus?, { createSocket? })`（`packages/core/src/relay-connection.ts`），內容就是 ADR-0398 的轉接規則，只多了可以注入 socket。`RelayConnection`、`RelayUnavailable` 也一起搬過去，engine 照原名轉出。engine 的 `webSocketConnector(url)` 變成一行：`connectRelay(url, handlers, onStatus)`。
2. **記憶體網路的 `connect()` 呼叫 `connectRelay`**，注入一個記憶體 socket：
   - SDK 掛好 open／message／close 就**同步開啟**；
   - 收發同步，接到 `RelayCore`。
   所以整個網路除了 OK 以外，時序跟以前一樣。`close()` 照 ADR-0399 真的斷線。
3. **`connectDirect()`** 保留舊的直連（core `RelayClient`，同步、OK 立刻回），只給展示模式（`BrowserChatBackend`）與桌面示範頁用。它們不需要正式環境的連線行為，也不該多背 SDK 連線池的計時器。
4. **`tap` 選項**：側錄每一個訊框（方向＋原始 JSON）。連線層只把結果交給引擎，OK 的說明文字（`warning: near-full:`）和 NOTICE 的位置要在線路上看。

## 理由

- 測試走的就是正式環境的路。以後 SDK 的修正（或退步）在引擎測試裡就看得到，不必等真機。
- 只換 socket、不換連線層，記憶體網路就沒有自己的一套連線行為要維護。

## 後果

- 正面：
  - 引擎測試第一次跑在 SDK 連線層上：驗簽、去重、NIP-42、補訂閱都在。
  - 遷移時挖出一個**既有的空包彈**：心跳「防風暴」測試（ADR-0109）少了 `acceptRequest`。ADR-0121 之後，Bob 根本沒訂 Alice 的心跳，「不回發」是因為沒收到，不是因為已經活躍。在 ADR-0399 的分支上把防風暴的條件拿掉，原本的測試照樣通過。現在補上接受、加上「握手真的發生了」的前提斷言。
- 負面 / 殘餘：
  - OK 晚一個微任務以上，發布本身也是非同步送出。改了 28 個測試：在動作之後 `await settle()`（只排微任務，假時鐘下也能用）；假時鐘的重試測試改用 `advanceTimersByTimeAsync`。
  - 有節流的外送匣（檔案分塊）用的是真實時間：以前 OK 同步回、在途名額立刻空出來，現在晚一步，最後幾塊可能要等下一次計時器。relay 檔案暫存的測試在 CI 上因此不穩（本機約六成失敗），改成等收件端收齊（`vi.waitFor`），本機連跑 10 次都通過。
  - 3 個容量相容測試改成用 `tap` 在線路上記錄。送訊迴圈改成一則一則等 OK，因為外送匣有在途上限。
  - 心跳防風暴測試：同一秒內容相同的心跳 id 一樣，對方的 SDK 以 id 去重、根本看不到第二顆，測試會變成空包彈。所以第二顆晚兩秒發，改在線路上數送出的心跳。
  - 「關了之後不再處理」那條斷言改成直接看中繼的狀態（`core.exportConn`）。SDK 收到不認得的訂閱 id 會丟掉，只看收件端看不出中繼有沒有忘掉訂閱。
  - 記憶體 socket 不再自己擋「關了還送」：SDK 關了就不送，那道檢查測不到。「關了送不出」由連線層保證，ADR-0399 的端到端測試照樣釘住。
  - 展示模式仍走直連，跟正式環境不同路。它只是不設中繼時的展示，沒有可靠性要求。
- 驗證：
  - 套件：core 696、engine 852、relay 203（新增 6 個）、desktop 835、mobile 514、cli 30，全部通過。
  - relay 新增 6 個測試：同步開啟、認證後訂閱與發布、以 id 去重、OK 晚一個微任務且帶中繼原話、`tap` 的方向、`connectDirect`。
  - 破壞測試 6 項，每項都至少讓一個測試失敗：
    - 心跳不論是否閒置都回發；
    - `connect()` 改回直連；
    - `tap` 漏記中繼送來的；
    - 斷線不讓中繼忘掉訂閱；
    - 舊連線的 `close()` 不檢查是不是自己；
    - 連線層把收下的 OK 當拒收。
