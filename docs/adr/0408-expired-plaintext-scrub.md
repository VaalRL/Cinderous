# 0408. 到期的限時訊息從本機刪掉明文

- 狀態：已接受
- 日期：2026-10-30
- 相關文件：ADR-0013（限時訊息）、ADR-0406（行動端到期處理，選項 C）、ADR-0111／0126（封存）、ADR-0071（雲端快照）、ADR-0094（匯出）、ADR-0234（無痕收回）

## 背景與問題

ADR-0013 與 ADR-0406 做到的是「到期後畫面不顯示」：原文、檔名、縮圖都還留在本機。這些明文會出現在：

- 本機儲存的熱區：瀏覽器 localStorage、桌面版的加密分部檔；
- 封存（ADR-0111）：熱區超過上限的舊訊息會搬進去。封存只能追加，事後改不了；
- 匯出（ADR-0094）：會把原文寫成 TXT／Markdown／JSON；
- 加密雲端快照（ADR-0071）：快照在中繼上一放好幾天，比訊息本身活得久。

使用者 2026-10-30 要求實作 ADR-0406 列的選項 C：到期後由 engine 真的刪掉明文。

## 考量的選項

- A. 維持現狀，只在畫面上遮掉。
- **B. 到期時就地清掉熱區的原文與檔案 metadata，留下佔位。封存、匯出、快照各自擋掉。**
- C. 到期時把整則訊息刪掉，不留佔位。對話裡會憑空少一則，回覆引用也指不到東西。而且這跟「無痕收回」（ADR-0234）是不同的語意，使用者選限時訊息時並沒有要求不留痕。

## 決策

採用 **B**。

- **儲存層 `AppStorage.scrubExpired(now)`**：
  - 對已到期的訊息，就地把 `text` 清成空字串、拿掉 `file`（含檔名與縮圖），保留 id、時間、`expiresAt` 當「訊息已到期」的佔位。
  - 回傳動到的對話鍵與下一則到期的時刻。
  - 已經清過的不再算，所以重複掃描不會一直重寫。
  - `MemoryStorage` 實作；`LocalStorage` 與桌面的 `TauriStorage` 委派給它，再把動到的對話落地。
- **engine 觸發**（`RelayChatBackend`）：
  - `start()` 時先掃一次，清掉關機期間到期的，然後才回放歷史。
  - 之後只排一個計時器，設在下一則到期的時刻再加 50ms。新的限時訊息進來（收到的一對一與群組訊息、自己送出的一對一訊息）時，如果它比已排的更早到期就改排。上限約 24.8 天，超過就分段排。
  - `stop()` 時清掉計時器。
- **封存**：封存只能追加。限時訊息搬進封存時就拿掉原文，不等它到期（`redactedCopy`）。
- **匯出**：已到期的只留佔位。TXT／Markdown 寫「（已到期）」，JSON 寫 `expired: true`、不帶 `text` 與 `file`。這也擋掉熱區還沒清到的和舊版封存裡的。
- **雲端快照**：建快照時跳過所有限時訊息，包括還沒到期的。還原舊版快照時，已到期的也不補回。

## 理由

- 佔位要留：對話順序、回覆引用、已讀水位都依賴這則訊息存在。只拿掉內容就和 ADR-0013 的「訊息已到期」顯示一致。
- 就地清除是最小的改動：三種熱區實作都委派給 `MemoryStorage`，只要寫一份。
- 封存沒有改寫 API。為了限時訊息加一個「改寫封存塊」會動到 OPFS 與桌面兩種封存實作，還要處理寫到一半失敗的情況。限時訊息最長 7 天，要被擠進封存，同一個對話得在 7 天內有超過熱區上限的新訊息。這很少見，但使用者把保留上限調小時就會發生。所以改在進封存時就去掉原文；代價是封存裡看不到「還沒到期」的限時訊息原文。
- 快照全部跳過限時訊息：快照是給換機與還原用的，留存時間不受訊息本身的到期時間約束；限時訊息本來就不該被搬到新裝置長期保存。
- 計時器只排一個，跟 ADR-0406 的行動端重繪時鐘一樣，不做每秒掃描。

## 後果

- 正面：限時訊息到期後，本機儲存、新進封存的內容、匯出與雲端快照都不再有它的原文與檔名。
- 負面 / 已知殘餘風險：
  - **這版之前已經搬進封存的限時訊息，原文還在封存裡**（封存改不了）。畫面、封存搜尋、匯出都已經擋掉（ADR-0406、本 ADR），但檔案層還在，直到該對話的封存被整個刪掉。
  - **已經另存到磁碟的檔案不刪**：那是使用者自己選位置存下的檔案，App 不去動它。
  - **對方那端要對方也更新到這一版**才會清。
  - 從畫面、記憶體或作業系統層級（交換檔、備份軟體）流出的副本，App 管不到。
  - 封存裡還沒到期的限時訊息只剩佔位。
  - 大量限時訊息時，每次到期都要掃一次所有對話。限時訊息本來就少，目前不另建索引。
- 後續行動 / 待辦：
  - 如果要清掉舊封存裡的殘留，需要封存改寫 API，另立 ADR。

## 測試

- `packages/engine/src/storage/memory.test.ts`：只清已到期的，清原文與檔案 metadata，回傳動到的對話與下一個到期時刻，重複掃描不重寫。
- `packages/engine/src/storage/local.test.ts`、`apps/desktop/src/native/tauri-storage.test.ts`：清過的版本落地，重開讀到的也沒有原文。
- `packages/engine/src/storage/archive.test.ts`：限時訊息進封存時沒有原文與檔名。
- `packages/engine/src/storage/export.test.ts`：TXT／JSON 都不帶到期訊息的原文與檔名。
- `packages/engine/src/storage/cloud-snapshot.test.ts`：快照不帶限時訊息；還原時已到期的不補回。
- `packages/engine/src/backend/relay-backend.test.ts`：收發兩端到期時引擎自己清掉；開機時清掉關機期間到期的。

除了 `tauri-storage.test.ts`（跟實作一起寫）之外，其餘都在實作前先確認是紅燈。
