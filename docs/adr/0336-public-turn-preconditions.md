# ADR-0336：公共 TURN 開通前必須先關的兩個口

- 狀態：已採用
- 日期：2026-08-05
- 關聯：ADR-0243（WebRTC TURN 保底）、ADR-0048（企業政策 `forceTurn`）、`docs/SECURITY.md` 已知限制 #5、`docs/OPERATOR-TODO.md`

## 1. 先把成本數字放下——它不是決策點

ADR-0243 把公共 TURN 列為「成本決策」並擱置。現在有數字了（2026-08-05 查證 Cloudflare Realtime 定價）：

| 項目 | 數字 |
| --- | --- |
| 費率 | **$0.05 / GB**，且**只計 egress**（Cloudflare → 客戶端） |
| 免費額度 | **1,000 GB / 月**，SFU 與 TURN **共用一份** |
| 換發憑證 | 免費（只算流量） |
| 單一 allocation 上限 | 50–100 Mbps、5–10 kpps、每秒 5 個新 IP |

TURN 是**雙向都經過**：A→CF→B 與 B→CF→A 兩段都算 egress，所以是 2× 單向位元率。

| | 每小時 egress | 免費額度可撐 | 超額後每小時 |
| --- | --- | --- | --- |
| 語音（Opus＋RTP/TURN 開銷） | ~45 MB | ~22,000 小時 | ~$0.002 |
| 視訊（~1 Mbps/向） | ~0.9 GB | ~1,100 小時 | ~$0.045 |

而且**只有 fallback 到 TURN 的通話才計費**。以中繼率 20% 估，免費額度約等於 11 萬語音通話小時、或 5,500 視訊通話小時的**總**使用量。

⇒ **以正常使用而言，金錢成本實質為零。ADR-0243 擱置的理由已經不成立。**

但把它擱置這麼久，剛好讓我們沒有在毫無防護的情況下開通。真正該擋的是下面這個。

## 2. 🔴 `/turn` 是一扇沒有門的通用中繼

`relay/src/worker.ts` 的路由裡，`/turn` 在任何驗證之前：

```ts
if (url.pathname === "/turn") return mintTurnResponse(env);
```

**任何人 `GET /turn` 就拿到一組有效 24 小時的憑證**（`TURN_TTL_SECONDS` 預設 86400）。沒有驗證、沒有限流、不綁任何身分。

關鍵在於 **TURN 是通用中繼，不限於 WebRTC 媒體**。拿到憑證的人可以把它當免費 proxy 轉發任意 UDP/TCP 流量——這不是理論上的濫用，這正是 TURN 的功能定義。

算一下曝險：單一 allocation 灌滿 100 Mbps ＝ **45 GB/小時 ＝ $2.25/小時 ＝ $54/天**。多開幾個就乘上去。**Cloudflare Realtime 沒有硬性支出上限**，超額直接進帳單。

這件事的形狀跟本專案反覆遇到的那類問題一樣：**功能本身沒有錯，錯在它的入口比它的用途寬。**

## 3. 決策

開通公共 TURN，但**先做完三件事再放 secret**：

### 3.1 TTL 從 1 天砍到 5 分鐘

`turnTtlSeconds()` 預設值 86400 → **300**。

客戶端本來就在半 TTL 前刷新（`turn-fetch.ts` 檔頭寫明），所以縮短只是讓它多刷幾次，功能不變。而**憑證外流的價值直接跟 TTL 成正比**：24 小時的憑證可以貼上論壇給人用一整天，5 分鐘的不行。

⚠ 這也代表**通話中途可能跨越憑證到期**。ICE allocation 一旦建立就不受後續憑證影響（allocation 有自己的生命週期），所以進行中的通話不會斷；影響的只是「拿舊憑證發起**新**連線」。要驗這一條。

### 3.2 `/turn` 綁定 relay 連線

換發前要求請求方**證明它是這個 relay 的使用者**。最小可行做法：要求帶上一個由 relay 在 WebSocket 連線期間發出的短期 token（沿用 NIP-42 AUTH 已建立的身分，不新開一套）。

⚠ **這不是門檻高低的問題，是把匿名開放中繼變成有歸屬的中繼。** 就算 token 很好拿，濫用者也從「任何人」變成「至少要跑一次 relay 握手、且可被撤銷的某人」。

### 3.3 帳單警示

Cloudflare 通知設在**免費額度的 50%（500 GB）**。這是最後一道網——前兩道都是預防，這一道是「已經在燒錢了，讓我知道」。

⚠ 不要設在 100%：那時已經開始計費，且若是濫用，從 100% 到失控只需要幾小時。

## 4. 元資料那一面：揭露已經有了，缺的是開關

`docs/SECURITY.md` 已知限制 #5 已經寫明：

> TURN 一旦使用即見兩端 IP 與通話時序/流量（不見內容，E2E 密文）——多一個元資料可見方，自架可避。

**所以這裡不需要補揭露。** 但目前 TURN 的來源優先序（`relay-backend.ts:1784`）只有兩層：企業靜態 `turnServers` ＞ 公共 TURN 保底。`forceTurn` 是**企業政策**（ADR-0048），不是使用者偏好。

⇒ **一般使用者沒有辦法說「我寧可打不通，也不要讓通話經過 Cloudflare」。** 一旦站方開通，所有人預設就用。

新增裝置層偏好 `allowPublicTurn`（預設 **開**）：

- **預設開**——關掉的後果是對稱 NAT 下通話接不通，那對多數人是壞掉而不是更安全。預設值要服務多數人。
- **關掉時 `fetchTurnServers` 直接不抓**，退回純 STUN，行為與站方未配 secret 時完全一致（那條路徑已存在且測試過，Fix-First）。
- 裝置層而非身分層：這是「**這台**的網路要不要經過第三方」，與 ADR-0327 判定 `cloudSync` 為身分層的理由正好相反——那個決定的是資料要不要離開裝置，這個決定的是本機網路路徑。
- 設定頁文案必須說出取捨，不能只寫「使用公共 TURN 伺服器」。要寫：**關閉後，在限制較嚴的網路下通話可能接不通。**

## 5. 買不到什麼

1. **擋不住有心人。** §3.2 的 token 只要能自動化取得，就能自動化濫用。這裡買到的是**成本與可歸責性**，不是不可能。真正的上限仍然只有帳單警示（§3.3）和事後撤 secret。
2. **`allowPublicTurn` 關掉不等於匿名。** 純 STUN 下 P2P 直連**向對端揭露 IP**（SECURITY §5(a)）。這個開關換掉的是「誰看得到」——Cloudflare 或聯絡人——不是「沒人看得到」。設定頁文案不得暗示後者。
3. **沒有處理 relay 自身的 metadata。** `/turn` 換發本身就洩漏「這個 IP 想打電話」給 relay，即使最後沒用上。
4. **免費額度是全站共用的**，不是每人。單一重度使用者（或濫用者）吃掉的是所有人的額度。這裡沒有做每使用者配額。
5. **沒有做多 TURN 供應商。** 開通後 Cloudflare 成為通話可用性的單點——與 `relay-url` 記錄的「兩座錨點都在 `*.workers.dev`」是同一類集中風險，只是又多押一注。

## 6. 開通檢查清單

`docs/OPERATOR-TODO.md` 以此為準，**三項全綠才放 secret**：

- [ ] `TURN_TTL_SECONDS` 預設值改 300，並驗證通話跨越到期不斷線
- [ ] `/turn` 要求 relay 連線 token；未帶 → 401（不是 204——204 代表「未配置」，語意不同）
- [ ] Cloudflare 帳單通知設於 500 GB
- [ ] `allowPublicTurn` 偏好與設定頁文案（含「可能接不通」的取捨說明）
- [ ] 以上皆綠 → `wrangler secret put TURN_KEY_ID` / `TURN_API_TOKEN`
