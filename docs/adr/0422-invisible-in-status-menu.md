# 0422. 隱身併進狀態選單：「隱身」就是真隱身，設定頁不再有開關

- 狀態：已接受
- 日期：2026-11-13
- 相關文件：ADR-0088 (d)（隱身停止廣播）、ADR-0240（真隱身：也停止訂閱聯絡人心跳）、ADR-0164（本機記住手動狀態）、ADR-0180（離職接管建構即隱身）、ADR-0237（presence 訂閱洩漏聯絡人集合）

## 背景與問題

在這份 ADR 之前，「讓別人看不到我在線」有兩個入口，語意不同：

| 入口 | 停止廣播自己 | 停止訂閱聯絡人心跳 |
|---|---|---|
| 狀態選單「顯示為離線（隱身）」（`status = offline`） | ✅ | ❌ 中繼仍拿到聯絡人名單 |
| 設定 → 隱私「隱身」開關（`setInvisible`） | ✅ | ✅（ADR-0240 真隱身） |

使用者（2026-11-13）要求：「隱身不用出現在設定之中，應該直接出現在狀態更改之中就好」。兩個入口並存本來就容易混淆，而且狀態選單那個標著「隱身」，卻不是 ADR-0240 定義的真隱身——名不符實。

## 決策

**狀態選單只留一個「隱身」，選了就是真隱身；設定頁的隱身開關移除。**

- **引擎**：`RelayChatBackend` 以 `hidden = invisible || status === "offline"` 判斷是否隱身。廣播（`beat`／封裝狀態）與訂閱（心跳 filter、EK 公告 filter）都看 `hidden`。`setStatus` 進出 `offline` 時，與 `setInvisible` 走同一個 `applyHidden()`：重建訂閱；進入時清空 presence，聯絡人立刻變灰；離開時重新廣播。
- **`setInvisible` 保留**：只剩離職接管（ADR-0180 `initialInvisible`／行動端 `forceInvisible`）在用，不再有 UI 入口。
- **UI 文字**：新增 `status_invisible`（「隱身」／"Invisible"），只用在**自己的**狀態選單。`status_offline` 改回「離線」／"Offline"，用在**別人**的狀態，例如聯絡人分區標題、側欄說明——別人離線不代表他在隱身。`settings_invisibleHint` 刪除。
- **行動端**：`PICKABLE_STATUS` 從三個加到四個（線上／離開／忙碌／隱身）。設定頁的隱身區塊與 `invisible`／`onInvisible` 屬性移除。
- **桌面舊資料遷移**：舊版設定頁把開關存在裝置層的 `nb.invisible = "1"`。`loadPresence` 讀到這個旗標時回傳 `offline`，讓升級後的使用者仍以隱身上線。使用者手動選一次狀態，就清掉旗標（`clearLegacyInvisible`）。行動端的隱身原本就不持久化（每次登入重設），不需要遷移。

## 理由

- **一個概念**：使用者只需要在一個地方決定「別人看不看得到我」，也只有一個名字。
- **選「真隱身」而不是「顯示離線但偷看」**：沿用 ADR-0240 的理由。「顯示為離線」仍會訂閱聯絡人心跳，聯絡人集合照樣外流給中繼，對隱私是假的。隱身就該對中繼也藏起來。
- **在引擎合併、不在 UI 合併**：UI 只是改呼叫 `setStatus("offline")`。桌面、行動端、CLI 共用同一個引擎，語意一次就一致，也不會出現「狀態說線上、旗標說隱身」的雙重真相。

## 後果

- 正面：
  - 入口只剩一個，名副其實，聯絡人集合不再因為「顯示為離線」外流。
  - 設定頁少一個區塊。
- 負面 / 已知殘餘風險：
  - **行為改變**：以前選「顯示為離線」的人仍看得到聯絡人綠點，現在看不到了（與 ADR-0240 的取捨相同）。
  - 自訂狀態文字在隱身時不送出（本來就如此：`beat` 早退）。
- 後續行動 / 待辦：
  - 無。若日後真的需要「看得到別人但自己隱藏」，必須另立 ADR，並明寫它會把聯絡人集合交給中繼。
