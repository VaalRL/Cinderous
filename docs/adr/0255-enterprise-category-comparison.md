# 0255. 企業版「與常見選擇的差異」：類別比較段（否決完整企業對比頁）

- 狀態：已接受
- 日期：2026-07-28
- 相關文件：ADR-0254（消費者比較頁）、ADR-0246（企業版頁）、ADR-0046/0052（零知識/無金鑰託管——本段誠實限制的依據）、ADR-0166（商標）

## 背景與問題

消費者比較頁（ADR-0254）上線後，使用者問企業版是否也該有對他牌的比較。企業通訊的真實競品分三類：雲端協作套件（Slack/Teams/LINE WORKS）、自架開源通訊（Mattermost/Rocket.Chat）、E2E 自架（Element/Matrix）。

## 考量的選項

- **A：完整企業對比頁**（逐產品欄）——SEO 好，但三重風險：**類別錯位**（拿安全通訊逐功能比協作套件＝一整欄 ✗；「合規稽核匯出」我們是**設計上做不到**——零知識連企業主都看不到明文）、**成熟度時機**（無 SSO/SCIM，對 Element 的誠實表現在輸多贏少）、**維護成本**（企業產品迭代快）。
- **B：輕量類別差異段（採納）**——企業版頁內一小段，按**類別**比（非逐產品）、只打隱私主權軸。
- **C：先不做**——只互連兩頁。

## 決策

採 **B**：

1. **企業版頁新增「與常見選擇的差異」段**：五列（預設 E2E／管理者能否讀訊息／組織內元資料／資料所在／離職金鑰託管）× 三類別欄（雲端套件/自架開源/E2E 自架，欄標附代表產品名）。開頭直說「只比隱私主權——功能廣度它們更成熟，那不是我們的主場，也不假裝是」。
2. **誠實限制段**（測試鎖住）：明示「零知識下任何人——包括企業主與我們——都無法匯出成員訊息明文；需要完整訊息稽核留存的受監管行業可能不適合」＋「SSO/SCIM 未提供」。誠實過濾掉不適合的客戶，比銷售話術省雙方時間。
3. **互連**：企業頁 ↔ 比較頁雙向 locale-aware 連結。
4. **完整企業對比頁**：等 SSO/外部審計落地後再議（本 ADR 即為該未來決策的背景記錄）。

## 理由

類別比避開逐產品的事實維護、商標密度與 Element 近身混戰；把戰場限定在我們真實領先的隱私主權軸,同時用限制段守住誠信（合規匯出做不到是**架構承諾的必然**,遮掩只會在銷售後期爆炸）。文案照 SSOT 進 `copy.ts`（`ec_*`/`ent_cmp_*` 雙語）。

## 後果

- **正面**：企業訪客一眼看懂定位與適不適合；不利事實主動揭露=信任資產；維護面小（類別特性比產品功能穩定）。
- **負面 / 已知殘餘風險**：無逐產品 SEO 著陸點（Element vs Cinderous 這類查詢吃不到）；類別概括對個別產品未必全準（欄標已附「等」字與代表例）。
- **後續行動 / 待辦**：SSO/SCIM 與外部審計落地後重評完整企業對比頁；與 ADR-0254 一同年度複查（2027-07）。
