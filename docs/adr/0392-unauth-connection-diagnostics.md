# 0392. 診斷「沒認證就斷線」的主平面連線（預設關閉）

- 狀態：已接受
- 日期：2026-10-20
- 相關文件：ADR-0391（主平面反覆重連限速）、ADR-0382（公開聯絡方式：kind 10050／10002）、ADR-0057／0123（NIP-42 與具名訂閱）；ARCHITECTURE「中繼只轉發、不持久化線上狀態」

## 背景與問題

ADR-0391 部署後，錨點 2 的 `shard-b` 用量**完全沒變**。`wrangler tail` 查出那個來源在**輪替 IP**：60 秒 15 次升級、6 個 IP，分屬 ASN 39351 與 215125，城市一直換。所以以 IP 計數擋不到。

時間點也對上了：
- `shard-b` 的連線從 **2026-10-14 06 時（UTC）**突然開始，之前一筆都沒有；
- 同一時間，一把測試身分（公鑰開頭 `b399`，住在錨點 2 的 `shard-b`）在公開索引中繼上發佈過 10050／10002（ADR-0382 公開聯絡方式）。現在公開的版本是空清單。

推測：清單公開的那段時間被 Nostr 爬蟲記住，之後它就照舊清單一直連 `/s/b`，送 2 則、被要求認證、斷線、再來。

要選中繼端的做法，得先知道它到底送什麼、要什麼：
- 它要的東西如果能便宜地給，也許就不會再來；
- 它的請求如果有特徵，也許就能在 Worker 認出來。

使用者 2026-10-20 選擇先診斷。

## 考量的選項

- 選項 A：環境變數控制的診斷，只記摘要，預設關閉，要查時才打開。
- 選項 B：暫時把診斷寫死在程式裡，查完再拿掉。每次查都要改程式、合併，下次再查又要重來。
- 選項 C：把原始訊息記下來。最完整，但會碰到使用者內容，違反隱私原則。

## 決策

採選項 A：
- **開關**：`DIAG_UNAUTH_LOG=1` 才開，預設關。部署時用 `wrangler deploy --var DIAG_UNAUTH_LOG:1` 打開，看完重新部署（不帶這個變數）就關掉。
- **範圍**：只記主平面、**從頭到尾沒有完成 NIP-42 認證就斷線**的連線。一旦認證成功，那條連線之前收集的摘要也一併清掉，所以正常使用者不會被記到。
- **每條連線印一行**到 console：
  - 進站訊息的動詞序列（最多 16 個，例如 `REQ,CLOSE`）；
  - REQ／COUNT 的 `kinds`（只有數字）；
  - 中繼回覆的動詞，以及機器可讀的原因前綴（例如 `CLOSED:auth-required`）；
  - 存活秒數與關閉碼。
- **不記**內容、公鑰、filter 的其他欄位（authors、#p…）、IP。不寫儲存，只有 `wrangler tail` 當下看得到。Worker 沒有開 observability，所以不會被保存。
- **記憶體上限**：最多同時記 1,024 條連線。DO 被回收時清空。

## 理由

- 只記摘要，就足以區分常見的情況：
  - 只是在 `REQ` 讀東西的爬蟲；
  - 想寄信、送 `EVENT` 的用戶端；
  - 根本不送東西的探測器。
- 預設關、靠部署參數打開：診斷碼可以留在程式裡，下次遇到類似問題不必再改程式。

## 後果

- 正面：知道爬蟲要什麼，就能在 ADR-0391 之外選一個真的有效的做法。
- 負面：多了一條「打開就會印出連線摘要」的路徑。摘要不含使用者資料，但部署參數打開時，看得到 tail 的人能看到連線的時間與行為。所以只能短時間開、看完就關。
- 後續：在錨點 2 打開約一小時，看完立刻重新部署關掉，把結果寫進 ADR-0391 的後續討論。
