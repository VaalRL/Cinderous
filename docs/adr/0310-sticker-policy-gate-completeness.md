# 0310. 補完 `disableStickers` 的 UX 閘門：文字觸發字與「點收到的貼圖＝收藏」

- 狀態：已接受
- 日期：2026-08-03
- 相關文件：ADR-0048（企業政策開關——`disableStickers` 的來源與其「僅 UX 層」定位）、
  ADR-0037（文字觸發貼圖）、ADR-0220/0221（自訂資產庫與自動收藏）、
  ADR-0308 §後果〈待辦〉（本問題於該次統一輸入層時被發現並記錄）、
  `apps/desktop/src/ui/composer-suggest.ts`、`apps/desktop/src/ui/ConversationWindow.tsx`

## 背景與問題

ADR-0048 把 `disableStickers` 明確定位為**僅 UX 層**：「貼圖是 kind 14 聊天訊息（內容標記），
無法以 kind 阻擋 → 由客戶端政策處理」，且已知限制寫著「決心的使用者可繞過客戶端」。

本 ADR **不推翻**那個定位。要修的是另一回事：**UX 層自己漏了**。
政策的意思是「把送貼圖的 UI 藏起來」，但桌面端盤點後有兩條路沒藏：

| 送出／取用貼圖的路徑 | 政策生效？ |
| --- | --- |
| 🧸 貼圖面板（含編輯器、匯入、最近／最愛） | ✅ 已設閘 |
| `/sticker` 斜線指令（ADR-0309） | ✅ 已設閘 |
| `:短碼` 自訂 emoji 自動補全（ADR-0220） | ✅ 已設閘 |
| 送出時附行內資產清單 `attachManifest` | ✅ 已設閘 |
| 收到貼圖時自動收藏（ADR-0220） | ✅ 已設閘 |
| **文字觸發字建議列（ADR-0037）** | ❌ **未設閘** |
| **點收到的自訂貼圖＝收藏進自己的庫** | ❌ **未設閘** |

第一條是真正的破口：觸發字建議列照跳，按 `Tab` **就送出一則貼圖訊息**——政策說要藏的按鈕藏了，
但同一個動作還有一條鍵盤捷徑開著。這不是「決心的使用者繞過」，是**應用程式自己提供的入口**。

第二條是自我矛盾：**自動**收藏已依政策關閉，**手動**點一下收藏卻沒有；而在政策開啟時，
收進來的庫本來就送不出去。

## 考量的選項

- **選項 A：不動，維持 ADR-0048「僅 UX 層、可繞過」的說法。** 混淆了兩件事——
  「使用者自己改客戶端繞過」與「客戶端自己開著另一扇門」。後者是缺陷，不是取捨。否決。
- **選項 B：把貼圖升為協定層硬強制。** ADR-0048 已論證做不到（貼圖是普通聊天訊息，
  無法以 kind allowlist 阻擋），且會需要中繼看內容——與端到端加密的前提衝突。否決。
- **選項 C（採用）：補完 UX 閘門**，讓所有客戶端提供的貼圖入口一致地受政策約束。

## 決策

1. **觸發字建議列納入 `stickersDisabled` 閘門**：在聚合器 `composer-suggest.ts` 中，
   貼圖觸發字與 `:短碼` 補全**同一個判斷**——政策開啟時兩者都不建議。
   觸發字**資料本身不動**（`nb.stickers.triggers` 照常保存、管理面板照常可編輯），
   只是不再建議、不再有 `Tab` 送出路徑；政策解除即完全恢復。
2. **「點收到的貼圖＝收藏」納入同一閘門**：政策開啟時 `onOwnSticker` 傳 `undefined`，
   收到的貼圖**照常顯示**、只是不再是可點擊的收藏按鈕。與既有的自動收藏閘門一致。
3. **不改變的事**：
   - **收到的貼圖照常渲染**。政策是「不要送」，不是「看不到別人送的」；
     擋渲染會讓對話變成看不懂的空白，且對已收到的訊息毫無意義。
   - ADR-0048 的定位不變：這仍是 UX 層，仍不宣稱是硬牆。本 ADR 只是讓 UX 層說到做到。

## 理由

- **政策的可信度來自一致**。一個「藏了按鈕但留著捷徑」的閘門，比沒有閘門更糟——
  管理者以為關掉了。
- **不動資料是刻意的**：政策由名冊分發、可能來來去去（換公司、離職、政策調整）。
  把觸發字表刪掉是不可逆的資料損失，用來換一個 UX 層的效果不成比例。
- **手動與自動收藏必須同進退**，否則同一個功能有兩套政策語意。

## 後果

- 正面：桌面端所有貼圖入口對 `disableStickers` 一致；關閉 ADR-0308 記下的待辦。
- 負面 / 已知殘餘風險：
  - 仍是 UX 層，**仍非硬牆**（ADR-0048 的原始限制不變，且無法變）。
  - 企業使用者在政策開啟時打到自己設過的觸發字會「沒反應」，而非收到說明。
    刻意不加提示——為了一個政策關閉的功能而跳訊息，是把噪音加在正常打字流程上。
- **後續行動（未在本次處理，屬獨立缺口）**：
  **行動端完全沒有實作 ADR-0048 的客戶端政策消費端**——`apps/mobile` 全庫沒有
  `disableStickers`／`disableFiles`／`disableCalls`／`forceTurn` 的任何使用（只有
  `RosterAdminScreen` 能**發佈**政策）。也就是說企業政策在手機上一條都不生效，
  包含本 ADR 修的這兩條。這比單一繞道嚴重，應另開 ADR 專案處理。
