# 0271. 群組發言者名字色：pubkey 雜湊的穩定色（否決「每次隨機」）

- 狀態：已接受
- 日期：2026-07-28
- 相關文件：ADR-0064（主題色）、ADR-0080（@cinderous/theme SSOT）、ADR-0253（無障礙／WCAG 與高對比）、ADR-0027（群組扇出）

## 背景與問題

盤點發現：對話中名字顏色只分兩態——自己＝`--accent`、對方＝`--in-name`（**單一固定色**）。
其中 `--in-name` 與「是誰」無關，因此**群組裡所有發言者的名字都是同一個顏色**，認人只能靠頭像
（`avatarColor(pubkey)` 是目前唯一 per-人 的顏色，但只用於頭像方塊）。使用者提議「他人名稱隨機顏色」。

## 考量的選項

- **A：每次渲染真隨機**——字面上的「隨機」。**否決**：顏色的價值在「這個顏色＝這個人」，
  每次變色等於雜訊，且破壞 SSR／測試決定性（重繪就跳色）。
- **B：直接把 `avatarColor` 的 HSL 當文字色**——**否決**：頭像底色是 `hsl(h 70% 55%)` 系，
  當文字用時黃/青綠系在白底僅約 2:1，遠低於 WCAG AA（4.5），會直接違反剛立的 ADR-0253。
- **C：同一把雜湊取 hue、亮度依主題選安全值（採納）**——看起來像隨機、實際每人固定，且全色環達標。

## 決策

1. **`@cinderous/theme` 新增 `nameColor(seed, theme, contrast)`**（SSOT，純函式）：
   - hue＝`hueOf(seed)`，與桌面 `avatarColor` **同一把雜湊** → 名字色與頭像色是同一個人的一致訊號；
   - 飽和度/亮度依主題×對比模式選安全值：`light 70%/27%`、`dark 65%/72%`、
     `lightHC 75%/20%`、`darkHC 70%/80%`；
   - **全 360 hue × 四組合以測試迴圈驗證**：一般模式 ≥ AA 4.5、高對比模式 ≥ AAA 7
     （最差 hue：亮色＝60 黃 4.87、深色＝240 藍 5.04）。
2. **只在群組套用**：`ConversationWindow` 的 `whoColorOf(m)` 僅當 `groupMembers` 存在且為
   他人訊息時給色；**1:1 維持 `--in-name`**（只有一個對方，不需分色，不動既有觀感），
   自己維持 `--accent`（自己永遠一致好認）。
3. **新增唯讀 hook**：`useThemeMode()`／`useContrastMode()`——缺 Provider 時回預設值
   （`light`／`normal`）而非拋錯。只是「想知道目前模式以挑顏色」的消費端，不該因為缺一個
   外觀 Provider 就整個炸掉；切換入口仍走會拋錯的 `useTheme`／`useContrast`。

## 理由

穩定色才有認人價值，這是所有主流 IM（LINE/Slack/Discord）的一致做法。把亮度決策放進 theme
套件並以全色環測試鎖死，讓「隨機感」不會偷偷產出看不清的顏色——這是 ADR-0253 立下的門檻在
新功能上的延續。群組限定讓改動範圍最小、既有 1:1 觀感零變化。

## 後果

- **正面**：群組一眼分辨發言者；顏色與頭像同源；四種主題組合皆保證可讀（測試鎖住）。
- **負面 / 已知殘餘風險**：色環雜湊仍可能讓兩位成員拿到相近 hue（大群較明顯）——頭像與名字
  文字仍可區分，未做 per-群 去重（會犧牲「同一人在不同群同色」的一致性）；行動端尚未套用
  （`nameColor` 已在共用套件，接上即可）。

## 後續行動 / 待辦

- 行動端群組訊息套用 `nameColor`。
- 若大群撞色回報變多，再評估「同群內 hue 間距最佳化」的取捨。
