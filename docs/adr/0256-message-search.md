# 0256. 歷史訊息搜尋：對話內巡覽、經典佈局、封存掃描、行動端（四階段）

- 狀態：已接受
- 日期：2026-07-28
- 相關文件：ADR-0079 Q2（三欄側欄搜尋）、ADR-0111（冷熱分離封存）、ADR-0054（加密儲存）、ADR-0220（行內資產 manifest）、ADR-0094（明文導出）

## 背景與問題

盤點發現搜尋能力殘缺：三欄側欄可依「名稱＋訊息內容」過濾**對話清單**（ADR-0079 Q2），但無法定位訊息；經典佈局完全無搜尋；**對話內搜尋不存在**；封存（每對話熱區 5,000 則之外）是搜尋盲區；行動端全無。訊息只存本地（零伺服器狀態）→ 搜尋必然純本地。

## 考量的選項

- 封存搜尋的索引策略：(a) 建持久明文索引（快，但**在加密儲存旁放一份可搜明文**，掏空 ADR-0054 的意義，否決）；(b) **逐塊解密掃描、即掃即棄**（採納——重用 HistoryWindow 既有分頁基建，非同步、不落地任何明文）；(c) 加密索引（工程大，未來若掃描太慢再議）。
- 對話內跳轉與視窗化：訊息列只渲染最近 visibleCount 則——跳轉需先擴窗再捲動（採納：命中在窗外→`setVisibleCount` 對齊→effect 重跑後捲動＋高亮），不為搜尋放棄視窗化。

## 決策（四階段依序交付）

1. **對話內搜尋＋跳轉**（本 commit）：標頭 🔍 開關＋搜尋列（Enter＝較舊、Shift+Enter＝較新、Esc 關、↑↓ 鈕、x/y 計數）。純函式 `msg-search.ts`：比對**可見文字**（剝 ADR-0220 資產 manifest）、檔案比檔名、已收回/過期不參與；環繞巡覽 `stepHit`。範圍＝熱區；跳轉配合視窗化擴窗；`.log` 子元素索引對映（不動 MessageLine 多分支根節點）。
2. **經典佈局搜尋**（本 commit）：自 `matchesQuery` 抽出 `nameOrMessagesMatch`（三欄/經典共用 SSOT），roster 頂端搜尋框過濾聯絡人（暱稱優先，ADR-0148）與群組；請求/封鎖區不在範圍。
3. **封存搜尋**：HistoryWindow 加搜尋——由新到舊逐塊解密掃描、即掃即棄（無持久索引）、顯示掃描進度與命中列表；詳見實作 commit。
4. **行動端**：聊天清單搜尋（名稱＋內容），比對邏輯上移共用（比照 thread-util 前例）。

## 理由

搜尋以頻率排序交付（對話內＞清單＞封存＞行動端）；一切純本地、零新增網路面。「即掃即棄」讓封存搜尋不產生新的靜態攻擊面——慢是誠實的代價（加密分塊本就以讀取成本換保密性），UI 以進度回饋補償。可見文字比對避免 manifest/SVG 內部字串誤命中。

## 後果

- **正面**：四個面的搜尋缺口有序補齊；純函式核心全可測；無明文索引落地。
- **負面 / 已知殘餘風險**：封存掃描為 O(全部塊)，長歷史下需時間（進度條＋可中止緩解）；熱區/封存是兩個入口（冷熱分離的必然，UI 以提示銜接）；側欄搜尋比對原始 text（含 manifest 字面）維持既有行為未改。
- **後續行動 / 待辦**：階段 3、4 實作；若封存掃描實測過慢再評估加密索引。
