# 0365. 後量子 EK：混合式封裝接線，並於同日開播（Phase 4＋4b）

- 狀態：已接受
- 日期：2026-09-21
- 相關文件：ADR-0236 / 0238 / 0245（EK 前向保密）、ADR-0302（能力宣告與釘選強度）、ADR-0306（外部審計與文案紅線）、ADR-0316 / 0325（解封失敗與保留）、ADR-0318 / 0326（EK 轉址與 hint）、ADR-0322（裝置目錄與 EK 分發）、`docs/research/post-quantum-ek-plan.md`、`docs/research/signal-triple-ratchet-applicability.md`

## 背景與問題

ADR-0236～0245 建立的前向保密是「每週換一把隨機子鑰（EK）、舊的刪掉」。它防的是**金鑰失竊**：私鑰刪了，之後偷到裝置的人解不開舊密文。

但它對**量子對手完全不生效**，而且不是「效果打折」，是**零**：

- NIP-44 的對話金鑰是 `ECDH(寄件者私鑰, 收件者公鑰)`。
- 收件者的 EK 公鑰**是明文公告的**（kind 10040）。
- ⇒ 攻擊者只需要「側錄的密文 ＋ 那顆公開的公告」就能在未來解開。他不需要任何人刪掉或沒刪掉的那一份。

換句話說：我們二十多份 FS 的 ADR，在 harvest-now-decrypt-later 這個威脅模型下買到的是零。今天被側錄的密文，等到有足夠規模的量子電腦時全部可讀。

這與研究階段的另一條線（Signal 的 Triple Ratchet / SPQR）指向同一個結論，但**棘輪不是我們可走的路**：棘輪的金鑰時程是**訊息歷史**的函數，而我們的是**時間**的函數；要棘輪就得放棄多裝置（詳見 `docs/research/double-ratchet-on-current-design.md`）。後量子 KEM 則與現行 EK 制**不互斥**——它換的是「怎麼從 EK 算出對話金鑰」，不動輪替節奏、不動多裝置。

## 考量的選項

**A. 不做。** 等 NIP 上游出標準再跟。
**B. 換成棘輪（含 SPQR）。** 拿掉多裝置換 PCS ＋ 後量子。
**C. 在既有 EK 上加一層混合式 KEM。** 每把 EK 額外帶一把 ML-KEM-768 金鑰，對話金鑰由「古典 ECDH 共享祕密 ‖ ML-KEM 共享祕密」一起導出。

幾個子選項（都在 C 之內）：

- **KEM 密文（`ct`）放哪**：外層 wrap 的明文 tag／seal 內／rumor 內。
- **一則訊息封裝幾次**：seal 與 wrap 各一次（兩份 ct）／共用一份（靠域分離）。
- **儲存展開後的私鑰（2400 B）還是種子（64 B）**。
- **公告 `pq` 的時機**：這一版就開／做成開關、預設關。

## 決策

採 **C**，並且：

1. **混合式 KDF**（`packages/core/src/hybrid-kem.ts`）：
   `K = HKDF-SHA256(ikm = ss_classic ‖ ss_pq, salt = SHA256("cinder-ek-pq-v1"), info = layer ‖ ct)`，
   輸出 32 bytes 直接當 NIP-44 的對話金鑰。**任一半缺席即拋**，不得靜默退回單邊。
2. **`ct` 放外層 wrap 的 `["pqct", base64]` tag**，一則訊息**只封裝一次**，seal 與 wrap 靠 `info` 裡的 `layer` 標籤做域分離。
3. **只存 64-byte 種子**（FIPS 203 的 `d‖z`），用時才決定性展開，並在記憶體快取。
4. **公告 `pq`（kind 10040 的 `v:2`）由 `EK_PQ_ANNOUNCE` 單一開關控制。** 先以 `false` 出貨（讀端全開、種子照生），同日量過安裝基數後**翻為 `true`**（見〈4b 的依據〉）。
5. **能力宣告分兩級**：`ek-v1`（rank 1）／`ek-pq-v1`（rank 2），與實際發出去的公告**同源**（`announcedPq()`）——宣告比實際做的多就是 ADR-0302 §4 的那種謊。
6. **線路格式不變**：payload 仍是標準 NIP-44 v2，我們只改「怎麼算出那把金鑰」。

## 理由

**為什麼不是 A。** harvest-now-decrypt-later 的性質是「今天不做，今天送的訊息就永遠救不回來」——它是唯一一種**補做沒有用**的安全問題。而 C 的成本已經量過（見下），不足以支撐「再等等」。

**為什麼不是 B。** 棘輪與多裝置在邏輯上對立：FS 要求刪金鑰、多裝置要求留金鑰；而棘輪的 DH 步會把 session 分叉。B 會拿掉一個使用者天天在用的功能，換一個沒有人要求的性質。

**`ct` 只能放外層明文 tag。** 收件端要先算出 wrap 那層的金鑰才解得開內容，而算那把金鑰**就需要 `ct`** ⇒ 先有雞先有蛋。代價是中繼看得到「這則用了後量子」——但多出來的 1452 bytes 本來就從體積上看得出來，藏不藏沒有差別。

**封裝一次而非兩次。** 兩份 `ct` 多花 1452 bytes，而兩份都是對**同一把公鑰**封的，換不到任何安全性。域分離用 `layer` 進 `info` 即可（`hybrid-kem.test.ts` 有針對性測試釘住兩層導出的金鑰不同）。

**存種子而非私鑰，是實測驅動的。** ADR-0322 S2 的 per-device 分發事件會對**每台裝置各加密一份**，還要補空槽到 8 的倍數（藏裝置數）⇒ 金鑰體積會被乘一個大係數。5 台裝置、1 把 EK 的實測（`JSON.stringify(event).length`，中繼上限 256 KiB）：

| 分發事件內容 | 位元組 | 佔上限 |
| --- | ---: | ---: |
| 無後量子（現況基準） | 3,171 | 1.2% |
| **存 64-byte 種子（本決策）** | **4,515** | **1.7%** |
| 存展開後的 2400-byte 私鑰 | 39,331 | 15.0% |

（設計期另量過一個「公私鑰都放進去、2 把金鑰」的變體，來到 **110,339 bytes ＝ 上限的 42%**——那個數字是把設計推向種子的原因。）

代價是每次用之前跑一次 keygen，實測 **0.34 ms**，在記憶體快取即可。

**開關必須預設關，這是順序問題不是程式問題。** 一旦我公告 `pq`，已升級的對方就會用混合式加密給我，而我**另一台還沒更新的裝置解不開** ⇒ 那台裝置上的訊息**永久消失**（不是延遲，是沒有金鑰）。公告是可取代事件，全網只有一份，中間沒有協商的餘地。⇒ **先讓讀端普及，再開播**，形狀與 ADR-0358 的金鑰輪替並存期相同。

**種子現在就生。** 種子要先經 ADR-0322 S2 分發到每一台裝置；等到要用才生，開關翻開的第一週會沒得用。而沒公告 ⇒ 沒有人會拿它加密給我 ⇒ 現在生是零風險。

### 4b 的依據（2026-09-21 實測）

原本預期要等數週的「讀端普及」。實際量下來，**沒有東西要等**：

| 指標 | 數字 |
| --- | --- |
| GitHub Releases 史上總下載（17 版） | **12 次** |
| 帶 v2 讀端的 v0.0.16／v0.0.17 | **各 0 次** |
| `cinder-relay.cinderous1` 近 30 天 requests | 2,235（尖峰日＝發版日／動工日） |
| `cinder-relay.jt0856` 近 30 天 requests | 74（僅 6 天有流量） |

⇒ 第三方安裝基數實質為零，對外沒有可等的普及曲線。

🔴 **但這兩個指標都量不到真正有風險的那群人，必須寫下來：**

- **下載量看不到自己的裝置**——v0.0.15 起 APK／MSI／NSIS 皆本機建置，不經 GitHub。
- **中繼也數不出人頭**——ADR-0123 強制具名訂閱（`#p` 或 `authors`），無法枚舉全站 pubkey；
  requests 含 healthz、WebSocket 重連與我們自己的測試。

而 4b 的失敗模式**正好落在那個盲點上**：受害者不是陌生人（他們只會退回純古典），
是**我自己那台還沒更新的裝置**——它拿得到 EK 私鑰、卻沒有 pq 種子也沒有混合式程式碼。

⇒ **這個開關的真正閘門不是程式，是發版前的人工確認**：「我手上每一台裝置都跑到了這一版嗎」
（設定→裝置，對照 ADR-0322 的目錄）。只有一台漏掉，那台就開始永久丟訊。

### 🔴 翻開開關當場抓到的三件事

全部由測試抓到，而且**全部都是「兩階強度」才會出現的病**——單階世界裡它們是無害的。

**(a) `readFsCapability` 把「我們支援的機制」寫死成 `ek-v1`。**
加入 `ek-pq-v1` 的那一刻，**同一個版本的兩台客戶端會互相判成「宣告了我不認得的機制，請更新」**
——雙方都是最新版，卻都叫對方更新。⇒ 改由 `FS_SCHEME_RANK` 決定；強度表與「認不認得」
必須是同一份事實。

**(b) 不帶版本的 `ek` hint 會製造降級假警報。**
`learnContactEk` 原本一律以 `FS_CAPABILITY` 去 `pinAfterDeclare`。對一個已釘在 `ek-pq-v1`
的對方，那會判成 `"weaker"` ⇒ 寫下 `declared` ⇒ `pinIsDowngraded` 為真 ⇒ 送訊時跳
「對方退回較弱的機制」——**而對方什麼都沒做，他只是傳了一則訊息給我**。
⇒ 新增 `pinOnEvidence()`：只有證據沒有版本時，**已釘過就完全不動**。
真正的降級只能由帶版本的來源（10040 的 `v`、簽章個人檔的 `fs`）判定。

**(c) 「v1 公告」與「沒有版本資訊」被混為一談。**
Phase 4 的配對規則是「沒帶 `pq` 且 `ek` 沒變 ⇒ 保留舊 pq」，那對 hint 是對的。
但對一顆 **v1 公告**是錯的——v1 是一句明確的「我沒有 pq」，不是資訊缺失。
留著會繼續對他發混合式，而他若真的退版就解不開 ⇒ 永久丟訊。
⇒ 保留只在「來源說不出版本」時成立。

## 後果

### 正面

- 側錄的密文取得後量子機密性（今天送的訊息，未來解不開）。
- 與現行 EK 輪替、多裝置、群組、檔案完全不互斥——輪替節奏、grace、分發機制一行沒動。
- 兩端只要有一端沒升級就自動走純古典，漸進升級期間不斷訊。
- **降級偵測跟著升級了**：對方從 v2 退回 v1 會被判成 rollback 並停用混合式；而不帶版本的訊息 hint **不會**誤觸發（見〈抓到的三件事〉(b)(c)）。
- 17 個 `sealAndWrap` 呼叫端一行都沒改：收件目標改成「可以是字串、也可以是 `{pk, pq}`」的寬鬆型別，**沒有開出第二條平行路徑**。

### 負面 / 已知殘餘風險

- 🔴 **這不是「量子安全」。** 換掉的只有加密。事件簽章（seal 的 `pubkey`/`sig`、wrap 的一次性金鑰）仍是 secp256k1 ⇒ 真的有量子電腦的攻擊者**照樣偽造得出訊息**。買到的只有機密性一件事。文案紅線同 ADR-0306 D2.2，並由 `packages/i18n/src/i18n.test.ts` 的「後量子文案紅線」擋住（本版還沒有任何後量子文案，該組測試是為了在**有人寫下第一句時**咬住）。
- **體積**：每則混合式訊息多約 1,464 bytes（1452 是 base64 的 1088-byte KEM 密文，其餘是 tag 名與 JSON 標點）。實測一則短中文訊息的外層 wrap：**2,241 → 3,705 bytes**。檔案位元組走 P2P、不受影響。
- **新的 metadata 洩漏**：中繼看得到哪些訊息用了後量子（`pqct` tag 是明文）。無法避免（見理由）。
- **組合器未經外部審計。** X-Wing 綁的是 X25519、我們是 secp256k1，且 NIP-44 要的是 HKDF 輸出 ⇒ 我們**沒有照搬任何一個已發表的組合器**，是依標準做法組出來的。ADR-0306 的審計期限（2027-01-30）涵蓋這一份。
- **相依是 pre-1.0**：`@noble/post-quantum` 若改了種子導出方式，既有種子會導出**不同的金鑰** ⇒ 所有訊息解不開。以一組釘死的測試向量（`sha256(pk)`）鎖住，升級相依時會被告知而不是靜默壞掉。
- **中繼拔掉 `pqct` ⇒ 斷訊**（不是降級）。`pqct` 進事件 id、被簽章覆蓋，拔掉就簽章不對；就算重簽也會換掉 `wrapEvent.pubkey` 而讓內容解不開。結論是 DoS，不是降級——但 DoS 仍是 DoS。
- **偏序未決。** `ek-pq-v1` 與 `ratchet-v1` 在偏序上是**不可比的**（前者後量子無 PCS、後者 PCS 非後量子），而 `FS_SCHEME_RANK` 是個全序。目前只有 `ek-v1 < ek-pq-v1` 這條真的成立的邊，`compareFsStrength` 對表外的機制一律回 `incomparable`（安全側），所以今天不會出錯——但第三個機制一進來就必須先解這題。

### 後續行動 / 待辦

- 🔴 **發版前必須人工確認：自己的每一台裝置都會更新到這一版。** 程式擋不住，只有一台漏掉就開始永久丟訊。
- **外部密碼學審計仍未完成**（ADR-0306，期限 2027-01-30）。FS 整體本來就以「實驗性、預設關閉、未經審計」出貨，後量子繼承同一姿態——但這是**唯一**還開著的實質風險。
- `nextPq`（下一週的封裝金鑰）——⚠ **查證後降級為非阻礙**：`next` 這個欄位**從來沒有被實作**（唯一的生產呼叫不傳它，全庫沒有任何地方讀 `read.next`），所以週界空窗**古典那邊也一樣存在**，不是後量子帶來的退步。輪替邊界的正確性由 grace 保證（對方用舊 `ek`＋舊 `pq`，我兩半都留著）。
- FS 強度偏序（`ek-pq-v1` / `ratchet-v1` 不可比）的設計。
- 量測 DO 儲存在開播後的實際增量。
- 使用者面尚無任何後量子文案（刻意）。要加的時候受 `i18n.test.ts` 的後量子紅線約束。
