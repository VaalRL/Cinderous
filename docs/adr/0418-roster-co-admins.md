# 0418. 組織名冊的共同管理者：任一位可簽，只有擁有者能改管理者名單

- 狀態：**已接受（Accepted，2026-11-12）**——使用者 2026-11-12 選「任一位可簽，只有擁有者改名單」、託管「只交給擁有者」
- 日期：2026-11-12
- 相關文件：**0047**（管理者簽章名冊＝成員權威；本文處理它「單一管理者金鑰」的已知限制）、0052（身分輪替）、0156（入職邀請碼）、0157（公司設定）、0163（金鑰託管）、0257 §7.1（單點信任根列為商業化風險）、0414（自架站自動套用名冊）；SDK ADR **0135**

## 背景與問題

組織名冊（kind 10038）只認一把金鑰：建立組織的那個身分（擁有者）。這把金鑰弄丟、或那個人離職休假，名冊就簽不動——不能加新人、不能移除離職者、不能改政策。ADR-0047 把它列為已知限制，ADR-0257 §7.1 建議承接企業客戶前先處理。

## 考量的選項

1. **任一位可簽，只有擁有者改管理者名單**（採用）。
2. 誰都能改名單：一把共同管理者金鑰被盜，就能踢掉其他管理者、接管組織。
3. M-of-N 門檻簽章：要新協定、多人同時在線協調，工程大，日常加一個人也要湊齊簽名。
4. 只做擁有者換鑰：遺失時仍是單點。

## 決定

協定與驗證在 SDK（ADR 0135）；本 ADR 記 Cinderous 客戶端怎麼用。

1. **名冊多一個 `admins`（共同管理者 pubkey）**，只有擁有者簽的名冊裡的這份名單算數；必須也是在世成員、不能是擁有者，最多 16 位。
2. **誰能簽**：擁有者，或擁有者**最新一份**名冊列的共同管理者。共同管理者簽的名冊：
   - 裡面的 `admins` 一律忽略，名單照擁有者的。
   - 必須讓每一位共同管理者都還是在世成員，否則整份無效——共同管理者不能把彼此踢出組織。
3. **引擎（`RelayChatBackend`）**：
   - 訂閱名冊事件的 `authors`＝擁有者＋目前的共同管理者（成員端與擁有者端都是）。共同管理者名單一變就重新訂閱，先前因簽章者不在名單而沒收的名冊會再送來。
   - 共同管理者名單只從擁有者的名冊更新、而且只看擁有者那邊的時間：擁有者的名冊即使比已採用的舊（成員那部分不採用），它列的名單照樣生效。與自架站（SDK ADR 0135 §4）同一規則，兩邊對「現在誰是共同管理者」的答案一致。
   - 成員內容照舊：所有合法簽章者裡 `updatedAt` 最新的那份勝出。擁有者端也記下共同管理者發的，下次發布才不會蓋掉他們的修改。
   - `isOrgCoAdmin()`；`onOrgInfo` 多 `coAdmin: true`。
   - `publishRoster(..., { admins })`：
     - 擁有者：沒給 `admins`＝沿用現有名單（入職自動核准等路徑不會洗掉它），給空陣列＝清空。
     - 共同管理者：用自己的金鑰簽、不寫 `admins`；成員裡少了任何一位共同管理者就丟 `roster-drops-admin`、不發出（發出去也會被所有人丟掉）。
4. **畫面（桌面 `RosterAdminModal`、手機 `RosterAdminScreen`）**：
   - 擁有者多一欄「共同管理者」（每行一個 npub，預填現有名單）。
   - 共同管理者也看得到 🗂／設定裡的名冊管理入口，畫面上沒有共同管理者欄、沒有邀請碼與託管、沒有儲存槽區，有一行說明它能改什麼、不能改什麼；`roster-drops-admin` 顯示專屬訊息。
5. **只屬於擁有者的不變**：
   - 入職邀請碼與核准入職請求（ADR-0156）。邀請碼裡的管理者 pubkey 是擁有者，成員端的信任根仍是它。
   - 金鑰託管（ADR-0163）：員工的私鑰備份只封給擁有者——使用者選「只交給擁有者」，託管對象多一位就多一個能讀員工歷史的人。
   - 離職接管、公司儲存槽。
6. **順手修**（同一個畫面、共同管理者會直接踩到）：
   - 桌面群組欄沒預填，留空發布會把組織群組洗掉 → 留空＝沿用現有群組，placeholder 說明。
   - 手機沒有群組欄，發布時傳 `undefined` 也會洗掉 → 改傳現有群組。

## 理由

- 擁有者仍是唯一能改「誰是管理者」的人。一把共同管理者金鑰外洩，損害限於成員與政策，擁有者發一份新名冊把它移出名單就止血。
- 共同管理者簽的名冊必須保留所有管理者，擁有者是仲裁者，不會出現共同管理者互踢。
- 不新增事件種類：名單與名冊同一個 replaceable 事件，訂閱、存檔、自架站自動套用都沿用。

## 後果

- 擁有者金鑰遺失：共同管理者仍能維護成員、政策、群組；不能改管理者名單、不能核准入職請求、拿不到託管。換擁有者仍走 ADR-0052 輪替，並更新自架站的 `ROSTER_ADMIN_PUBKEY`。
- 共同管理者之間沒有鎖：兩位同時發布，較新的那份勝出，另一份的修改要重做。
- 共同管理者發布時，桌面群組欄若有填，填的群組會把它自己加進每個群（與擁有者自動加入自己同一規則）。
- 自架 Node 站（ADR-0414）要升到 SDK v0.90.0 才會套用共同管理者簽的名冊；舊版站只認擁有者，共同管理者發的名冊客戶端照採用，但站上的白名單不跟著換。Worker／官方錨點沒有名冊套用，不受影響。
- 舊客戶端只訂閱擁有者：看不到共同管理者發的名冊，直到擁有者再發一份。所有成員都要升到帶這個功能的版本，共同管理者才實際可用。
