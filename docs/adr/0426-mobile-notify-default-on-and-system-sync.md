# 0426. Android 版訊息通知預設開，開關跟系統設定同步

- 狀態：已接受
- 日期：2026-11-21
- 相關文件：ADR-0116（行動端通知，原本預設關）、ADR-0410（Android 原生本機通知）、ADR-0272／0274（前台服務保活）、ADR-0076（隱藏預覽）、ADR-0294 §2（per-identity 狀態分類）

## 背景與問題

使用者 2026-11-21 要求先補可靠性，並選了這兩項：

1. **預設關**：ADR-0116 讓通知預設關，要使用者自己到設定打開。Android 版自 ADR-0410 起已經能在背景跳本機通知、前台服務也預設開，
   但沒打開通知的人仍然不知道有新訊息——對一個通訊軟體來說，「收得到但不會提醒」幾乎等於收不到。
2. **開關會說謊**：ADR-0410 列為已知殘餘——使用者之後在系統設定把通知關掉，App 裡的開關仍顯示「開」，通知卻不會出現。

ADR-0116 預設關的理由是「瀏覽器只肯在使用者手勢裡要權限」。這條在 Android 殼不成立：原生外掛向系統要 `POST_NOTIFICATIONS` 不需要手勢。

## 考量的選項

- A：維持預設關，只在聊天清單放一條「打開通知」提示——還是要多一步，而且多數人會略過。
- B：Android 殼第一次登入就問一次權限；瀏覽器預覽維持預設關（採納）。
- C：每次開機都問，直到使用者允許——騷擾；Android 13 起拒絕兩次後系統也不會再跳。

## 決策

採 B：

1. **預設值依環境**（`initialNotifyWanted`）：使用者選過就照他的選擇（`nb.notify` 為 `"1"`／`"0"`）；
   沒選過時，Android 殼＝要，瀏覽器預覽＝不要。
2. **第一次登入問一次**（`shouldAskNotifyOnStart`）：只有 Android 殼、而且從沒選過。允許記 `"1"`、拒絕記 `"0"`，之後不再自動問，使用者隨時可到設定打開。
3. **偏好與系統權限分開存**：`notify` 是使用者「想不想要」，`notifyPerm` 是系統目前允不允許（`granted`／`denied`／`unknown`）。
   開關顯示與是否送通知都看 `effectiveNotify(想要, 權限)`＝想要而且系統沒有關掉。
4. **回到前景就重查**：`visibilitychange` 變成可見時呼叫 `notifyPermission()`——原生殼走新增的 `LocalNotify.checkPermission()`（只查 `areNotificationsEnabled()`，不跳對話框），
   瀏覽器看 `Notification.permission`。系統關掉時開關顯示關、並出現「去系統設定打開」的說明；在系統設定打開後回到 App，開關自動恢復，**使用者的偏好本身不會被改掉**。
5. 查不到（舊版 APK 的外掛沒有 `checkPermission`、或外掛丟例外）＝`unknown`，不改顯示——舊 APK 配新前端時行為與以前相同。
6. 說明文字從「打開後再回來按一次」改成「回到 Cinderous 就會生效」。

一樣只用系統本機通知，不經任何第三方推播；`notifyHidePreview`（ADR-0076）照舊。

## 後果

- 正面：
  - Android 新使用者第一次登入就有通知，不必知道要去設定打開。
  - 開關跟系統設定一致，不會再出現「顯示開、收不到」。
  - 在系統設定打開通知後不必回 App 再按一次。
- 負面 / 已知殘餘風險：
  - 第一次登入多一個系統權限對話框。
  - 既有使用者（`nb.notify` 已是 `"0"` 或從沒設過）：從沒設過的人升級後第一次登入也會被問一次；選過關的人維持關。
  - 只在回到前景時重查；App 在背景時系統關掉通知，下次通知就靜默略過（原生端本來就會檢查），回前景時開關才更新。
  - 原生外掛的 `checkPermission` 沒有自動化測試，要實機驗收。
- 後續行動 / 待辦：實機驗收（見 OPERATOR-TODO §B）：
  1. 清除 App 資料後第一次登入 → 跳系統通知權限對話框；允許 → 設定頁開關是開的。
  2. 到系統設定關掉 Cinderous 的通知 → 回到 App，開關變關、出現說明。
  3. 再到系統設定打開 → 回到 App，開關自動變回開，背景收訊有通知。
  4. 第一次登入時拒絕 → 開關是關的；之後重開 App 不再被問。
