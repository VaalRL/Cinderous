# ADR-0334：前向保密開關改為帶時間戳的 LWW——「關閉」原本關不掉

- 狀態：已採用
- 日期：2026-08-05
- 關聯：ADR-0245／0306（FS opt-in 與實驗性上線）、ADR-0314（明示退場 `"none"`）、ADR-0071（加密雲端快照）、ADR-0242（per-key LWW）、ADR-0322（裝置撤銷）、ADR-0327（同一類「分不出兩個狀態」的錯）

## 1. 使用者按下「關閉」，系統會把它打開回去

原本的合併規則：

```ts
enabled: local.enabled || content.fs.enabled === true   // OR，沒有時間概念
```

OR 的用意是「舊快照不得把新啟用蓋掉」——**方向是對的，但只考慮了啟用那一側**。停用同樣是使用者較新的決定，卻被壓過去：

1. A 按下停用 ⇒ `enabled: false`。
2. B 的快照說 `true`。
3. A 一重連就抓回那份快照 ⇒ OR ⇒ **又變回 `true`**。

🔴 **這與同步快慢無關。** 快照是**可取代事件**（每台一份，中繼保留最新），**B 不必還在線上**——它可以是一支三個月前弄丟的手機。那份 `enabled: true` 就躺在那裡，而使用者**沒有辦法從手上的裝置清掉它**（`purgeCloudSnapshot()` 只能清自己那份）。

⇒ 在多裝置情境下，**單台停用永遠回不去**。

### 1.1 兩個更難看的後果

**產生矛盾狀態 `enabled: true, retired: true`。** 個人檔的宣告是 `enabled ? "fs" : retired ? "none" : 缺席`——`enabled` 先判，所以宣告變回 `"fs"`、聯絡人重新釘選；使用者按下的「明示退場」被完全撤銷，而 `retired` 成為一個永遠讀不到的死旗標。

**UI 不會知道。** `fsEnabled` 只在登入時被讀進前端，合併之後**沒有任何事件推回**。⇒ **開關顯示「關」，引擎其實是「開」**，靜默不一致到下次重新登入為止——那正是這個專案一路在防的「假的開關」。

## 2. 決策

### 2.1 帶時間戳的 LWW

`StoredFsState` 加 `enabledAt`：`enabled` 最後一次被**使用者動作**改變的時間。合併沿用 ADR-0242 `mergeSyncedPrefs` 的形狀（**不另發明**）——比時間戳，較新者勝。

- **平手時偏向 `true`**：保留原本 OR 的安全側。同一毫秒各按一次的機率可忽略，而萬一發生，「多加密了」比「以為加密其實沒有」安全。
- **沒有時間戳的一方視為更舊**：舊版快照與升級前的本機資料都沒有這個欄位。若把缺省當「現在」，第一次同步就會讓舊值贏。
- **兩邊都沒有時間戳 ⇒ 沿用舊的 OR**：升級當下不改變任何人的狀態。

### 2.2 已撤銷的裝置不投票

一台弄丟／已交還、已被 `removeDevice()` 撤銷的裝置，它的快照仍留在中繼上替它投票。而使用者清不掉別台的快照。

⇒ `mergeSnapshotContent` 收 `fromRevokedDevice`，為真時 FS 開關**只採用本機的值**。

⚠ **只擋開關這一項**，不是整份快照都不採用。撤銷的語意是「拿不到新的 EK」，不是「這台的資料全部作廢」；把它擴大成「整份忽略」是另一個決策，不在本 ADR 內順手做。

### 2.3 翻轉要通知 UI

新增 `onFsEnabled(enabled)`：合併真的改變開關時發出，兩端設定頁跟著動。

🔴 **這條不是錦上添花。** 沒有它，就算合併規則修對了，使用者仍可能看到與實際不符的開關——**修好行為卻沒修好顯示，等於只修了一半**。

## 3. 這是同一類錯的第二次

ADR-0327 修 `cloudSync` 時是「**分不出『從未設定』與『明確關閉』**」；這次是「**分不出『舊的啟用』與『新的停用』**」。

兩次的形狀相同：**一個沒有時間／來源概念的合併規則，把使用者較新的決定壓過去，而 UI 不會說。** 值得記著這個模式——下一個同步欄位加進來時，先問「它分得出這兩個狀態嗎」。

## 4. 買不到什麼

1. **時鐘不可信。** LWW 依賴各裝置的本機時間；時鐘歪掉的裝置可能贏得不該贏的合併。這是 LWW 的固有性質（ADR-0242 已承擔同樣的取捨），沒有在本 ADR 內另解。
2. **升級前就存在的殭屍快照仍沒有時間戳** ⇒ 第一次合併走的是「本機有時間戳就本機贏」那條。使用者升級後**按一次停用**即可穩定下來；但在他按之前，行為與升級前相同。
3. **不解決「別台的快照清不掉」這件事本身**——只讓已撤銷的那些不再投票。未撤銷但已不再使用的裝置仍會投票，那要靠使用者去移除它（設定頁的裝置清單，ADR-0322 S3）。
