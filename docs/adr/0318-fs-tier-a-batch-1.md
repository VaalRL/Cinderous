# 0318. FS 擴大批一（檔案 metadata ＋ 共享行程）：只 retarget，不帶 EK hint

- 狀態：已接受
- 日期：2026-08-03
- 相關文件：**ADR-0315（本工作是其第 2 步；第 1 步可觀測性已由 ADR-0316 完成、閘門解除）**、
  ADR-0245（1:1 FS 實作，`ek` hint 的出處）、ADR-0264 §9（行程 id ＝ rumor 雜湊、補送形狀一致）、
  ADR-0095（rumor.id 跨成員一致）、`packages/core/src/giftwrap.ts`、`calendar.ts`

## 背景與問題

ADR-0315 判定 Tier A「只差送件側傳選項」。實際動手前細看，發現一個**不能照抄 1:1 作法**的約束。

1:1 的 FS 做兩件事（ADR-0245）：

1. 把 wrap **加密到對方的 EK**（retarget）；
2. 在 **rumor 內嵌自己的 `ek` hint**，讓對方即時學到、免一次元資料往返。

**第 2 件對 Tier A 是有害的。**

## 關鍵約束：Tier A 的 rumor 是內容定址的識別碼

- **行程**：`wrapCalendarEvent` 的 `id = getEventHash({...rumor, pubkey})`，RSVP 靠這個 id 對回去。
  ADR-0264 §9 為此立過規則——補送群組行程給單一成員時必須用**同一個形狀**重建 rumor，
  否則「收件人會得到一個新 id 的重複行程，而且原本的 RSVP 全對不回去」。
  `calendar.ts` 的註解甚至寫著「與 `wrapGroupCalendarEvent` 產出的 rumor **逐位元組相同**」。
- **群訊／檔案 metadata**：`rumor.id` 是**跨成員一致**的識別（ADR-0095），回條與引用都靠它。

`ek` hint 是**會輪替的值**（ADR-0313 每 7 天換一把）。把它放進 rumor ＝

- 同一個行程在輪替前後補送會產生**兩個不同的 id** ⇒ 重複行程 ＋ 孤兒 RSVP；
- 把一個**非決定性的值**放進本該由內容決定的識別碼。

## 決策

1. **Tier A 只做 retarget，不帶 `ek` hint。** rumor 內容一個位元組都不動。
2. **hint 的功能由 kind 10040 公告承擔。** 這條路以前不可靠（公告 TTL 約 7 天、只在啟用與手動
   換鑰時發），但 **ADR-0313 的自動輪替讓它每 7 天刷新一次**——先做 0313 才讓本決策成立。
3. **批一範圍**：檔案 metadata（`wrapFileMessage`）＋共享行程（`calendar.ts` 的 `fanOut`，
   一個私有 helper 涵蓋 1:1 行程／群組行程／RSVP 三個公開 API）。
   **群訊留批二**——它需要先定義群組的降級警告語意（ADR-0315 §其他要先想清楚的），
   否則 15 人群裡 3 人沒 EK 會每送一則跳 3 次警告。
4. **收件端零改動**：`openFs()` 多鑰解封早已掛在 kind 1059 的收件路徑上。
5. **失敗語意沿用既有**：不知道對方 EK ⇒ 該份退回加密到身分（＝現況），
   per-recipient 各自決定；解不開的情形已由 ADR-0316 可觀測。

## 理由

- **rumor.id 的穩定性優先於一次元資料往返**。hint 買到的是「對方早幾分鐘知道我的新 EK」；
  代價是識別碼變成非決定性——那會壞掉行程與回條這些**跨時間**的東西。不對等。
- **一個私有 `fanOut` 涵蓋三個公開 API**：改動面比逐一改小，且不可能漏掉其中一條路徑。
- **批一刻意避開群組**：把「需要新決策」的部分（降級語意）與「純接線」的部分分開，
  讓這一批可以直接驗證、不必等產品決定。

## 後果

- 正面：檔案名稱／大小／MIME 與行程標題／時間／地點這些**真正敏感**的欄位進入 FS 保護；
  收件端零改動；成本近乎零（見下）。
- **成本（實測）**：對 1–400 字的全樣本量測「只 retarget」相對「加密到身分」的事件位元組差，
  **最大 3 位元組**（base64/JSON 編碼雜訊，無 NIP-44 padding 跳階）。
  額外事件數 **0**、額外中繼請求 **0**、CPU 相同。
  （對照：若照 1:1 帶上 `ek` hint，同一量測是 38% 的樣本跳一階、平均 +139B——
  這也是「不帶 hint」在成本面的附帶好處，但**不是**主要理由。）
- 負面 / 已知殘餘風險：
  - 對方若從未收過我的 1:1 FS 訊息、也還沒抓到我的 10040，**這批事件就沒有 FS**（退回身分）。
    自動輪替（ADR-0313）讓 10040 常保新鮮，但首次接觸仍可能落空。
  - 擴大加密面 ＝ 擴大**尚未經外部審計**的程式碼作用範圍（ADR-0306 定位不變）。
- 後續行動 / 待辦：
  - **批二：群訊**——先定義群組降級警告語意。
  - ADR-0315 §UI 文案的提醒仍然有效：設定頁現在寫「發給聯絡人的訊息」，涵蓋範圍變了要跟著改。
