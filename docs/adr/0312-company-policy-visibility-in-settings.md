# 0312. 設定頁條列公司政策：讓「按鈕消失」變成一句話

- 狀態：已接受
- 日期：2026-08-03
- 相關文件：ADR-0048（企業政策開關——政策的定義）、ADR-0310（桌面補完貼圖閘門）、
  ADR-0311（行動端消費政策；本缺口於該次列為待辦）、ADR-0157（組織資訊唯讀摘要，本區塊的鄰居）、
  `packages/core/src/org-roster.ts`、`apps/desktop/src/ui/SettingsPanel.tsx`、
  `apps/mobile/src/screens/SettingsScreen.tsx`

## 背景與問題

ADR-0048 的客戶端政策層，表現形式從第一天起就只有一種：**按鈕消失**。

員工打開 App，📎 不見了、通話鈕不見了、😊 不見了——他無從分辨這是

- 公司政策關掉的，
- 這個版本沒有這個功能，
- 還是壞了。

第三種猜測最貴：他會去回報一個不存在的 bug，或以為 App 不可靠。而政策**本來就不是祕密**——
它由公司簽章的名冊分發，員工的裝置上就有那份文件，只是沒人把它翻譯給使用者看。

ADR-0310／0311 分別補完了桌面與行動端的閘門，兩份都把這件事列為待辦。

## 考量的選項

- **選項 A：在按鈕原位顯示停用狀態（灰掉＋提示）。** 每個入口各做一次、四個地方各一種寫法，
  且「灰掉的按鈕」在小螢幕上是純粹的空間浪費（行動端輸入列已因擠不下而折行，ADR-0287）。否決。
- **選項 B：功能被擋時跳訊息。** 把噪音加在最高頻的操作流程上，且使用者已經知道按不下去了。否決。
- **選項 C（採用）：設定頁一個唯讀區塊，條列政策做了什麼。** 使用者困惑時會去看設定；
  答案放在他會去找的地方，而不是他每天會撞到的地方。

## 決策

1. **共用的攤平函式放 core**：`policyNotices(policy)` → `PolicyNotice[]`
   （`{ id, kind: "disabled" | "rule", value? }`）。**core 不認識 i18n**，
   所以它只決定「有哪幾條、什麼順序」，文案留給各端。
   這樣桌面與行動端不會各列一份清單，新增政策旗標時也只有一個地方要改。
2. **兩段式呈現**：
   - **已停用的功能**（`disableFiles`／`disableCalls`／`disableStickers`／`disableCloudBackup`）
   - **生效中的規則**（`forceTurn`／`messageTtlDays`／`relayFilesMaxMb`）——功能還在，但行為受限。
   分兩段是因為這兩類對使用者的意義不同：前者是「你不能做」，後者是「你可以做，但會這樣做」。
3. **文案講清楚邊界**，不只列名稱：
   - 通話寫「發起語音／視訊通話（仍可接聽）」——ADR-0311 只擋發起，不擋接聽。
   - 貼圖寫「貼圖與自訂 emoji（仍看得到別人送的）」——只擋送出。
   - `forceTurn` 寫「通話與檔案只走 TURN 中繼（不揭露內網 IP）」——講它**為你做了什麼**，
     而不是丟一個技術名詞。
   - 結尾固定一句「以上由貴公司簽章的名冊設定，無法在本機關閉。」——明示這不是本機開關，
     省掉使用者去找哪裡可以打開的時間。
4. **落點**：桌面設定面板**身分分頁**，緊接在既有的「組織資訊」（ADR-0157）之後；
   行動端設定頁的對應位置。政策為空（或無政策）時**整段不渲染**——
   一般個人身分完全看不到這一區。

## 理由

- **政策不是祕密，隱瞞它只會製造誤判**。名冊已經在員工裝置上，顯示它不洩漏任何新資訊。
- **放 core 是為了避免第三次漏接**：ADR-0311 的成因就是「UI 層的政策兩端各接一次，而其中一端沒接」。
  清單邏輯只有一份，下次加旗標時漏掉的機率大幅降低（core 的測試也會直接指出）。
- **兩段式＋括號註記**是誠實成本最低的作法：使用者最常誤解的就是「停用通話＝我也接不到」，
  而那正好是錯的。

## 後果

- 正面：使用者能自己回答「為什麼沒有這個按鈕」；支援成本下降；
  政策旗標的顯示邏輯有單一真實來源。
- 負面 / 已知殘餘風險：
  - 文案是**靜態對照**，管理者無法自訂說明（例如「依資安規範 X 條」）。
    名冊已有 `welcome` 可放公司訊息，暫不另開欄位。
  - 條列只反映**目前採用的名冊**。名冊更新前顯示的是舊政策——與實際生效的規則一致，
    因為引擎也是以同一份名冊為準。
- 後續行動 / 待辦：無。ADR-0310／0311 的待辦至此清空。
