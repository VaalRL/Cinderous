# ADR-0277：行動端正式進入點與「建立身分」為預設登入路徑

- 狀態：已接受
- 日期：2026-07-29
- 相關：ADR-0081（行動端登入 A/B）、ADR-0085（web preview 外框）、ADR-0112（絕不無密碼記住 nsec）、ADR-0117（記住我）、ADR-0248（初次登入預設明亮）、ADR-0251（桌面把 nsec 登入降為次要）、ADR-0274（Capacitor 打包）

## 脈絡

實機檢視行動版初次登入時發現兩個疊在一起的問題，兩者都是**使用者一開 App 就撞到**的。

### 一、APK 打包的是開發預覽台，不是 App

`apps/mobile/index.html` 載入的是 `src/preview.tsx`——ADR-0085 為了在瀏覽器裡看行動版而做的預覽台：

- 標題寫「Cinderous 行動端 — Web Preview」
- 一排「示範／真實 relay」切換鈕，**預設是「示範」**
- 一個「示範 nsec（複製後貼到「用私鑰登入」，名稱隨意）」的區塊，附「複製」鈕
- 一段說明：「示範模式：登入後可與機器人「小幫手／阿明」對話（記憶體 relay）」
- 整個 App 被包在一個 390×800 的手機外框圖裡

ADR-0274 讓 Capacitor 以 `webDir: "dist"` 打包 vite 產物，而 `dist/` 就是從這個 `index.html` 建出來的。
於是**Android APK 開起來看到的就是這個預覽台**：手機裡再畫一支手機，
使用者被要求先複製一串 nsec 才進得去，而且預設連的是記憶體示範後端——訊息根本不出裝置。

這不是「文案不好」，是進入點接錯。

### 二、行動端根本沒有「建立身分」的路徑

`apps/mobile/src/auth.ts` 只有三個入口：`identityFromNsec`、`identityFromSecret`、`identityFromPairBundle`——
**全部都要求使用者已經有一把金鑰**。登入畫面標題直白寫著「用私鑰登入」，提示是
「在桌面版『設定 → 身分備份』複製你的 nsec」。

也就是說：**手機是第一個裝置的人，沒有入口**。他必須先去裝桌面版、建身分、複製 nsec、
想辦法把 nsec 傳到手機（而那本身就是把私鑰丟進剪貼簿與傳輸通道的壞習慣），才能用手機版。

桌面早在 ADR-0251 就把 nsec 登入降為次要連結、以「填名字＝建立新身分」為主要路徑；
行動端從未跟上。

## 決策

### 1. 進入點與預覽台分家

| 檔案 | 用途 | 進 `dist/`？ |
| --- | --- | --- |
| `index.html` → `src/main.tsx` | **正式 App**：滿版、預設連生產錨點、零示範字樣 | 是 |
| `preview.html` → `src/preview.tsx` | 開發預覽台（外框／示範後端／示範 nsec） | **否** |

`vite.config.ts` 明確把 `build.rollupOptions.input` 釘在 `index.html`。
`vite dev` 仍服務得到 `preview.html`（開發照舊），但它不會進 `dist/`，也就**不可能被打進 APK**。

`main.tsx` 傳 `relayUrl={DEFAULT_RELAY}`：正式 App 不提供「示範後端」這個選項。
示範後端（`createDemoChat`）保留給預覽台與測試——那是它該待的地方。

`index.html` 只留撐開版面所需的高度鏈（`100dvh`）與關閉整頁回彈，**不放任何配色**：
視覺一律由 App 內的 `@cinderous/theme` 決定，避免兩處主題打架。

### 2. 「建立新身分」成為預設登入路徑

新增 `createIdentity(name)`：本機生成 secp256k1 金鑰，只要顯示名稱。

`NsecSignInScreen` 依 ADR-0251 的桌面模式重整：

- 預設只顯示**顯示名稱**＋**記住我密碼**兩欄，主按鈕是「建立新身分」
- nsec／備份碼欄**預設收合**，底下一條次要連結「已經有身分？用 nsec 登入」點了才展開
- 展開後主按鈕變回「登入」，並提供「← 改為建立新身分」折返

文案同步改寫：標題由「用私鑰登入」改為「登入 Cinderous」；提示由「在桌面版複製你的 nsec」
改為說明這是去中心化端對端加密、身分是本機生成的金鑰、不需手機號碼或電子郵件。

### 3. 不變的紅線

- **密碼留空＝不記住**。ADR-0112 依舊：絕不無密碼把 nsec 落地。新路徑的密碼欄走的是
  ADR-0117 同一條 Argon2id 包裹，沒有另開捷徑。
- 私鑰只在本機生成與保存，不因為「現在是 App 自己生的」就放寬任何事。

## 後果

**正面**

- 手機可以是第一個裝置——這是「去中心化即時通」最基本的期待，先前竟然做不到。
- APK 不再洩漏開發用詞與示範 nsec；也不再有「使用者以為在聊天、其實訊息沒出裝置」的風險。
- 行動與桌面的初次體驗一致（填名字→建身分），減少兩套心智模型。

**負面／代價**

- 多一個 HTML 進入點要維護。以 `vite.config.ts` 的顯式 `input` 與本 ADR 表格記錄，
  避免日後有人「順手」把 `preview.html` 加回 build 輸入。
- 使用者更容易**不小心建出多個身分**（每次填新名字就是一把新金鑰）。行動端已有身分登錄
  （ADR-0138/0146 名稱唯一檢查）擋掉同名，但不同名仍會各自成身分——這與桌面現況相同，
  暫不另做收斂。

**待辦**

- 實機驗收：Android APK 首開應直接看到「登入 Cinderous」卡片，無外框、無示範鈕。
- `dist/` 產物大小未因此下降（示範後端仍被 `createBackend` 參照而打包）；若日後要瘦身，
  可把 `createDemoChat` 改成僅預覽台動態載入。
