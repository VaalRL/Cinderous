# 0412. 登入畫面收成三條路：建立新身分／我還有另一台裝置／我的裝置都沒了

- 狀態：**已接受（Accepted，2026-11-11）**——使用者 2026-11-11 決定推 ADR-0305（入口整併）；本文是它要求的「實作 ADR」的第一階段
- 日期：2026-11-11
- 相關文件：**0305**（入口整併提議，本文實作其提議 1、4 與 §6 的文案）、0303 §6（裝置授權加／刪不對稱）、0304 §5（新裝置對加入前的訊息沒有金鑰）、
  0072／0118（配對搬家）、0070／0200（救援登入碼）、0071（多裝置狀態同步）、0122（瀏覽器本地密碼／`needNsec`）、0138／0146（多身分、以名稱登入既有身分）、
  0156（入職邀請碼）、0277（行動端建立新身分為主路徑）、0251（次要動作用幽靈鈕）、0278／0287（UI 不得說謊）

## 背景與問題

ADR-0305 查出登入相關入口有六個，而且同一樣東西（nsec）出現在兩個入口、用兩套文案；但程式其實早就用 `isBackupCode` 把 nsec 與救援登入碼當成同一件事。它提議收成三條路，對應使用者的三種處境，並要求另立實作 ADR。

動工前查證還發現一個 ADR-0305 沒寫到的缺口：**桌面版第一次啟動沒有「用救援登入碼或 nsec 找回身分」的入口**。nsec 欄只在 `needNsec`（有設定檔但拿不到金鑰，ADR-0122）時出現；裝置全沒、手上只剩救援登入碼的人，得先隨便建一個身分，再到「新增身分」裡匯入。

## 考量的選項

- **選項 A：只改文案**。把「用 nsec 登入」「從舊裝置匯入」改成以處境命名。成本最低，但桌面的缺口還在。
- **選項 B（採用）：改文案＋桌面補〈我的裝置都沒了〉＋兩端排成同一個結構**。不碰協定，也不碰配對流程。
- **選項 C：連 ADR-0305 §7 的「授權／搬資料兩階段」一起做**。這要改配對協定（目前一次性全量搬家），而且和 0303 §6 的 live 授權綁在一起；0303 的棘輪那一半已延後到外部審計之後。現在做是先做一半的狀態機。延後。

## 決策

1. **登入畫面固定三條路**（桌面 `SignIn`、行動端 `NsecSignInScreen`）：
   - 主路徑：**建立新身分**（顯示名稱；名稱命中本機既有身分時改為登入它，ADR-0146；貼邀請碼時轉入職面板，ADR-0156——兩者行為不變）。
   - 「**已經用過 Cinderous？**」底下兩條次要入口（幽靈鈕／連結，ADR-0251），順序固定：
     - **我還有另一台裝置**＝配對搬家（ADR-0072／0118，流程不變）。
     - **我的裝置都沒了**＝貼**救援登入碼或 nsec**，同一個欄位；偵測到救援登入碼才多問救援密碼。
   - 以**處境**命名，不以手段（nsec、配對碼）命名——承接 ADR-0200 的正名線。
   - 貼了邀請碼時兩條次要入口都收起（入職面板優先）。
2. **桌面〈我的裝置都沒了〉**（新的 `onRestore`，取代只在 `needNsec` 出現的 `onEnterNsec`）：
   - 解出金鑰後由 `resolveRestore`（`packages/engine` 的 profiles）決定去處：本機已有那把金鑰的身分（含隱藏的）就回到它，不建重複；沒有就以那把金鑰建新的設定檔（走「新增身分」匯入的同一條路 `addIdentity`），名稱用上方的顯示名稱欄。
   - 中繼站：救援登入碼自帶的優先，其次是畫面上選定的、最後是第一座錨點。
   - 救援密碼錯與格式不符**回同一句錯誤**，不給猜密碼的人訊號（同 `identityFromSecret`）。
   - 瀏覽器建新設定檔時仍要本機密碼（ADR-0122）；回到既有身分不用。
   - `needNsec` 時面板**一進來就打開**（`restoreFirst`）——那是唯一的出路。
3. **行動端**：結構同上；從解鎖畫面選「改用私鑰登入」進來時，面板一進來就打開；配對畫面的返回改叫「← 返回登入」。
4. **文案「可延後但有期限」**（ADR-0305 §6、0278）：〈我的裝置都沒了〉打開時一律顯示能找回什麼、不能找回什麼——中繼站上的近期訊息會回來；更早的歷史只能從**還開著的舊裝置**搬，或之前已開多裝置同步，「舊裝置沒了就真的沒了」；前向保密的子鑰不在救援登入碼與 nsec 裡。行動端過去這一格沒有任何提示，現在補上。
5. **ADR-0305 未決項的處理**：
   - 0071 多裝置狀態同步**留在設定頁**，不併進登入畫面（它是「開啟後持續運作」的設定，不是一次性的入口）。
   - 「新增身分」（設定裡，ADR-0138）維持原樣：那是已經在用的人加第二個身分，不是第一次進來的入口。
   - 「用 nsec 登入」**沒有移除**，只是併進〈我的裝置都沒了〉；真正收掉直接貼 nsec 這條捷徑仍排在 0303 §6 上線之後（ADR-0305 提議 6）。
   - 授權／搬資料兩階段（ADR-0305 提議 2、3、§7）**這次不做**，見選項 C。

## 理由

- 主要成本在介面與文案；辨識邏輯（`isBackupCode`）與建立設定檔（`addIdentity`）都已存在，照 Fix First 重用。
- 桌面缺口是真的會卡住人的路：手上只有救援登入碼的人，第一個畫面上找不到能用的按鈕。
- 不碰協定，風險小、可回滾；兩階段等 0303 §6 一起設計，避免做出半套狀態機。

## 後果

- 正面：
  - 入口從六個收成三個，而且兩端的名稱、順序、結構一致。
  - 桌面第一次啟動也能用救援登入碼找回身分。
  - 行動端〈我的裝置都沒了〉補上誠實的還原範圍說明。
- 負面／已知殘餘風險：
  - 直接貼 nsec 成為一台裝置的捷徑仍在（ADR-0305 §5 要收掉的那條），只是換了名字。要等 0303 §6。
  - 配對仍是一次性全量搬家；「授權完成就能用、資料之後補」還沒有。
  - 桌面 `restoreIdentity` 的組裝（解碼→`resolveRestore`→進入或建立）沒有獨立的整合測試；判斷邏輯在 `resolveRestore`、畫面在 `SignIn` 各有單元測試。
  - 未做使用者研究（同 ADR-0305 已知限制）。
- 後續行動：
  1. 0303 §6 上線後：移除直接貼 nsec 的捷徑，〈我的裝置都沒了〉只收救援登入碼；〈我還有另一台裝置〉改成「先授權、再搬資料」兩階段。
  2. 使用手冊同步本次的入口名稱（本 PR 已改兩處）。
