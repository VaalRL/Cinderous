# 0320. FS 擴大批二（群訊）：逐位成員 retarget，群組控制訊息不動

- 狀態：已接受
- 日期：2026-08-03
- 相關文件：**ADR-0319（群組 FS 狀態的呈現語意——本批的前置）**、ADR-0318（批一：只 retarget
  不帶 hint，本批沿用同一形狀）、ADR-0315（擴大順序與 fail-open 的判準）、ADR-0027（群組
  成對扇出、對中繼隱形）、`packages/core/src/group.ts`

## 背景與問題

批一（ADR-0318）已把檔案 metadata 與共享行程接上 FS。批二處理群訊——技術形狀相同，
但有一個**必須另外決定**的問題：群組裡有哪些事件該 retarget。

## 決策

1. **群訊與群組檔案 metadata retarget**（`fanOutGroupRumor`，一個私有 helper 同時涵蓋
   `wrapGroupMessage` 與 `wrapGroupFile`）。
2. **逐位成員各自決定**：有那位成員的 EK 就用 EK 鎖，沒有就退回身分金鑰。
   同一則群訊因此可能「部分成員有 FS、部分沒有」——**那不是失敗，是盡力而為**，
   與 1:1 「不知道對方 EK 就退回」是同一條規則。
3. **`rumor` 一個位元組都不動**（沿用 ADR-0318）：`rumor.id` 是跨成員一致的群訊識別，
   回條與引用都以它為鍵（ADR-0095）。不帶 `ek` hint。
4. **群組控制訊息（`wrapGroupControl`）不 retarget。** 見下。
5. **成員面板顯示三態狀態**，實作 ADR-0319 的語意：
   `known` / `unknown`（常態，不上警示色）/ `lost`（曾知現無，⚠）＋一行匯總；
   自己不計入；FS 未啟用時整段不顯示。引擎新增 `fsPeerState(pubkey)` 供兩端共用。

## 🔴 為什麼群組控制訊息不 retarget

ADR-0315 為「收回訊息（kind 5）」立過一條判準：**看失敗的方向**。

- 一般訊息解不開 ＝ **fail-safe**（你沒看到不該看到的東西）。
- 收回事件解不開 ＝ **fail-open**（該收回的訊息繼續留在對方畫面上）。

群組控制訊息屬於**第二類，而且更嚴重**：

| 控制訊息 | 解不開的後果 |
| --- | --- |
| `group-create` | 成員**永遠不會加入這個群**，而建立者以為他在裡面 |
| `group-remove` | 被移除的人**繼續以為自己還在群裡**（其他人已經不再扇出給他） |
| `group-add` | 其他成員的名冊與實際扇出對象不一致 |

這些是**結構性事實**，不是內容。一則訊息掉了可以重傳；一個「你被移除了」掉了，
兩邊對群組成員的認知就永久分歧。

而它們的內容敏感度**不高於群訊本身**（群名 ＋ 成員 pubkey），
拿「可能永久分歧」換這個，不划算。

⚠ 這條要與 ADR-0316 一起讀：解不開現在**是可觀測的**（會進 `maybeEkLoss` 計數），
但可觀測不等於可復原——使用者只會看到「有 N 則解不開」，不會知道那是一封入群通知。

## 理由

- **逐位成員退回**讓 FS 成為漸進的：今天覆蓋 3 個人，明天多兩個人加你為聯絡人就覆蓋 5 個。
  不需要「全群都支援才啟用」這種永遠達不到的門檻。
- **一個私有 helper 涵蓋兩個公開 API**，與批一 `calendar.ts::fanOut` 的作法一致，不可能漏接。
- **控制訊息的例外有明確判準**（fail-open），不是臨時的謹慎——同一條判準已經否決過收回訊息。

## 後果

- 正面：群訊內容與群組檔名進入 FS 保護；使用者第一次看得到「群組裡誰受保護」；
  成本與批一相同（每份 wrap ≤3 位元組、零額外事件）。
- 負面 / 已知殘餘風險：
  - ~~**群組的 FS 覆蓋率會偏低。**~~ 🔵 **2026-08-04 已量測，並已解決（ADR-0326）。**
    量出來的形狀與這裡寫的不一樣：問題是**不對稱**的——**建群者**的覆蓋率天然是滿的
    （`createGroup()` 會 `ensureContact()` 每位成員），**被邀請者**才是問題，而且不是「偏低」
    是**結構性 0**（`applyControl()` 刻意不把其他成員加成聯絡人 ⇒ 他們的 10040 我根本沒訂，
    且不會隨時間改善）。ADR-0326 以 **seal 層 hint** 解決：發現改為對話式
    （他發過一次言即可），成本 +9.9 位元組/份，且**不多洩漏任何東西給中繼**。
  - 群組控制訊息維持靜態 ⇒ 群名與成員 pubkey 沒有 FS。
  - 成員面板要使用者主動去看（ADR-0319 已記）。
