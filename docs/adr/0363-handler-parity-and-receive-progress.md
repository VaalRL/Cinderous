# 0363. 收檔進度、進度節流，與「行動端漏接九個回呼」的結構性擋板

- 狀態：已接受
- 日期：2026-09-18
- 相關文件：ADR-0017（WebRTC 檔案傳輸，記下「收檔端無逐塊進度」）、ADR-0093（收檔另存語意）、
  ADR-0345／0346（送檔管線與惰性讀取）、ADR-0347／0349（串流落盤與原生另存）、
  ADR-0355（合集、續傳與整檔校驗）、ADR-0071（加密雲端備份）、ADR-0243（通話失敗提示）、
  ADR-0052（企業工作身分輪替）、ADR-0317（入群同意閘門）、ADR-0294 §2（per-identity state 守衛）

## 背景與問題

2026-09-18 的抽驗從三個方向查同一件事：**同一份引擎，兩個平台，有沒有哪一邊忘了接上。**

### 一、收檔端從來沒有進度（兩個平台都是）

ADR-0017 的「後果」就寫過：

> 收檔端無逐塊進度（`DataChannelReceiver` 未回報），僅「接收中→完成」。

那時檔案上限 100 MiB，這個窗口一閃而過。**ADR-0346／0355 把上限提到 1 GiB 之後，它變成
好幾分鐘**——而收件人在那幾分鐘裡看到的不是「沒有進度」，是一句**錯的話**：

檔案 metadata 走中繼先到（快），位元組走 P2P 後到。這中間 `sent === 0 < size` 且沒有 url，
於是泡泡顯示「📍 檔案在你另一台裝置」——那句話的本意是 ADR-0093 的**多裝置語意**
（位元組去了你的另一台），不是「正在下載」。收件人會盯著一個說檔案不在這台的泡泡，
而檔案正在傳進來。

### 二、送出端的進度**完全沒有節流**

分塊是 16 KiB。1 GiB ＝ **65,536 次**回呼，而每一次在 UI 端都是一趟「掃過整條對話、
重建陣列」。改上限那次沒有回頭看這裡。

### 三、行動端完全沒接九個 `ChatBackendEvents` 回呼

| 回呼 | 後果 |
| --- | --- |
| `onFileProgress` | 送 1 GiB ＝按下去之後數分鐘畫面毫無變化 |
| `onFileError` | 傳輸失敗**無聲**——泡泡停在原地，不知道該重傳還是該等 |
| `onCallFailed` | 通話失敗只有視窗關閉，沒有原因。而 `unreachable`（限制網路無 TURN 退路）最常發生的地方**正是行動網路**（CGNAT／對稱 NAT） |
| `onIdentityRotated` | 🔴 **不只是少一句提示**：後端已把歷史從舊 npub 接到新的，但記憶體的對話表還鍵在舊的上——那條對話會分裂成兩半 |
| `onGroupInviteHeld` | 邀請被閘門擋下（ADR-0317）而使用者完全不知情 |
| `onCloudBackup` | 見下 |
| `onMutes`／`onAssetCached`／`onRelayPool` | 行動端沒有對應功能可餵（見「刻意不接」） |

另外兩件順帶查出來的：

- **行動端從不註冊 `onStorageQuota`。** 掛勾與桌面共用、一直都在，行動端卻沒接——配額爆掉
  只有一行 `console.warn`，使用者看到的是「訊息收得到卻存不下來」，畫面上零線索。
  **手機 WebView 的配額比桌面小得多，最會撞到的平台反而最安靜。**
- **`onCloudBackup` 兩端都沒接。** 這是 2026-09-18 早上那次「讓雲端備份的沉默看得見」
  修正沒收尾的部分：桌面靠打開設定頁時現讀才看得到，而註解裡提到的重繪觸發器
  `backupNonce` **沒有任何程式碼 bump 它**；行動端則連顯示都沒有。
- **桌面的「已更新金鑰」提示是硬寫的中文**，英文使用者看到一串看不懂的字。

### 為什麼型別系統擋不住

`onFileProgress?` 是**可選**的。不接就是不接，型別完全合法，沒有任何測試會紅。
而這一類問題在這個專案裡**反覆發生**：`sweepInbox` 的瀏覽器分支、`onStorageQuota` 的
行動端註冊、ADR-0273 漏掉的第三個送檔入口，成因一模一樣。

## 考量的選項

- **收檔進度放在核心並自己節流。** 否決：核心（`packages/core`）不持有時鐘，注入一個只為了
  節流並不划算；而且送出端的節流也要一份，兩份節流各走各的遲早漂移。
- **收發各用一個回呼。** 否決：UI 兩邊要做的是**同一件事**（更新那一則的 `sent`），
  而訊息本身的 `outgoing` 已經說明了方向。兩個回呼只是讓每個呼叫端都要寫兩次。
- **靠人記得接。** 否決：上面列的每一次都是「有人忘了」，而且每一次都有人在審查。

## 決策

### 1. 收檔端逐塊回報，節流在引擎層

`DataChannelHandlers.onProgress`（核心，每塊都叫）→ `WebRtcTransfer.throttled()`（引擎，
150 ms 一次）→ `onIncomingProgress` → **`onFileProgress`（與送出端同一個回呼）**。

送出端也改走同一個 `throttled()`，六萬五千次因此降到每秒六、七次。

**頭尾一定送**：`received === size` 是完成、`0` 是起點，兩者漏掉都會讓進度條停在錯的地方。

### 2. UI 分得出「正在收」與「在另一台」

判準是 `sent > 0`：位元組真的在流進來。`sent === 0` 分不出「還沒開始傳」與「位元組在我
另一台裝置上」，那一格留給 `file_onOtherDevice`——第一塊 16 KiB 一到就跳成進度條。

桌面畫進度條；行動端把同樣的資訊寫進附註那一行（`接收中… 45%（120 MB / 260 MB）`）。

### 3. 接線齊備性做成擋板，不靠人記得

新增 `apps/mobile/src/handler-parity.test.ts`：掃出 `ChatBackendEvents` 宣告的全部回呼，
比對兩個 app 的 `src/`，**沒接的每一個都必須在 `NOT_WIRED` 裡寫下理由**。

理由只有一種是正當的：**這個平台沒有對應的功能可以餵**。「還沒做」不是理由——
那正是這支測試要抓的東西。清單另有兩道反向檢查：接上了就必須從清單移除（殭屍項目），
以及清單上的名字必須真的存在於介面上（改名後清單會失效）。

順帶把 `AppSession.perIdentityState.test.ts` 的掃描從 `useState` 擴到 `useReducer`——
它是**命名 state 的第二條路**，原本整個繞得過去。

### 刻意不接的（行動端）

| 回呼 | 理由 |
| --- | --- |
| `onMutes` | 行動端**還沒有每對話靜音功能**（唯一的 mute 是通話麥克風），接了也沒有 UI 可更新 |
| `onAssetCached` | 行動端**沒有自訂 emoji**（ADR-0223 backfill 的對象），沒有占位可重繪 |
| `onRelayPool` | 行動端**沒有中繼池顯示**，只顯示 home 單座的連線狀態 |
| `onSlotDeposit` | 企業儲存槽需要原生檔案系統，PRD §12 明說部分功能限桌面 |

前三項是**功能缺口**，不是接線缺口——它們留在 `NOT_WIRED` 裡，等功能做出來時測試會逼人回來。

## 理由

- **ADR-0017 早就寫下了這個缺口**，但它是寫在「後果」而不是「後續行動」裡，於是沒有人回去看。
  真正讓它變嚴重的是**另一個 ADR**（0346／0355 放寬上限）——而改上限的人沒有理由想到
  三年前的一行後果。這正是擋板要解決的事。
- **節流放引擎層而非核心**：兩個方向共用一份，不會漂移；而核心保持不需要時鐘。
- **收發共用一個回呼**：UI 兩邊做的是同一件事，分開只會讓每個呼叫端都要寫兩次，
  然後其中一次被忘掉——那正是本 ADR 在修的東西。

## 後果

- **正面**：兩個平台、兩個方向都看得到進度；大檔傳輸不再讓介面卡住。
- **正面**：漏接一個回呼會讓測試紅，而不是安靜地少一個功能。
- **正面**：行動端的配額警示、備份狀態、通話失敗原因、身分輪替接續都補齊了。
- **負面 / 已知殘餘風險**：
  - **`sent === 0` 那一瞬間仍然顯示「在另一台裝置」**。metadata 先到、P2P 還沒接上的那段
    窗口確實存在，而我們分不出「對方正要傳給我」與「位元組去了我的另一台」。
    第一塊一到就正確，所以窗口很短——但它不是零。
  - **節流是 150 ms 的固定值**，沒有依檔案大小調整。小檔會少幾筆中間值（無妨），
    極大檔的進度條更新頻率偏高（每秒六、七次仍遠低於逐塊）。
  - **擋板擋不住「接了但接錯」**，那需要人看。它擋的是「忘了接」。
  - **`NOT_WIRED` 的三個功能缺口沒有被這份 ADR 解掉**（行動端的每對話靜音、自訂 emoji、
    中繼池顯示）。它們現在至少**被寫下來了**。
  - 收檔進度**不進儲存**，傳到一半重開 app 會回到 0——與送出端一致，不是新引入的。

## 後續行動 / 待辦

1. 實機驗收：手機收一個 >100 MB 的檔，確認附註那行從「接收中 N%」走到完成，**而不是**「檔案在你另一台裝置」。
2. 實機驗收：手機通話在行動網路下失敗，確認對話裡留下「可改用 Wi-Fi」那句。
3. 評估行動端的每對話靜音（`onMutes` 的功能缺口）——多裝置收斂是 PRD §11 的承諾。
