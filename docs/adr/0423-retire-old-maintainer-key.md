# 0423. 停用並銷毀舊的維護者金鑰（ADR-0358 結案）

- 狀態：已接受
- 日期：2026-11-17
- 相關文件：ADR-0358（輪替維護者信任根，本 ADR 為其第 3 項後續行動的結案）、ADR-0239（信任根移出 CI）、ADR-0039（簽章 relay 清單）、`docs/MAINTAINER-ACTIVATION.md` §金鑰輪替

## 背景與問題

ADR-0358（2026-09-18）把維護者公鑰從 `6efd2603…` 換成 `7b5cd386…`，舊金鑰進入**並存期**：
已出貨、只認舊公鑰的客戶端（v0.0.15 以前）還要靠舊簽章收清單更新，所以舊金鑰先不銷毀，
等帶新公鑰的版本普及後再停用，並補一份結案 ADR。

兩個月後盤點時發現：

- 新公鑰從 **v0.0.16** 起出貨（`17e95e10`，2026-09-18），之後已發到 v0.0.24。
- 舊金鑰還有**兩份副本**：本機 `Downloads/maintainer.nsec`，以及 repo 的 GitHub Actions secret
  `MAINTAINER_NSEC`（2026-07-17 建立）。ADR-0239 只讓 CI 不再讀它，**secret 的值本身一直留著**——
  也就是說，ADR-0358 要防的那個曝險面（CI）上，舊金鑰其實還在。

## 考量的選項

- 選項 A：繼續並存，等有更明確的普及證據。
- 選項 B：現在停用舊金鑰，銷毀所有副本。

## 決策

採 **B**。2026-11-17 由維護者親手：

1. 刪除 GitHub Actions secret `MAINTAINER_NSEC`（`gh secret delete`；之後 `gh secret list` 為空）。
2. 刪除本機舊金鑰檔 `Downloads/maintainer.nsec`。
3. 從此**只用新金鑰簽章**；`relays.json` 變動後只跑一次 `bootstrap:sign`。

舊公鑰 `6efd2603…` 簽的清單此後不會再有更新。

## 理由

- **只認舊公鑰的客戶端已經不能用**：v0.0.18 起訊息走後量子混合加密（ADR-0365 等），
  發版政策要求每台裝置至少 v0.0.18，更舊的那台會永久丟訊。v0.0.15 以前的客戶端本來就收不到訊息，
  讓它們繼續收清單更新沒有實益。ADR-0358 擔心的「把仍在用的人變成孤島」已不成立。
- **並存的代價是真的**：舊金鑰在並存期仍然有效——若它在 CI 那二十天被拿走，攻擊者仍簽得出舊客戶端會接受的清單；
  而且它的一份副本至今還留在 GitHub。早一天銷毀就早一天關掉。
- **並存期要每次簽兩次、沒有自動化、漏簽不報錯**（ADR-0358 後果）；結束並存也消掉這個失誤來源。

## 後果

- 正面：唯一的信任根只剩新金鑰，且只存在維護者本機（與其離線備份）；CI 上不再有任何維護者金鑰。
- 負面 / 已知殘餘風險：
  - 仍在跑 v0.0.15 以前版本的客戶端（若還有）從此收不到清單更新；它們本來就收不到訊息，影響可忽略。
  - 舊金鑰若曾外洩，攻擊者仍可對**那批舊客戶端**簽出惡意清單；這無法撤回，只能靠使用者升級。新版客戶端不受影響。
  - 新金鑰沒有第二把可接手：遺失＝再也無法發新清單，只能再輪替一次（並重新出貨所有客戶端）。離線備份是維護者的責任。
- 後續行動 / 待辦：
  - `MAINTAINER-ACTIVATION.md`（中英）的「待輪替」段落改成輪替紀錄；`OPERATOR-TODO.md` A2 改為完成；
    `bootstrap-config.ts` 與 `relay/bootstrap/genkey.ts` 裡「並存期簽兩次」的說明同步更新。
  - 日後若要再輪替，照 `MAINTAINER-ACTIVATION.md` §輪替程序，且**輪替前先確認舊金鑰還在**、**記得檢查 CI secret 是否已刪**。
